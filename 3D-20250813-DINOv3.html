1论文概要与核心贡献

一句话概括:DINOv3 要解决的不是「分类精度」——DINOv2 已经够高(IN-ReAL 89.7 线性探测,Table 14)——而是训练越久、模型越大,稠密(patch 级)特征就越崩的退化现象:patch 与 CLS 的余弦相似度随训练单调升高,相似度图从「局部干净」变成「全局糊成一团」,分割/深度/对应全面掉点。DINOv3 的答案是 Gram anchoring:取一个训练早期的 checkpoint 当 Gram 教师,用 patch 特征自相关矩阵(Gram 矩阵)的 Frobenius 距离,把 student 的「patch 间相关性结构」钉死。这一招让 6.7B 的教师模型可以「无限期」训练下去而不掉稠密指标,从而把自监督预训练真正推到了 LLM 那种规模的尺度游戏里。

核心贡献一句话:论文自己的三段式总结(Abstract)——① 靠精细的数据准备、架构设计与优化,同时放大数据集(LVD-1689M)与模型(ViT-7B/16);② 提出 Gram anchoring,解决长期训练下稠密特征图退化这个「已知但未解决」的问题;③ 用 post-hoc 策略(高分辨率适配、蒸馏、文本对齐)在分辨率、模型规模、文本对齐三个自由度上放大模型的适用面。

三个宣称的贡献(论文 §1)

  1. 规模化(数据 + 模型 + 优化):构建 LVD-1689M 数据配方(Table 1 做了 Raw / Clustering / Retrieval / 混合 四路对照);把教师从 DINOv2 的 ViT-g/14(1.1B)扩到自研 ViT-7B/16(6.7B),引入轴向 RoPE + 4 个 registers;去掉 DINOv2 里那一堆 cosine schedule,改用常数超参训练 1M 迭代(§3.2,原文:"Departing from the multiple cosine schedules in DINOv2, we train with constant hyperparameter schedules for 1M iterations")。
  2. Gram anchoring:提出用早期 checkpoint 的 patch 特征 Gram 矩阵约束 student,缓解长训练下的 patch 级不一致(§4)。
  3. Post-hoc 三个自由度的拉伸:高分辨率适配(§5.1)、蒸馏出 S/S+/B/L/H+ 五档 + ConvNeXt 四档(§5.2)、文本对齐给零样本能力(§5.3)。卫星版 SAT-493M 也一并放出。
为什么这篇值得进本库的「前馈式重建」专题:因为它同时提供了 ① 一个可直接冻结使用(❄,无需微调)的编码器,② 一份「把 VGGT 的 DINOv2 换成 DINOv3 会怎样」的官方对照实验(Table 13),③ 一整套从小到大的模型家族(21M→6.7B),让前馈重建这条线可以按显存预算选型。详见 §15。

2研究背景与动机:稠密特征退化

SSL 的谱系与 DINOv3 的位置

论文把视觉预训练划成三条路线:全监督(SL)、弱监督图文对比(WSL,以 CLIP / SigLIP 2 / Perception Encoder 为代表)、自监督(SSL,以 DINO / iBOT / DINOv2 为代表)。论文在 §2 给出的判断是:SSL 在分类上已经追平甚至超过 WSL(Figure 1a 的 ImageNet-1k 线性探测曲线),但在规模化上落后——"relatively little work has focused on scaling unsupervised image pretraining"。已有的规模化尝试要么撞训练稳定性(Darcet et al., 2025),要么方法过于简化。唯一的例外是 DINOv2(1.1B),能匹配 CLIP 级别的表现;而把 DINOv2 往 7B 扩的尝试(Fan et al., 2025)"在全局任务上有前景,但在稠密预测上结果令人失望"。

论文点名的「已知但未解决」问题(Abstract 原话):"the known yet unsolved issue of dense feature maps degrading during long training schedules"。注意这个措辞——论文不声称这是一个新发现的问题,而是声称这是一个业界都知道、但一直没解决的问题。DINOv3 的贡献是把这个问题解决了,并且顺手把它变成了「可以放心无限期训练」的前提。

失败模式到底长什么样(机制层面)

论文 §4 的观察链条非常清楚,值得逐层拆开:

  1. 现象:训练越久,全局 benchmark 继续涨,但稠密任务掉点(Figure 5/6)。
  2. 量化代理指标:patch token 与 CLS token 之间的余弦相似度随训练上升。Figure 5 的图注直接写明:"segmentation performance is maximal when the cosine similarities between the patch tokens and the class tokens are low. As training progresses, these similarities increase and the performance on dense tasks decreases."——即 CLS 与 patch 的相似度是一个「稠密特征健康度」的负向指标。
  3. 视觉后果:Figure 6——"As training progresses, the features produced by the model become less localized and the similarity maps become noisier."(特征局部性下降、相似度图变噪)。
  4. 本质归因:patch 级一致性(patch-level consistency)丧失,即 patch 表示的相对结构被破坏;论文还提到持续训练会出现不同类型的 outlier(App. A)。
图2(对应论文 Figure 6,子图取 iter 199,999 / 999,999 两档)训练越久,相似度图越糊。左:输入图像;中:训练早期(约 20 万迭代)时,红色标注的 query patch 与其它 patch 的余弦相似度图——局部结构清晰、物体边界干净;右:训练后期(约 100 万迭代)时同样的图——相似度弥散到整幅图像,物体边界已不可辨。论文图注原文:"Evolution of the cosine similarity between the patch noted in red and all other patches. As training progresses, the features produced by the model become less localized and the similarity maps become noisier."这张图的价值在于它把「稠密特征退化」从抽象指标变成了肉眼可见的现象,也让后面 Figure 10 的 Gram 修复效果有了直接对照。
核心洞察(insight):退化发生在 patch 之间的相关性结构上,而不是单个 patch 的表示上。这个判断直接决定了药方——如果问题是「patch 特征各自变坏」,该做的是重建目标;既然是「patch 间关系变坏」,那就应该直接对关系矩阵下手,而 Gram 矩阵 $X_S X_S^\top$ 恰好就是 patch 间所有内积构成的矩阵。因果链条是完整闭合的,这是本文方法设计上最漂亮的一环。

3算法总体框架与符号表

输入 / 输出定义

  • 训练输入:每 mini-batch 4096 张图像(256 张/GPU × 16 GPU? 非也——论文写 "global batch size 4096",实际部署为 32 节点 × 8 卡 = 256 GPU,batch_size_per_gpu: 16,合 4096)。每张图取 2 个 global crop(256×256)+ 8 个 local crop(112×112)。

不可复现性提示(继承 DINOv2 的坑):论文明确写 "We build our large-scale pre-training dataset by leveraging a large data pool of web images collected from public posts on Instagram";且官方 README 的 Known Limitations 里写着训练使用私有数据集。也就是说 LVD-1689M 本身不公开,Table 1 的四路对照只能读、不能重跑。复现 DINOv3 的可行路径是在自己的数据上重放「聚类 + 检索 + seed 保留」的混合流程,而非复刻同一个语料。
对前馈重建线的直接启发:这条线的多视图数据(如 DL3DV / RE10K / 自采集扫描)天然是「场景中心 + 长尾物体」的分布。Table 1 的结论可以平移为操作建议:不要只用 cluster-based 采样——它会把 IN1k 这类通用判别性拉低;也不要只用 retrieval——它会丢掉少见物体的多样性。这与本库 前馈式高斯重建 2026 下半年调研 中「训练数据分布决定泛化边界」的判断一致。

数学形式化:轴向 RoPE + box jittering

DINOv3 的 RoPE 实现在标准化到 $[-1,1]$ 的坐标盒上给每个 patch 分配坐标,再在多头注意力里按两个 patch 的相对位置加偏置:

$$\text{Attn}(i,j)\;=\;\underbrace{q_i^\top k_j}_{\text{内容项}}\;\cdot\;\underbrace{R\!\left(\mathbf{p}_i-\mathbf{p}_j\right)}_{\text{相对位置项}},\qquad \mathbf{p}\in[-1,1]^2$$ (式 2)轴向 RoPE 的相对位置偏置,依据 §3.2 原文描述

关键在于坐标盒不是固定的,而是训练时随机缩放:

$$[-1,1]^2\rightarrow[-s,s]^2,\qquad s\sim\mathcal{U}[0.5,\,2]$$ (式 3)RoPE-box jittering,依据 §3.2 原文

前向流程(训练时的一张图)

  1. 取 2 个 global crop($256\times256$)+ 8 个 local crop($112\times112$);global 面积比 $\in[0.32,1.0]$,local $\in[0.05,0.32]$。
  2. 按 ImageNet 统计量归一化(mean 0.485/0.456/0.406,std 0.229/0.224/0.225)。
  3. patch 化 + patch embed(patch 16)→ 拼接 CLS 与 4 个 storage token。
  4. 40 个 block,每块内注意力加轴向 RoPE 相对位置偏置;随机抽一个 $s\sim U[0.5,2]$ 缩放坐标盒。
  5. 输出被 3 个 head 共享:DINO head(CLS,图像级)、iBOT head(patch 级)、KoLeo(head 之后的特征多样性项)。

6模块三:Gram anchoring(核心创新)

一句话定位

不去修单个 patch 的表示,而是直接约束 patch 两两之间的相关性矩阵——用一个训练早期的 checkpoint 当「锚」,把它算出的 Gram 矩阵当作目标,把 student 的 Gram 矩阵往它上面拉。名字里的 anchoring 正是这个意思:锚不在当下,而在过去。

目标函数

$$\mathcal{L}_{\text{Gram}}=\left\|\mathbf{X}_{\mathrm{S}}\cdot\mathbf{X}_{\mathrm{S}}^{\top}-\mathbf{X}_{\mathrm{G}}\cdot\mathbf{X}_{\mathrm{G}}^{\top}\right\|_{\text{F}}^{2}$$ (式 4)Gram anchoring 损失,论文式 (2)

其中 $\mathbf{X}_{\mathrm{S}}$ 是 student 的 patch 特征,$\mathbf{X}_{\mathrm{G}}$ 是 Gram teacher 的特征,$\|\cdot\|_{\text{F}}$ 是 Frobenius 范数。叠加后的总体目标:

$$\mathcal{L}_{\mathrm{Ref}}=w_{\mathrm{D}}\,\mathcal{L}_{\mathrm{DINO}}+\mathcal{L}_{\mathrm{iBOT}}+w_{\mathrm{DK}}\,\mathcal{L}_{\text{DKoLeo}}+w_{\mathrm{Gram}}\,\mathcal{L}_{\text{Gram}}$$ (式 5)refinement 阶段总损失,论文式 (3);$w_{\mathrm{Gram}}=2$

前向流程(Gram 阶段的一次迭代)

  1. 取 student 特征:只用 global crop 的 patch token("We only compute this loss on the global crops"),取 pre-head 的 patch 表示。
  2. 取 teacher 特征:冻结的 Gram teacher 对同一批 global crop 前向,取 backbone_out["x_norm_patchtokens"]。
  3. 分辨率对齐(关键):Gram teacher 的 crop 尺寸是 512,student 的 global crop 是 256——teacher 的 patch 网格是 $32\times32$,student 是 $16\times16$。代码用 F.interpolate(mode="bicubic", antialias=False) 把 teacher 的 $D\times32\times32$ 特征图下采样到 $16\times16$ 再算 Gram。这个「高分辨率 teacher → 低分辨率 student」的不对称,正是后文 §7 所说「高分辨率 Gram」的实现方式。
  4. 可选 L2 归一化:gram.normalized: true → 两侧特征都先做 $\ell_2$ 归一化,于是 Gram 矩阵退化为余弦相似度矩阵(见下方源码复核)。
  5. 算 MSE:mse_loss(student_sim, target_sim),其中 $sim=\mathbf{X}\mathbf{X}^\top$。
  6. 反向传播:梯度只流进 student(student 侧的 Gram 是可微的,teacher 侧 requires_grad_(False))。

Gram teacher 的选取是有讲究的,而且结论反直觉(Figure 9b 消融):论文实验了三种 Gram teacher 来源,结论是"choosing the Gram teacher from 100k or 200k does not significantly impact the results, but using a much later Gram teacher (1M iterations) is detrimental because the patch-level consistency of such a teacher is inferior."——即只能用早期 teacher,用「最新的」teacher 反而有害,因为最新的那个自己已经退化了。【推测】这也解释了为什么 Gram 只能是「一次性导入 + 少量刷新」:一旦 Gram teacher 被替换成最新 EMA 教师,锚就失效了。yaml 的 max_updates: 3 与「每 10k 更新」组合起来,把 Gram teacher 的漂移限制在一个很小的步数内($1.01\text{M}\to1.03\text{M}$),与这个结论自洽。
源码复核纠正了一处「论文表述 vs 实际实现」的差异(本库原创发现):
  • 论文式 (2) 写的是原始内积 $\mathbf{X}\mathbf{X}^\top$;但官方实现的 GramLoss.forward(src_dino/dinov3/loss/gram_loss.py:34-84)在算相似度矩阵之前先对两侧特征做了 F.normalize(feats, dim=-1)(L55 / L66,由 apply_norm=<cfg.gram.normalized>=true 控制)。
  • 因此实际被优化的对象是「余弦相似度矩阵」而非「内积矩阵」。两者相差每个 token 的模长因子。
  • 第二处:实现用的是 torch.nn.MSELoss()(L24),即 $\frac{1}{P^2}\sum_{i,j}(\cdot)^2$;而式 (2) 写的是 Frobenius 范数的平方 $\sum_{i,j}(\cdot)^2$。二者只差一个常数 $1/P^2$,乘进 $w_{\mathrm{Gram}}$ 后被吸收,数值上等价。
  • 第三处:实现保留了负相似度项(remove_neg: false,只有 remove_neg/remove_only_teacher_neg 两个开关的代码分支,L75-L82),而论文未提及这个选项。这在「读论文以为只约束正相关」和「实际代码把负相关也一起拉」之间划出一条不可忽略的界线。

7模块四:高分辨率适配

为什么需要单独一个阶段

蒸馏配方

  • 教师:7B 模型本体,固定不更新("we use the 7B model directly as the teacher... the teacher model is fixed")。
  • 目标函数:与第一阶段完全相同(即 $\mathcal{L}_{\mathrm{Pre}}$,式 1),保证学习信号一致。
  • 迭代:1M + 250k 迭代(cosine 降温),之后接高分辨率适配阶段,但不带 Gram。
  • 学生档位:ViT-S 21M / B 86M / L 0.3B,外加两个自定义档 ViT-S+ 29M 与 ViT-H+ 0.8B(用于填补与 7B 教师之间的空档)。
  • 为何跳过 Gram:论文原话 "We do not observe patch-level consistency issues and therefore do not apply the Gram anchoring technique."——固定教师不漂,学生跟着不漂。
一个可以直接抄的工程结论(Table 14):ViT-L 学生已在多数密集任务上接近 7B 教师——ADE20k 54.9(7B 为 55.9)、NYU RMSE 0.352(7B 为 0.309)、NAVI 62.3(7B 为 64.4)。而参数量只有 1/22、算力只有 1/20。所以本库后续讨论「前馈重建该用哪一档 DINOv3」时,ViT-L/16 是默认起点,ViT-B/16 是显存紧张时的退路。
权重获取的现实约束(README 已确认):
  • ViT-S/S+/B/L/H+ 与 ConvNeXt 全家 + SAT-493M 的 ViT-L 公开可下(HuggingFace facebook/dinov3-{vits16,vits16plus,vitb16,vitl16,vith16plus}-pretrain-lvd1689m)。

  1. 「自监督 vs 弱监督」在稠密任务上已经分出胜负,而且差距很大。同为 1~2B 量级,自监督的 DINOv2/AM-RADIO 在 ADE20k 上比弱监督的 SigLIP 2/PEcore 高 6.8~15.1 个 mIoU;在 3D 对应(NAVI)上高 9.5~20.2 个 recall 点。论文对后者的诊断是 "lack of 3D awareness"——图文对比目标里没有能让模型学会跨视图几何一致性的信号。
  2. 「蒸馏自监督模型」这条中间路线(AM-RADIO)确实有效,但仍被原生 DINOv3 压制。AM-RADIOv2.5 的 ADE20k 53.0 已高于所有弱监督基线,逼近 DINOv2 的 49.5;但 DINOv3 的 55.9 仍领先它 2.9。这说明「从强监督模型蒸出来的空间能力」不能完全替代「自监督原生学到的空间能力」。
  3. 数据规模不等于特征质量(Web-DINO 是最好的反例)。Web-DINO 用 7B 参数、网络公开数据重放 DINO 目标,ADE20k 只有 42.7、NYU 0.466——连 1.1B 的 DINOv2(49.5 / 0.372)都不如。这反向印证了 Table 1 的结论:LVD-1689M 的策展配方本身就是贡献,不是「有公开数据就能重放」。
  4. LingBot-Vision 与 DINOv3 是「事后修补」与「事前设计」两条不同的路。DINOv3 承认 patch 级一致性会随训练退化,用 Gram 去事后修;LingBot-Vision 则选择改造 patch 级目标本身(把边界 token 强制塞进掩码集)。结果是 LingBot-Vision 用 1.1B 参数量、不到 DINOv3 三分之一的样本量,在 NYUv2 深度上做到了 0.296,反超 6.7B 的 DINOv3(0.309);但在 ADE20k 语义分割上仍落后 2.4 个 mIoU。详尽的机制对比与源码级差异见 LingBot-Vision 笔记 的「同类方法对比」章节。
横向对比的口径陷阱(引用这些数字时必须带上):
  • patch 16 vs patch 14 会改变可比性。DINOv3 与 LingBot-Vision 用 patch 16,DINOv2 / AM-RADIO / PEspatial 用 patch 14。论文自己的做法是「对齐到 1024 个 patch token」,于是在 patch 16 下输入是 $512^2$、在 patch 14 下是 $448^2$——两者看到的输入总像素量不同。这意味着表格里的差距有一部分来自「输入像素量」而非纯特征质量。
  • 「参数量」列不能直接当效率指标。DINOv3 的 6.7B 是教师;实际部署的 ViT-L 只有 300M,而在 ADE20k 上做到 54.9(见表 14),只比 7B 教师低 1.0。横向比「谁家大」时要指明比的是哪一档。
  • 迭代数/batch 不可直接换算算力。LingBot-Vision 的 300k 迭代 × batch 3072 与 DINOv3 的 1M 迭代 × batch 4096 之间,还差着模型规模(1.1B vs 6.7B)这个更大的乘数。

15.3 为什么是 DINOv3 而不是别的(逐条给依据)

① 成本:token 数少 23.4%

patch 16 vs patch 14,同一分辨率下 token 数比 $(\frac{14}{16})^2 = 0.766$。因为多视图 transformer 的自注意力开销 $\sim O(N^2)$,前馈重建模型(VGGT-Ω、LocusGS 这类)最紧张的资源就是 token 数。库内 VGGT-Ω 笔记直接把这个记为「速度快 20~25%」的来源。

② 精度:冻结即可用

Table 12 的 ❄ 列:相对深度五个数据集上全面覆盖需要微调的 DAv2 ViT-g。含义是前馈重建不需要把 encoder 放进训练回路,省掉一整个「joint finetune encoder」的工程复杂度。

③ 分辨率:能外推

RoPE + box jittering 让编码器在训练分辨率之外不漂(Figure 17 给出每档的安全区间)。前馈重建常在训练时用小图、推理时上采样到高分辨率,这是硬需求。

④ 选型:五档可选

21M / 29M / 86M / 300M / 840M 五档 ViT + 四档 ConvNeXt,覆盖从移动端到服务器的显存预算。且 Table 14 显示 ViT-L 已接近 7B 教师——不必为了精度去申请 7B 权重。

⑤ 还有一个容易被忽略的理由:语义与几何在同一份特征里。前馈重建经常需要两件事同时成立——把「人」和「背景」分开(语义),以及把「同一个点在不同视图里对齐」(几何)。Table 4 显示 DINOv3 在 NAVI(几何对应)与 SPair(语义对应)上同时领先;而 Table 3、Table 5 显示弱监督模型在两者上都弱。库内 SAM 3D Body 与 PDF-GS 恰好分别用到了这两面(前者用密度高的特征图做 prompt,b 后者用 L2 距离做语义级 distractor 检测)。

16.2 「作为前馈重建编码器」时的具体短板

① 没有跨视图机制

DINOv3 是逐帧编码器。前馈重建需要的「同一 3D 点在不同视角的特征一致」是上层聚合器负责建立或外挂匹配器建立的。DINOv3 只提供「单帧内的好特征」。

可改进:把 Gram 的思想从「帧内 patch 相关性」推广到「跨视图 patch 相关性」——即用一个早期 checkpoint 的跨视图特征相关性当锚。这在概念上是 Gram anchoring 的自然延伸,但需要多视图数据与配对机制,论文未涉及。

② 首帧 token 尺寸固定,难以适配变长序列

patch 16 在低分辨率下 token 数不足(如 $256^2 \to 16\times16=256$ token),高分辨率下 token 数爆炸($4096^2 \to 65536$ token)。前馈重建常在 $448\times256$ 这种非方形输入上工作,需要对 patch 网格做特殊对齐。

可改进:论文的评估协议已经给出「最短边缩放到目标 + 长边取 patch 整数倍」的做法,但这会造成轻微的非等比拉伸(论文自己的例子:$960\times1712$ 是「slight horizontal stretch」)。对几何敏感的 3D 任务而言,这个拉伸是系统性误差来源。【推测】这是一个尚未被前馈重建社区认真对待的细节。

③ 最大档位的权重不开放

7B 需申请,而 Table 12/13 的最优结果全部来自 7B 或 7B 蒸馏档。对学术复现构成实际门槛。

缓解:Table 14 显示 ViT-L 已接近 7B(ADE20k 54.9 vs 55.9、NAVI 62.3 vs 64.4),代价是 1/22 参数。因此「用 ViT-L 顶替 7B」在多数前馈重建场景是可接受的近似。

④ 训练数据与训练流程都不可复现

LVD-1689M 私有、7B 训练细节只在论文层面公开、官方只提供 ViT-L/ImageNet-1k 的「快速上手」配置。

缓解:把 Table 1 的「聚类 + 检索 + seed 保留」配方作为方法而不是数据集来复用——这是本笔记给出的可操作路径。

16.3 对本地 vggt_human pipeline 的三条可执行建议

  1. 先把 encoder 换成 DINOv3 ViT-L/16 跑一次对照。依据是 Table 13 的可分离性结论。成本极低(只换推理组件,不训 encoder),预期收益可从 Table 13 的外推估计(相机位姿 +1.0 AUC@30、DTU Overall 0.382 → 0.368)。唯一需要小心的是 §10 提到的 patch 16 vs 14 分辨率对齐重算。
  2. 如果显存紧张,退到 ViT-B/16。依据是 Table 14(86M 参数在 ADE20k 上 51.8、NYU 0.373)与库内分布(FFAvatar、PDF-GS、Tele360 都在用 B 档)。不要一开始就冲 H+ 或 7B——7B 权重门槛 + 算力(3550 GFLOPs/帧)都不划算。
  3. 编码器与聚合器分开调参。既然二者是可分离变量(Table 13),实验设计上就应该做「2×2:encoder ∈ {DINOv2, DINOv3} × aggregator ∈ {基线, 改进}」的对照,而不是把两者揉在一起做消融——后者无法归因。

三条演进线索

线索一:规模化的瓶颈从「数据」转到「稳定性」

DINOv2 的贡献是证明「数据策展 > 数据规模」;DINOv3 的贡献是证明「当规模足够大时,训练稳定性成为新瓶颈」,而且这个瓶颈不能靠调学习率解决,必须改目标函数。

线索二:自监督的战场从「分类」转到「稠密」

Figure 1a 显示 SSL 在 IN1k 上已到平台期;真正的增量在稠密任务上,而稠密任务恰好是 3D 重建、分割、深度、对应的公共底座。DINOv3 的定位变化,本质上是「视觉基座」的定义从「分类特征」变成「空间特征」。

线索三:一个基座同时服务自然图像与遥感

SAT-493M 卫星版用完全相同的超参,只换 RGB 统计量 + 缩短训练(100k 预训练 + 10k Gram + 8k 高分辨率),就在 GEO-Bench 上刷新 15 个任务中的 12 个。这说明 Gram anchoring 不是针对某个域的补丁,而是针对「长训练退化」这个通用病的药。

图8(对应论文 Figure 18)同一套 DINOv3 模型在遥感上的多用途:左 DINOv3、右 DINOv2 的 PCA 特征对照。论文图注:"Illustration of versatile applications in remote sensing made possible by a single DINOv3 model. 一句话定位

DINOv3 不是「又一个更强的 DINOv2」,而是把自监督视觉预训练从「能训多大的模型」推进到「能训多久的模型」。Gram anchoring 的价值不在于它多精巧(核心代码只有 84 行),而在于它解除了「训练时长」这个约束——而训练时长一旦解除,规模化就重新变成一个纯粹的资源问题,这恰恰是 LLM 已经走通的那条路。对于本库关心的前馈式重建,它的实际贡献是把「编码器」这一层变成了一个可以直接选购的、冻结的、跨域稳定的组件,从而让研究者可以把精力集中在聚合器与解码器上。
