1论文概要与核心贡献

AHOY! 来自图宾根 AI Center、MPI-INF、帝国理工与 KAUST,已中稿 ECCV 2026。它要解决的是一件被整个领域刻意绕开的事:

一句话概括:此前所有单目人体重建方法都假设输入「无遮挡、全身可见、常常还是规范姿态」。这个假设把互联网上绝大多数真人视频排除在外——YouTube 上有数以十亿计的人在做日常活动的视频,身体被家具、物体或其他人挡住。AHOY! 的做法是承认大片人体区域永远不会被观测到,然后用一个身份微调过的视频扩散模型去「幻觉」出这些区域的稠密监督,再用这些监督训练一个完整的、可动画的 3DGS avatar。

2研究背景与动机:被排除的绝大多数真实视频

2.1 此前方法的假设与代价

论文的批评非常直白:基于 NeRF 与 3DGS 的 avatar 方法已经能产出高保真、可实时摆动姿态的结果,但这些方法都假设输入无遮挡、主体全身可见、常常还是规范姿态。

这个假设的代价被作者算得很清楚:YouTube 上有数以十亿计的人在做日常活动(做饭、锻炼、交谈)的视频,身体被家具、其他人或场景本身遮挡。视角有限,身体的大片区域可能从未被观察到,或者在镜头里被切掉。
反过来看收益:如果能从这类视频重建完整 avatar,就解锁了一个几乎无限的多样化人体外观来源(各种体型与服装风格),而且不需要受控采集、不需要多视角相机阵列、不需要被拍摄者配合。

2.2 四个具体挑战(与四个贡献一一对应)

挑战一:从局部观测 bootstrap 出完整 avatar

大片身体区域从未被观测,avatar 的相当一部分没有任何直接监督。论文用三步解决:① 先从「部分观测主体生成的多视角图像」建一个粗 3DGS avatar;② 让粗 avatar 做结构化运动,用身份微调的视频扩散 + 扩散反演把渲染结果精修成幻觉监督视频;③ 用这些幻觉视频训练带姿态相关形变的完整 avatar。

挑战二:没有多视角采集,却要学姿态相关外观

高保真 avatar 需要 pose-dependent 形变来刻画衣物随身体构型的变化。但第一阶段没有任何针对姿态相关形变的多视角监督,所以只能先学一个不建模姿态相关形变的 avatar(时间不变的 canonical 高斯图)。缺失的监督靠第二阶段设计的结构化运动序列补齐——这构成了「canonical → pose-dependent」这一步的架构洞察。

挑战三:吸收扩散生成数据的多视角不一致

每段幻觉视频是独立从扩散模型采样的,因此跨视角、跨帧并不几何一致。naive 地在这上面训练会产生伪影。解法是引入两个不同的姿态:一个「map pose」(跨相似姿态帧共享,保证高斯属性预测一致)与一个「LBS pose」(逐帧优化,用来吸收扩散模型固有的几何不一致)。

挑战四:扩散输出不可靠时保住面部身份

视频扩散模型生成的人脸身份不一致。做法是通过 SMPL-to-FLAME 顶点对应把 avatar 划分成头与身体,把头部像素从基于扩散的身体监督中 mask 掉,改用专门的多视角人脸扩散模型监督头部以保身份。

2.3 假设在什么条件下会失效

作者自陈(§5 Conclusion):
  1. 身份微调模型可能对「从未被观测过的区域」幻觉出「看似合理但错误」的细节——生成模型没有事实依据可依,只能靠先验猜。
  2. 最终 avatar 的质量上界由视频扩散模型的保真度决定。
  3. 流水线需要多阶段优化与多次扩散推理,因此显著慢于前馈方法。
本笔记补充的一条隐含边界:整套机制依赖「输入视频里有足够可见区域来微调身份」。身份微调需要从输入视频学 LoRA + 文本 token;如果遮挡过于严重(比如只露出头与肩膀),身份先验本身就学不好,幻觉质量会随之崩塌。论文在 50 个 YouTube 视频上没有给出「遮挡比例 × 质量」的曲线来界定这个边界。

3算法总体框架与符号表

3.1 任务定义

给定一段人体被部分遮挡的单目视频,目标是重建完整的、可动画的 3D 高斯 avatar,并可用任意姿态驱动。流水线分四步:

  1. 从部分观测主体构建粗 avatar;
  2. 通过身份微调的视频扩散生成幻觉监督;
  3. 用这些监督训练带 pose-dependent 高斯图的完整 avatar;
  4. 动画与场景合成。

4阶段一:粗粒度 avatar 构建

4.1 纹理映射与补全

  1. 用 NLF 估计逐帧 SMPL 参数 $\{(\bm{\theta}_t,\bm{\beta})\}$,用 SAM 3 得到可见性掩码 $\{\mathbf{M}_t\}$;
  2. 用 DensePose 给每个可见像素分配 UV 坐标,逐帧累积到一张规范纹理图上,采用 first-write-wins 规则以避免时间混合伪影;
  3. 定义一个固定的正面规范姿态 $\bm{\theta}_{*}$,通过 DensePose 逆对应把纹理图 warp 回该姿态,得到部分规范姿态图像 $\mathbf{I}_{*}^{\mathrm{part}}$——从未被观测的区域留空;
  4. 用预训练的 FLUX inpainting 模型填充这些缺失区域,得到完整的规范姿态图像 $\mathbf{I}_{*}$。
「first-write-wins」这个细节值得记:如果对同一 UV 位置按多帧做平均或加权合成,前景人物自身的运动就会在纹理图上留下时间混合伪影(拖影)。先写先赢意味着只信任第一次观测,主动放弃后续观测——在一个「反正大部分区域要交给 inpainting」的流程里,这个取舍是合理的。

4.2 多视角生成与粗 3DGS

补全后的规范图像只提供一个视角。为了获得更广覆盖,用预训练的多视角扩散模型生成 $V-1=3$ 个额外的规范姿态视角(后、左、右),丢弃它的 3D 重建分支。连同正面视角 $\mathbf{I}_{*}^{1}=\mathbf{I}_{*}$,得到 $V=4$ 张规范姿态图像 $\{\mathbf{I}_{*}^{v}\}_{v=1}^{V}$,相机 $\{\bm{\gamma}_v\}$ 已知且为正交。

Canonical 高斯图

沿用既有工作(论文引用 [85] 与 [71])的做法:在规范姿态 $\bm{\theta}_{*}$ 的 SMPL 网格上稠密采样 $N_H$ 个点,定义 canonical 高斯模板 $\mathcal{G}^{H}_{*}$;从正面与背面投影生成 canonical 位置图,建立像素到高斯的一一对应。

与既有工作的关键差异(作者明确点出):不同于 [85] 里姿态相关的人体高斯图,这里用的是时间不变的 canonical 图。理由是——「我们的单目遮挡设定缺少姿态条件偏移所需的多视角覆盖」。这是一次诚实的能力降级:不是不想做 pose-dependent,而是数据条件不允许。这也直接催生了阶段二「用结构化运动把缺失的多视角监督造出来」的设计。

StyleUNet 预测

一个 StyleUNet $S$ 处理 canonical 位置图,为每个高斯属性预测相对模板的逐像素偏移,得到 canonical 高斯集合 $\mathcal{G}^{H}=S(\bm{\theta}_{*})$。此外 $S$ 还预测每个高斯的蒙皮权重 $\mathbf{w}^{H}_{k,j}$,$j=1,\dots,J$ 为关节索引。

LBS 形变

对每一帧 $t$,用估计姿态 $\bm{\theta}_t$ 通过线性混合蒙皮(LBS)与预测的蒙皮权重 $\mathbf{w}^{H}_{k,j}$ 把 canonical 高斯形变到 posed 空间,记整个形变为 $\mathcal{T}(\mathcal{G}^{H};\bm{\theta}_t)$。颜色与不透明度保持 StyleUNet 的预测不变。

4.3 训练目标

粗 avatar 由两个来源监督:① 已知相机下的 $V$ 张规范姿态图像;② 估计姿态与观测相机 $\bm{\gamma}^{\mathrm{obs}}$ 下的 $T$ 帧观测视频。记 $\hat{\mathbf{I}}_{t}=\mathcal{R}(\mathcal{T}(\mathcal{G}^{H};\bm{\theta}_{t});\bm{\gamma}^{\mathrm{obs}})$ 为第 $t$ 帧渲染结果:

$$\mathcal{L}_{\mathrm{coarse}}=\sum_{v=1}^{V}\|\mathbf{I}_{*}^{v}-\mathcal{R}(\mathcal{G}^{H};\bm{\gamma}_{v})\|_{1}\;+\;\sum_{t=1}^{T}\|(\mathbf{I}_{t}-\hat{\mathbf{I}}_{t})\odot\mathbf{M}_{t}\|_{1}$$ (式 1)

其中 $\odot$ 为逐元素乘,$\mathbf{M}_t$ 把遮挡区域 mask 掉。另加一个同样带掩码的感知损失(细节在补充材料)。结果是一个「对可见部分忠实、但未观测区域有伪影」的粗 avatar。

这个损失的设计需要点出来:监督被显式拆成两项——规范视角项(无条件、全图)与观测帧项(带掩码)。关键在于未观测区域在第二项里被 $\mathbf{M}_t$ 屏蔽,所以那个区域在阶段一确实没有任何监督。这正是伪影的来源,也是阶段二必须存在的理由。

5阶段二:身份微调的视频扩散模型

阶段二的逻辑起点很清晰:粗 avatar 只被 $V=4$ 张规范视角图与被遮挡的输入帧监督。这个覆盖度意味着未观测区域(背部、手臂内侧、被遮挡物持续挡住的任何区域)重建质量差,且 avatar 无法泛化到训练中未见的新姿态与新相机角。

5.1 为什么必须做身份微调

一个通用视频扩散模型不认识这个具体主体的外观。所以要在输入视频上微调它,建立一个身份专属的先验。如果不微调,后续的「幻觉」就会生成任意一个穿戴类似衣物的人,而不是视频里的这个人。

5.2 做法:把 Dynamic Concepts 的身份编码迁到 Wan 2.2

论文把 Dynamic Concepts 的身份编码阶段适配到 Wan 2.2 上:

  • 记预训练整流流模型的速度场为 $\mathbf{v}_{\phi}$;
  • 学习一个 LoRA 更新 $\mathbf{A}\mathbf{B}$,同时学习一个可学习文本 token $[\mathrm{v}]$,它在文本编码器的嵌入空间中绑定到目标身份;
  • 沿用 Dynamic Concepts 的做法,把输入视频当作一组无序帧(去掉时间信息),使 LoRA 只捕捉外观与身份,而不把运动动态纠缠进来。

5.3 训练目标:流匹配损失

$$\mathcal{L}_{\mathrm{id}}=\mathbb{E}_{\tau,\mathbf{z}_{0}}\left[\left\|(\mathbf{z}_{1}-\mathbf{z}_{0})-\mathbf{v}_{\phi}(\mathbf{z}_{\tau},\tau;\text{``a}\;[\mathrm{v}]\;\text{person''})\right\|^{2}\right]$$ (式 2)

其中 $\mathbf{z}_{0}=\mathsf{Enc}(\mathbf{I}_{t})$ 是 VAE 编码的 latent;$\mathbf{z}_{1}\sim\mathcal{N}(\mathbf{0},\mathbb{I})$ 是噪声($\mathbb{I}$ 为单位矩阵);$\mathbf{z}_{\tau}=(1-\tau)\mathbf{z}_{0}+\tau\mathbf{z}_{1}$ 是流时间 $\tau\in[0,1]$ 处的插值 latent;速度场由施加在预训练权重 $\mathbf{W}$ 上的 LoRA 更新 $\mathbf{W}'=\mathbf{W}+\mathbf{A}\mathbf{B}$ 参数化。

「无序帧」这个设计是本节最关键的一步:把视频当帧集合处理,等价于主动丢弃时序结构。目的不是简化,而是隔离变量——让微调只学到「这个人长什么样」,而不是「这个人怎么动」。这样后面用该模型去精修「任意姿态的渲染」时,它提供的是纯粹的外观先验,不会与目标动作冲突。
本笔记的对照:这与我们在 pipeline 里「固定所有帧的表情系数以消除面部微动」是同一种思路——都是主动把某个方差源置零,以免它污染真正想学的东西。

6阶段二:结构化运动与 RF-Inversion 幻觉

6.1 为什么要「设计」运动序列

不是随便生成任意动作,而是精心策划 $N$ 段运动序列,目的有二:① 系统性地把所有身体表面暴露给相机;② 提供学习 pose-dependent 高斯图所需的多视角覆盖。

结构化运动(转体类 / turn)

每段序列把一个目标身体动作(如抬臂、双臂高举)与一次完整 360° 身体旋转配对。

关键观察:这种序列里的所有帧都可以视为同一姿态在不同角度下的视图——身体动作近似恒定,而旋转扫过了人的四周。因此一段 $T'$ 帧的转体,提供了对单一姿态的 $T'$ 视角监督,使模型能学到「在该特定身体构型下,高斯表示从每个方向看应该是什么样」。

结构化运动(静态类 / static)

某些姿态(如坐姿)与全身转体不兼容。对这些姿态,论文生成同一坐姿在多个不同相机角度下的多段视频,然后把姿态匹配的帧跨视频同步,用所有对应视频的图像监督每个姿态。

这提供了与转体序列「视频内多视角」等价的跨视频多视角监督。

这一节的洞察是全文最漂亮的一处:「一个姿态 × 环绕视角」被等价转化为「$T'$ 个视角对同一姿态的监督」。它把「没有多视角采集」这个硬约束,用受控的运动设计绕过去了——因为你控制着让 avatar 做动作,所以你也就控制了它被观察的方式。
这是「主动制造监督」而非「被动等待监督」的思路,与本库 StudioRecon 用视频扩散合成数百个新视角来稠密化背景监督属于同一类策略。

6.2 粗渲染

对每个运动序列 $n$,用对应的姿态 $\{\bm{\theta}'_t\}_{t=1}^{T'}$ 驱动粗 avatar,并从观测相机 $\bm{\gamma}^{\mathrm{obs}}$ 渲染:

$$\hat{\mathbf{V}}_{n}=\bigl\{\mathcal{R}\!\bigl(\mathcal{T}(\mathcal{G}^{H};\bm{\theta}^{\prime}_{t});\,\bm{\gamma}^{\mathrm{obs}}\bigr)\bigr\}_{t=1}^{T^{\prime}}$$ (式 3)

这些渲染捕捉到了正确的身体姿态与轮廓,但在输入视频中被遮挡的区域带有伪影与缺失纹理。

6.3 通过 RF-Inversion 做幻觉

精修的方式是把每段视频过一遍身份微调模型的 latent 空间,用 RF-Inversion 把伪影替换成身份一致的外观。记 $\mathsf{Enc}$ / $\mathsf{Dec}$ 为 VAE 编解码器,$\mathbf{z}_{0}=\mathsf{Enc}(\hat{\mathbf{V}}_{n})$ 为编码后的粗视频:正向前向整流流 ODE 把它映射到噪声 latent $\mathbf{z}_{1}$,再用身份微调模型反向流动并解码出幻觉视频:

$$\mathbf{z}_{1}=\mathbf{z}_{0}+\!\int_{0}^{1}\mathbf{v}_{\phi}(\mathbf{z}_{\tau},\tau)\,\mathrm{d}\tau,\qquad \tilde{\mathbf{z}}_{0}=\mathbf{z}_{1}+\!\int_{1}^{0}\mathbf{v}_{\phi}(\mathbf{z}_{\tau},\tau)\,\mathrm{d}\tau,\qquad \tilde{\mathbf{V}}_{n}=\mathsf{Dec}(\tilde{\mathbf{z}}_{0})$$ (式 4)
为什么这个「正反两遍」是必要的(论文的解释):
  • 正向过程把粗渲染的空间结构(身体姿态与轮廓)编码进 $\mathbf{z}_{1}$——这一步是「编码结构」;
  • 反向过程在保留这个布局的同时,通过 LoRA 把外观引向主体身份,从而把先前缺失的区域填上合理纹理——这一步是「注入身份」。
换句话说:结构来自渲染,外观来自扩散先验。二者分工明确,这也是它既能保住姿态又能补出纹理的原因。

对全部 $N$ 段运动序列施加该过程,得到幻觉视频集 $\{\tilde{\mathbf{V}}_{n}\}_{n=1}^{N}$,它提供了后续训练完整 avatar 所需的多视角身体覆盖。

7阶段三:pose-dependent 高斯图

7.1 从 canonical 升级到 pose-dependent 的条件已经具备

阶段一用的是时间不变的 canonical 图,因为当时没有针对多个姿态的多视角监督。现在幻觉视频提供了这个覆盖:

  • 在转体序列里,所有 $T'$ 帧观察到近似同一个身体姿态,但来自不同视角 → 对该姿态等效 $T'$ 视角监督;
  • 在静态姿态序列里(如坐姿),把不同角度的多段视频中同一个姿态出现处的帧同步起来 → 跨视频多视角监督。

有了这些稠密覆盖,就可以按既有工作(Animatable Gaussians 系)的做法升级为 pose-dependent 高斯图:对每一帧把 posed SMPL 顶点投影到前 / 后 UV 图,并用一个重新初始化的 StyleUNet $S$ 以这些 pose-dependent 图为输入,预测相对 canonical 模板的逐像素高斯属性偏移:

$$\mathcal{G}^{H}_{n}=S(\bm{\theta}_{n}^{\mathrm{map}})$$ (pose-dependent 高斯集)

7.2 全文最关键的设计:同一个「姿态」的两个角色

角色符号作用粒度
map pose$\bm{\theta}_{n}^{\mathrm{map}}$作为 StyleUNet $S$ 的输入,决定生成哪一套高斯属性序列内固定(所有帧共享)
LBS pose$\bm{\theta}_{n,t}^{\mathrm{lbs}}$把 $S$ 预测出的高斯形变到 posed 空间逐帧变化
以转体序列为例:map pose 编码目标身体构型(如双臂高举),使 $S$ 产出一套代表该姿态的高斯;逐帧的 LBS pose 则负责身体旋转,把同一套高斯映射到每个视角下正确的 3D 朝向。
本笔记的机制解读(论文未明说):map/LBS 解耦的本质是把一个「N 个视角 × 1 个姿态」的欠定问题,从 N 套参数压成 1 套参数。参数被共享,不一致就只能体现在被显式优化的修正量上;而修正量受 $\mathcal{L}_{\mathrm{reg}}$ 约束,不会无限增长。这是一个用参数共享换一致性的设计——与 4DVD 用「稠密视角共享同一 batch」换一致性在心理模型上属于同一类。

8阶段三:map/LBS 解耦与联合优化

8.1 初始化

因为幻觉视频是无遮挡的,可以直接用 NLF 估计 SMPL 姿态,并假设相机在 NLF 参考系下。这些估计同时初始化两件事:map pose $\bm{\theta}_{n}^{\mathrm{map}}$(用于构造 $S$ 的 pose-dependent 输入图)与逐帧 LBS pose $\bm{\theta}_{n,t}^{\mathrm{lbs}}$。

8.2 联合优化的对象

优化的东西有三类,同时进行:① StyleUNet $S$ 本身(重新初始化);② 逐帧 LBS 姿态修正 $\{\Delta\bm{\theta}_{n,t}\}$;③ 逐帧相机修正 $\{\Delta\bm{\gamma}_{n,t}\}$。

记 $\tilde{\mathbf{I}}_{n,t}$ 为第 $n$ 段幻觉视频的第 $t$ 帧。用 Sapiens 与 SAM 3 得到的分割掩码 $\mathbf{M}_{n,t}^{\mathrm{head}}$ 排除头部像素(因为扩散生成的人脸对身份保真不可靠)。身体监督损失为:

$$\mathcal{L}_{\mathrm{body}}=\sum_{n,t}\bigl\|\bigl(\tilde{\mathbf{I}}_{n,t}-\hat{\mathbf{I}}_{n,t}\bigr)\odot\bigl(1-\mathbf{M}_{n,t}^{\mathrm{head}}\bigr)\bigr\|_{1} ,\qquad \hat{\mathbf{I}}_{n,t}=\mathcal{R}\!\bigl(\mathcal{T}(\mathcal{G}^{H}_{n};\,\bm{\theta}_{n,t}^{\mathrm{lbs}}\!+\!\Delta\bm{\theta}_{n,t});\;\bm{\gamma}^{\mathrm{obs}}\!+\!\Delta\bm{\gamma}_{n,t}\bigr)$$ (式 5)
「故意制造 map pose 与 LBS pose 的分歧」——这句话是全文的机制核心(论文原话要点):
map pose $\bm{\theta}_{n}^{\mathrm{map}}$ 在序列 $n$ 的所有帧间共享,因此每个幻觉视角都在监督同一张 pose-dependent 高斯图。而 LBS 姿态修正 $\Delta\bm{\theta}_{n,t}$ 逐帧不同,专门用来吸收扩散生成数据里逐帧的多视角不一致。论文明确说这引入了「一个有意的分歧」,使 canonical 高斯保持彼此一致、而形变能适配每一帧。

8.3 保留的观测帧监督(防漂移锚点)

$$\mathcal{L}_{\mathrm{obs}}=\sum_{t}\|(\mathbf{I}_{t}-\hat{\mathbf{I}}_{t}^{\mathrm{obs}})\odot\mathbf{M}_{t}\|_{1}$$ (与式 1 第二项同构)

其中 $\hat{\mathbf{I}}_{t}^{\mathrm{obs}}$ 用原始估计的姿态与相机(不加修正)渲染。这一项是防止「幻觉漂移太远」的锚点——它始终把 avatar 拉回真实观测。

9阶段三:FLAME 头部路径与总目标

9.1 为什么头部必须走独立路径

论文直说:Wan 生成的视频里,头部区域对「面部身份」是不可靠的。这与 §5 里「无序帧」设计想解决的问题同源——视频扩散模型的强项是场景与外观的合理性,不是特定人脸的身份保持。
因此策略是彻底的「不信任 + 替换」:把头部像素从扩散监督里 mask 掉(§8.2),再用一个专门保身份的多视角人脸扩散模型单独监督头部。

9.2 做法

  1. 用 CAP4D 的多视角人脸扩散模型,从 $P$ 个已知相机 $\{\bm{\gamma}_{p}^{\mathrm{face}}\}$ 生成身份一致的头部图像 $\{\mathbf{I}^{\mathrm{face}}_{p}\}_{p=1}^{P}$;
  2. 用 SMPL-to-FLAME 顶点对应把 canonical 高斯划分成头与身体两部分:
$$\mathcal{G}^{\mathrm{head}}=\bigl\{(\bm{\mu}_{k},\ldots)\in\mathcal{G}^{H}\;\big|\;k\in\mathcal{H}_{\mathrm{head}}\bigr\}$$ (式 6)

其中 $\mathcal{H}_{\mathrm{head}}\subset\{1,\ldots,N_{H}\}$ 是 SMPL 头部区域对应的高斯索引集合。

  1. 头部监督时只形变这些头部高斯,用 FLAME 表情参数 $\bm{\psi}_{p}$:
$$\mathcal{L}_{\mathrm{head}}=\sum_{p=1}^{P}\bigl\|\mathbf{I}^{\mathrm{face}}_{p}-\mathcal{R}\!\bigl(\mathcal{T}_{\mathrm{FLAME}}(\mathcal{G}^{\mathrm{head}};\,\bm{\psi}_{p});\,\bm{\gamma}_{p}^{\mathrm{face}}\bigr)\bigr\|_{1}$$ (式 7)

其中 $\mathcal{T}_{\mathrm{FLAME}}$ 对头部高斯施加基于 FLAME 的形变,但它们的 canonical 位置与整体身体表示是共享的。

「canonical 位置与整体身体表示共享」这一句是设计要点:头部高斯不是一个独立的小 avatar 再拼上去,而是同一套高斯集合的子集——只是监督信号与形变算子不同。这样头部与脖子、肩部之间不会有接缝。这一点与「分离训练再拼接」的做法在工程结果上是不同的。

9.3 总目标

$$\mathcal{L}=\lambda_{\mathrm{body}}\mathcal{L}_{\mathrm{body}}+\lambda_{\mathrm{obs}}\mathcal{L}_{\mathrm{obs}}+\lambda_{\mathrm{head}}\mathcal{L}_{\mathrm{head}}+\lambda_{\mathrm{per}}\mathcal{L}_{\mathrm{per}}+\lambda_{\mathrm{reg}}\mathcal{L}_{\mathrm{reg}}$$ (式 8)

其中 $\mathcal{L}_{\mathrm{per}}$ 是感知损失,$\mathcal{L}_{\mathrm{reg}}$ 把蒙皮权重正则向 SMPL 推导出的值。论文没有给出具体的 $\lambda$ 数值(原文只写这些系数用于平衡各项),细节在补充材料。

【待核实】 式(8)的五个 $\lambda$ 权重、$N_H$ 的具体值、$N$ 的具体值、$P$ 的取值、训练迭代数与硬件配置,主论文(arxiv.org/html/2603.17975v2)均未给出。本笔记尝试从项目页的补充材料 PDF 获取,但该 PDF 始终无法连通(SSL 握手超时 / UNEXPECTED_EOF,重试多次均失败),因此未能核实。所有相关项在 §11 中标为「未获取」。

9.4 推理时的动画与场景合成

前面各阶段产出一个完整的、可动画的 3DGS avatar,可以由任意 SMPL 姿态通过 LBS + pose-dependent 高斯图驱动。动画部分沿用 AHA! 的做法在重建好的 3DGS 场景中驱动 avatar。为防分布外伪影,推理时施加基于 PCA 的姿态投影,把新驱动姿态约束到训练分布内(细节在补充材料)。

给定一个从随手手机视频重建的静态高斯集 $\mathcal{G}^{S}$ 与 $T''$ 帧驱动运动 $\{\bm{\theta}_{t}\}$:

$$\mathbf{I}_{\mathrm{out}}=\mathcal{R}\!\bigl(\mathcal{T}(\mathcal{G}^{H}_{t};\,\bm{\theta}_{t})\cup\mathcal{G}^{S};\;\bm{\gamma}\bigr),\qquad \mathcal{G}^{H}_{t}=S(\bm{\theta}_{t})$$ (场景合成与渲染)
「PCA 姿态投影」这个工程细节值得记:pose-dependent 高斯图只在训练见过的姿态分布上可靠。把驱动姿态投影到训练姿态的主成分空间内,是一种廉价的 OOD 防护——避免生成模型在未见姿态下崩坏。这是纯工程性的补丁,但它决定了 demos 是否会出现诡异动作。

11.4 PCA 姿态投影的完整公式(补充材料 §7)

在训练期间收集的位置图特征 $\{x_t\}$ 上做 PCA,保留 $N_{pca}$ 个主成分 $S$ 及其标准差 $\{\sigma_i\}$。对新的驱动姿态位置图特征 $x$:

$$\xi=S^{\top}(x-\bar{x}),\qquad \xi_i\leftarrow\mathrm{clip}(\xi_i,\,-2\sigma_i,\,2\sigma_i),\qquad x_{\mathrm{recon}}=S\xi+\bar{x}$$ (式 9,补充材料)

$\bar{x}$ 为训练均值。把系数裁剪到 $\pm2\sigma$ 内即把新姿态约束在训练分布内,保证 StyleUNet 收到分布内输入。

11.5 LBS 形变的具体形式(补充材料 §5)

$$\mathbf{R}^{H}_{k,t}=\sum_{j=1}^{J}\mathbf{w}^{H}_{k,j}\,\mathbf{R}^{\mathrm{SMPL}}_{j}(\bm{\theta}_{t}),\qquad \bm{\mu}'_{k,t}=\mathbf{R}^{H}_{k,t}\bm{\mu}_{k}+\mathbf{t}^{H}_{k,t},\qquad \bm{\Sigma}'_{k,t}=\mathbf{R}^{H}_{k,t}\bm{\Sigma}_{k}\bigl(\mathbf{R}^{H}_{k,t}\bigr)^{\!\top}$$ (式 5–6,补充材料)

即先按蒙皮权重加权融合各关节旋转矩阵得到逐高斯旋转,再同时变换均值与协方差(协方差用 $\mathbf{R}\bm{\Sigma}\mathbf{R}^\top$ 保持正半定)。

11.7 落地坑与隐藏约束

  • 依赖链条很长:NLF(SMPL 估计)+ SAM 3(掩码)+ DensePose(UV)+ FLUX(inpainting)+ 自训多视角扩散 + Wan 2.2(身份微调)+ RF-Inversion + CAP4D(人脸)+ Sapiens(头部掩码)+ AHA!(场景动画)。任一环失败都会中断整条链,且这些依赖分布在多个不同的模型与许可体系里。
  • 优化规模大:粗 avatar 400k、完整 avatar 500k 迭代,而 batch size 只有 1。
  • 「重建任意真人」的伦理风险被作者自己写进了补充材料:从公开视频、未经当事人配合地生成照片级数字复制体,涉及隐私、同意与滥用风险(未授权 deepfake、身份冒充)。作者声明本方法面向研究与创意应用,所有 YouTube 视频均公开可得,并呼吁采用水印、来源追踪与同意框架。这条对本库同样适用——若基于真人视频重建 avatar,需事前定下数据使用边界。
  • 作者自陈的偏见风险:重建质量取决于底层视频扩散模型,而该模型可能继承训练数据中的偏见,导致不同人群、体型、服装风格上的质量不均。作者建议后续工作审计并处理此类偏见。这是很少见的一段自我披露,对本库做人体 / 人脸增强时同样值得警惕。

14.1 对比结论:AHOY 凭什么强

① 靶子选得对

所有 baseline 都假设输入无遮挡。AHOY 是唯一把「遮挡」当成默认情况而非边界情况的方法。所以它在遮挡场景下的 +3~4 dB 优势,本质是问题设定上的错位,而不是同一个问题上的技术碾压。

② 把「不一致」当成一等公民

绝大数用生成模型做监督的工作,都在努力让生成更一致。AHOY 反过来:承认生成一定不一致,然后在表示层开一个自由度去吸收它(map/LBS 解耦)。这个转向在工程上更可行,因为「让扩散模型跨视角一致」是个开放难题,而「给姿态加一个可优化修正量」是标准操作。

③ 主动制造监督

用「目标动作 + 360° 转身」把「一个姿态的 $T'$ 帧」等价转换为「一个姿态的 $T'$ 个视角」。这不是数据增强,而是把数据采集问题转化为控制问题——因为你控制 avatar,所以你能决定它被怎样观察。

14.2 AHOY 凭什么弱

  • 速度:作者自陈显著慢于前馈方法。粗 400k + 完整 500k 迭代 + 多次扩散推理,LHM 这类前馈方法在秒级完成。
  • 质量上界被生成模型锁死:作者明确写「未观测区域可能被幻觉出看似合理但错误的细节」。
  • 依赖链极长:见 §11.7,10 个外部模型/组件。
  • 只支持单目单主体:输入是「一个人被遮挡」的视频;多人交互、多主体遮挡不在讨论范围。
  • 未开源,且论文几乎不报资源账:GPU、显存、耗时全缺。

15🎯 应用场景与落地适配性

判断基准:本库主线是单卡 RTX 3090(24GB)、WSL2、12–16 路中等稀疏可控场景、目标是人体;而 AHOY 的设定是单目 in-the-wild 视频 + 重度遮挡。两者的匹配关系比较微妙,需要逐项看。

维度AHOY 的情况与我们的匹配度
输入形态单目视频(1 视角)比我们的场景更宽松——我们有多视角,而它连一个都没用满
遮挡处理把遮挡当默认情况,正面解决高价值——我们的多人场景同样存在相互遮挡,目前是当作「要过滤掉的干扰」处理(见 微动人体三维重建调研)。AHOY 的思路是把遮挡区域交给生成先验,而不是丢弃观测
head/body 拆分用 SMPL-to-FLAME 对应把头/身体分成两部分,各自独立监督,但共享同一套 canonical 高斯与本库的 head_gs / body_gs / scene_gs 拆分直接同构,而且它给出了一个关键设计原则:拆分应该是「监督与形变算子分开」而不是「两套独立高斯拼起来」——后者会产生接缝
map/LBS 解耦用参数共享 + 逐帧修正量吸收生成数据的不一致可迁移——我们的 SAM3 person mask ID 映射与 track 去重本质也在处理「多视角不一致」,但它处理的是身份不一致,AHOY 处理的是几何不一致
面部身份保持用专用多视角人脸扩散模型(CAP4D)替换掉不可靠的通用扩散人脸可迁移——我们的人脸增强链路(HYPIR / SAM3)同样面临「通用增强会改变身份」的问题,「对不可靠区域屏蔽通用监督 + 换专用监督」是一条明确的解法
算力与速度900k 迭代 + 多轮扩散推理;GPU/显存/耗时全未给不可用。我们无法评估在 3090 上要跑多久
开源项目页无 Code 链接;GitHub 检索无相关仓库无法采用
数据前提需要 NLF 估 SMPL + DensePose UV + 可用的 FLUX 修复NLF 与 DensePose 我们链路里没有;引入成本不低
结论:机制可借,代码不可用。
AHOY 对我们的价值集中在三条设计原则,它们与代码是否开源无关:
  1. 拆分要「共享表示、分开监督」,不要「独立训练再拼接」——这对我们的 head_gs / body_gs 设计是直接的指导。
  2. 不一致不要试图消灭,要给它一个可优化的出口——用一组低维修正量(map/LBS 解耦里的 $\Delta\bm{\theta}$)吸收生成误差。
  3. 对已知不可靠的区域,屏蔽通用监督 + 接入专用监督——头部像素被 mask 掉后交给专用人脸模型,是我们人脸增强链路可以直接照搬的策略。
一条不太显眼但很实用的工程经验(§11.3):StyleUNet 在 Stage 1 与 Stage 3 都先做 2,000 迭代的「零偏移预热」——先让网络学会「什么都不改」。对任何「预测相对偏移」的模块,这都是一个几乎零成本、但能显著改善训练稳定性的技巧。我们如果要做逐人高斯属性的残差预测,这一条可以直接用。

16可改进方向分析

方法层面

[高优先级] 幻觉的质量没有任何「可信度」度量,而这是整条链的命门。

问题:作者自己在 Conclusion 里承认「身份微调模型可能对从未被观测的区域幻觉出看似合理但错误的细节」。但论文没有给出任何量化「幻觉对了吗」的实验——没有把幻觉结果与真值比较(在 BEHAVE 上其实是可以的,因为 BEHAVE 有多视角真值)。

佐证:§5 原文 "the identity-finetuned model may hallucinate plausible but incorrect details for body regions that are never observed";BEHAVE 的评测只报告最终渲染指标,未单独报告幻觉视频的质量。

改进建议:在 BEHAVE 上做一组「遮挡受控实验」:人为遮挡某人体的固定区域比例(如 30% / 50% / 70%),然后测量「幻觉出来的区域」与真值的误差。这能直接给出「遮挡容忍度曲线」,而这正是使用者最需要的先验知识。

[高优先级] 「面部身份保持」这个核心贡献缺乏针对面部的定量指标。

问题:贡献④ 是「保住面部身份」,消融 (D) 是「去掉 head/body 拆分」,但评测只用 PSNR / SSIM / LPIPS 三个整体指标,消融 (D) 的跌幅仅 0.5–0.6 dB(见 §13.2)。整体指标对面部身份的敏感度极低,导致这一贡献在定量上看起来无关紧要,而其真实重要性只能靠 Fig.7(D) 的定性图来体现。

改进建议:补三组指标——① 人脸区域的裁剪 PSNR/LPIPS;② Face ID 相似度(如 ArcFace 嵌入余弦);③ 面部 landmark 误差。本库里 SAM 3D Body 与 MHR 笔记都涉及密集面部 landmark,可以借用同一套评估口径。

[中优先级] map pose 在整个训练中固定,但论文没有论证「固定」优于「也参与优化」。

问题:设计上 map pose 是固定输入,LBS pose 逐帧可修正。这是一个明确的二元选择,但论文没有做「只优化 map pose」「两个都优化」「都不优化」的对照。消融 (C) 只是把整个解耦机制去掉了。

改进建议:加一组「map pose 也允许微调」的对照。这会直接回答「解耦的有效性来自参数共享,还是来自可修正自由度」这个机制问题。

[中优先级] 结构化运动序列是人工设计的,没有说明覆盖度与冗余度。

问题:运动序列数 $N$ 未给出,也没说这些序列如何被挑选、是否覆盖了足够的姿态分布。而整个 pose-dependent 学习的监督完全来自这些序列——如果它们覆盖不足,后续的 PCA 姿态投影就会频繁触发裁剪。

改进建议:给出 $N$、姿态空间覆盖度指标(如与训练集姿态分布的距离分布),以及 PCA 裁剪被触发频率的统计。

数据与评估

[中优先级] YouTube 评测没有多视角真值,只有「与留出帧比较」。

问题:50 段 YouTube 视频的评测是「把重建结果渲染回输入视角,与原视频留出帧比较」。这是一个自洽性检查,不是新视角正确性检查——它无法证明未见区域重建对了。而 BEHAVE 有多视角真值,却只有 8 个序列。

改进建议:扩大 BEHAVE(或类似多视角遮挡数据集)上的评测规模,并明确区分「可见区域」与「不可见区域」的指标。

[中优先级] 用户自陈的偏见风险没有对应的任何实验。

问题:补充材料里写了「质量可能随人群、体型、服装风格而不均」,并建议未来工作审计。但论文自己没有做这个审计。

改进建议:这是一个相对便宜的实验——按人群/体型/服装风格分组报告指标即可。既然作者已经意识到了问题,顺手做掉比留作 future work 更有价值。

工程实用性

[高优先级] 资源账几乎全部缺失。

问题:GPU 型号、数量、训练总时长、推理显存、推理耗时全部未给出(补充材料只给了迭代数与优化器)。而论文明确包含「粗 400k + 完整 500k 迭代、batch size 1」这种重负载训练。这让任何人都无法评估可行性。

改进建议:照 StudioRecon 的做法给出逐阶段耗时表(它给了 Table S1:单张 A6000 上视图合成 50 min、人体位姿 3 min、背景重建 30 min、人体重建 40 min、增强 3.3 s/帧)。

[高优先级] 代码未开源,且已有 ECCV 2026 的中稿身份。

问题:项目页只提供论文、补充材料与视频;无 GitHub 链接。GitHub 全库检索「AHOY + occlusion」也没有对应仓库。也就是说这篇中稿了 ECCV 2026 的工作目前完全不可复现(且当年就已是中稿状态)。

改进建议:哪怕只放出粗 avatar 阶段 + StyleUNet 的代码,也能让「先学恒等映射预热」「Pose-dependent 高斯图」这些可复用组件被社区用起来。

17总结、演进定位与资源

一句话总结

AHOY! 的核心不是「又做了一个更好的 avatar」,而是重新划分了「可重建」与「不可重建」的边界——它把此前被当作前提排除掉的「遮挡」变成了默认输入,并用「身份微调视频扩散造监督 + map/LBS 解耦吸收不一致 + head/body 拆分保身份」这三件套把欠观测区域的几何问题转成了生成问题。它的三条设计原则(共享表示分开监督、给不一致一个可优化出口、对不可靠区域换专用监督)比它的具体数字更有迁移价值,尤其与我们的 head_gs / body_gs / scene_gs 拆分架构直接相关。

对本库的三条可带走结论

  1. 拆分要「共享表示、分开监督」:头部高斯是整体高斯集合的子集,只是监督信号与形变算子不同。这避免了「独立重建再拼接」的接缝问题——对我们的 head_gs / body_gs 设计是直接指导。
  2. 不一致不要试图消灭,要给它一个出口:用一组低维、受正则约束的逐帧修正量吸收生成误差,比「努力让生成更一致」在工程上可行得多。
  3. 「零偏移预热」是便宜且通用的稳定化技巧:任何预测相对偏移的模块,先训 2,000 迭代「什么都不改」,再开始真正学习。
一条必须记下的伦理边界(出自补充材料 §1):本方法能从公开视频、未经当事人配合地重建照片级数字复制体,涉及隐私、同意与滥用风险(未授权 deepfake、身份冒充)。作者声明所有 YouTube 视频均公开可得、方法面向研究与创意用途,并呼吁社区采用水印、来源追踪与同意框架。若本库要把这类能力用到真人素材上,应先把数据使用边界写进规范。

在研究脉络中的位置

AHOY 属于综述里的「路线 C:生成当补全器 / 伪监督源」——与它同在路线 C 的是 StudioRecon(人机分工:背景交生成、人体交几何)。二者的差别值得记清:StudioRecon 不信任生成模型处理人体,只用它管背景;AHOY 则把人体本身未观测的部分整个交给生成模型。前者保守但稳,后者激进但能处理「连人体都没拍全」的极端情况。这两条分支代表了「生成先验用在人体上的哪一部分」这个问题的两种答案。
