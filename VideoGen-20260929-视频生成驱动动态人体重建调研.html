视频生成模型驱动动态人体重建：六条技术路线调研

把「视频扩散模型」当作动态人体重建链路中的一个可插拔部件——它可能生成视角、补全遮挡、提供 SDS 监督、充当几何编码器，或干脆只生成动态纹理。本调研按「视频生成模型在链路中承担什么角色」切分六大路线，覆盖 2024-05 ~ 2026-08 的 14 篇代表作。

1结论先行：六条路线一张表

「用视频生成模型解决动态人体重建」不是一个单一赛道，而是同一种能力（大规模视频先验）在重建链路四个不同位置上的插入方式。按插入位置划分，当前可归为六条路线：

三条可直接用于决策的判断

  1. 主战场是路线 A，且 2026 年的竞争焦点已经从「模型能生成什么」转到「上下文怎么管」。DiT 单次前向能容纳的目标视角数有上限，超过就必须分组，而分组会带来参考侧 O(N) 膨胀与目标侧组间结构漂移。4DAnyone 的 RCP/TCR、Diffuman4D 的滑动迭代去噪、4DVD 的级联解耦，都是对同一个问题的不同工程解。
  2. 路线 E / F 是 2026 年才出现、但性价比可能更高的「非生成式」用法。DreamHand 明确把 VDM 从「随机多步渲染器」降级为「确定性编码器」（clean latent 单次前向），绕开了采样延迟与生成伪影传播；AvatarDynamizer 则把视频扩散用在 2D 纹理空间，避开了 3D 一致性难题。二者都比「让扩散模型直接吐多视角视频」更稳。
  3. 路线 C 的人机分工思路对自采数据最实用。StudioRecon 明确写「video diffusion 对人体直接给出几何不一致的结果」，因此只让视频扩散负责背景的稠密视角合成，人体走几何关联 + 关键点三角化初始化，最后用递归增强模块统一。这是一个「承认生成模型能力边界、按部件分配职责」的范式，比端到端生成更接近可交付工程。

⚠️【待核实】跨论文的 PSNR/指标不可直接横向比较：这些工作分别在 DNA-Rendering、ActorsHQ、DyMVHumans、Objaverse 派生集上评测，且「重建后的渲染 PSNR」与「生成视频本身的 PSNR」口径不同，选型时不能只看数字大小。

2问题定义：动态人体重建缺什么，视频生成模型能补什么

先把任务与缺口拆开，六条路线的划分才有依据。动态人体重建的目标是：从单目或稀疏多视角视频得到可自由视角回放的 4D 表示（4DGS / 可变形高斯 / 动态 NeRF）。与「数十台同步相机的容积捕获」相比，它同时在三个维度上欠定：

① 视角缺失

输入相机数远小于重建所需（典型 4 路 vs 44-48 路）。这是路线 A 存在的理由：让生成模型把「那台不存在的相机」拍到的画面造出来。

② 观测缺失

遮挡、出画、自遮挡导致某些身体区域全程无观测。这是路线 C 的靶子：生成内容作为伪监督，去补「从没被拍到过」的区域。

③ 监督缺失

4D 真值稀缺，变形场/物理参数无直接监督。这是路线 D 的靶子：用视频先验经 SDS 蒸馏成可微信号。

此外还有第四个常被忽略的接口问题：即便生成模型造出了正确的动态内容，它也必须先解码成 RGB 再交给重建器，而重建器是在更窄的数据分布上训练的（路线 B 的靶子）。

为什么视频生成模型（而不是图像生成模型）

动态人体重建需要的是时序一致 + 跨视角一致的观测。2D 图像扩散只保证单帧合理，直接拿来补帧会闪烁；视频扩散模型天然建模时序，且在大规模视频上预训练后隐含了人体运动学与遮挡常识。这是 2024 年后这条路线成立的底层前提。例外：只补静态外观（如单姿态遮挡）时，2D 扩散 + SDS 仍够用（WonderHuman、OccFusion 即属此类，本调研把它们作为对照保留）。

3路线 A：多视角视频生成 → 4DGS 重建

核心范式（generate-then-reconstruct）：把视频扩散模型当作「虚拟相机阵列」，输入单目或稀疏视角视频，输出 N 路同步且时序一致的多视角视频，再交给 off-the-shelf 的 4DGS / 动态 NeRF 优化器重建。这条路线的全部技术难点只有一句话：如何让 N 个视角在同一时刻指向同一个人。

3.1 通用场景的起点：CAT4D / SV4D / 4DVD

人体专用方法的技术底座来自「单目视频 → 4D 场景」的通用工作，它们证明了「多视角视频扩散 + 可变形高斯」这条路可行，但训练分布是物体/场景，迁移到人体（宽松衣物、头发、自遮挡）会显著退化——Diffuman4D 的论文正文明确指出了这一点（CAT4D 面对 soft structure 的运动时形变严重）。

CAT4D · 2024-11

arXiv 2411.18613（Google DeepMind / Columbia / UCSD）。多视角视频扩散模型，核心卖点是解耦相机控制与时间控制：可生成「固定视角变时间」「固定时间变视角」「两者同变」三类序列；配合新的采样策略把单目视频变成多视角视频，再优化可变形 3DGS。评测在 DyCheck 一类动态场景基准上。⚠️【待核实】会议标注 CVPR 2025 来自 IEEE 收录信息，非 arXiv abs 的 comments 字段

SV4D · 2024-07

arXiv 2407.17470（Stability AI / NEU）。统一的 latent video diffusion：一次采样直接出 5 帧 × 8 视角的 novel-view 视频，再优化隐式 4D 表示，明确避免以往「图像+视频+多视角三个扩散模型 + SDS」的重型组合。训练数据来自 Objaverse（合成物体）。SV4D 2.0（arXiv 2503.16396）去掉参考多视角依赖、引入 3D/frame attention blending、渐进式 3D-4D 训练与两阶段精修。⚠️【待核实】官方 blog 称 SV4D 1.0 单次推理 5帧×8视角约 40 秒、4D 优化约 20-25 分钟

4DVD · 2025-08

arXiv 2508.04467。级联解耦：先用一个分支预测粗糙的多视角布局（跨视角与时间一致性优先），再用结构感知分支把布局先验与输入单目视频的精细外观融合，生成最终稠密视角视频。训练集 D-Objaverse（每物体 16 视角 × 21 帧）。思路与「先结构后纹理」的课程学习一致。

3.2 人体专用主线：Human4DiT → Diffuman4D → MV-Performer → 4DAnyone → Flex4DHuman

Human4DiT（2024-05）— 4D DiT 的注意力分解范式

arXiv 2405.17405｜清华 + 新畅元｜项目页标注 SIGGRAPH Asia 2024（Journal Track）｜⚠️【待核实】arXiv abs 的 comments 字段仅给出项目网址，会议信息取自项目页

  • 架构：级联的 4D Transformer，把自注意力分解为三个 block——2D image block（帧内空间自注意力）、view block（跨视角对应）、temporal block（跨时间）。
  • 条件注入：参考图编码出的人体身份 + 相机参数 + 时间信号，分别注入对应 block。
  • 数据与训练：收集跨图像 / 视频 / 多视角 / 有限 4D 捕捉的多维数据集，配多维训练策略。
  • 推理：两阶段时空采样——第一阶段把 360° 视频当单视角长序列（最大化时间窗保长期一致），第二阶段当多视角短 clip（较大视角窗保视角一致）。
  • 定位：它把「视角 × 时间 × 空间」三维注意力的分解方式确定下来，后来者（Diffuman4D 的 3D 自注意力、4DAnyone 的 target context routing）都在这个框架内做上下文工程。

Diffuman4D（2025-07）— 稀疏视角 + 骨架条件 + 滑动迭代去噪

arXiv 2507.13344｜浙大 zju3dv｜⚠️【待核实】未从 abs 页核实会议信息，此处不标会议

  • 输入/输出：4 路同步稀疏视角视频 → 44 路目标视角视频（序列长度 150 / 225 帧），再由输入的 4 路 + 生成的 44 路一起重建 4DGS。
  • 样本网格：所有视角与时间步的 latent 组织成 $(N+M)\times T$ 的 4D 网格，用 3D 自注意力在视角与时间之间交换信息。
  • 滑动迭代去噪：受 GPU 显存限制，视频扩散一次只能处理有限帧，直接分组去噪会让各组独立收敛、产生不一致；该文用滑窗沿空间与时间交替去噪，使信息在网格内充分流动，从而扩大有效感受野而不爆显存。
  • 条件：3D 人体骨架投影到各视角并渲成 RGB map，编码进同一 latent 空间；相机参数用 Plücker 坐标编码。文本条件被显式关闭（prompt 置空）。
  • 附带的工程资产：重新标定了 DNA-Rendering（相机参数、CCM 颜色校正、前景 mask、骨架），开源 dna_rendering_processed：1000+ 序列 × 48 相机 × 225(150) 帧，约千万张图。这是这条路线后续工作共同的训练底座。
  • 下游：官方用 LongVolcap（未开源）做 4DGS，另给 nerfstudio 的 splatfacto 3DGS 作为可跑的替代。

MV-Performer（2025-10）— 把「部分点云渲染的法线」当条件，解决 360° 歧义

arXiv 2510.07190｜港中深（CUHKSZ）等｜SIGGRAPH Asia 2025 conference track（arXiv HTML 页含 ACM DOI）｜代码开源 github.com/zyhbili/MV-Performer

  • 问题：视频扩散模型可作为「隐式 4D 新视角合成器」，但以往方法只能在前视角附近挪相机轨迹，做不到 360°。
  • 做法：从 oriented partial point cloud 渲染出视角相关的法线图作为条件信号——用有限的几何先验缓解「见过的区域 vs 没见过的区域」的歧义；再用一个人体中心的多视角视频扩散模型融合参考视频、部分渲染与不同视角的信息以保持同步。另提供 in-the-wild 的鲁棒推理流程，抑制单目深度估计误差带来的伪影。
  • 数据：主要依托 MVHumanNet。

4DAnyone（2026-08）— 把瓶颈诊断为「有界注意力上下文」并做上下文工程

arXiv 2608.20335｜浙大 / Ant Group / Robbyant / HKUST / CUHK｜SIGGRAPH Asia 2026（项目页）｜Apache-2.0 开源｜库内已有 deep 笔记 3D-20260820-4DAnyone.html

  • 输入/输出：未标定的随手单目视频 → 数十路多视角一致视频 → FreeTimeGS。无需 rig、无需标定、无需三脚架；输出视角数可选（6 路环绕到 48 路）。
  • 诊断（本调研认为这是 2026 年最重要的框架性贡献）：当目标视角数超过单个 DiT 的前向容量时，必须分组去噪，于是出现两个耦合瓶颈——参考侧条件成本随视角数 O(N) 增长，稀释跨视角外观指导（后生成的视角越来越不像本人）；目标侧组间无法直接交换信息，产生整体结构漂移（每组各自长出一个几何）。
  • RCP（Reference Context Packing）：把不断增长的参考视角压成固定长度的混合分辨率上下文，参考侧复杂度从 O(N) 降到 O(1)。
  • TCR（Target Context Routing）：去噪过程中轮换目标视角的分组——高噪声阶段频繁交换组内容以确定全局结构，低噪声阶段固定相邻组以稳定细节。
  • 条件信号取舍：用 3D 骨架（稀疏但准确）替代稠密深度（脆弱）与不可靠的相机参数，作者把 in-the-wild 的鲁棒性归因于此。
  • 数据与规模：自建 MVGameHuman（游戏引擎合成，38k 视频 / 24 相机 / 318 actors），混入 light-stage 与真实视频；backbone 为 Wan2.2-TI2V-5B；训练用 128×H20-3E。
  • 数字（据论文与报道，二手源）：DNA-Rendering PSNR 24.33 dB（对比方法最好 21.47 dB）；DyMVHumans 上 21.03 dB——后者明显更低，作者也承认真实无控场景下的泛化仍是短板，背面细节本质上是「与正面合理自洽的推测」。

Flex4DHuman（2026-06）— 去掉一切显式几何先验，只用相对相机位姿

arXiv 2606.13655｜University of Washington + World Labs｜⚠️【待核实】未从 abs 页核实会议信息，此处不标会议

  • 主张：不需要骨架、深度、法线、也不需要渲染目标视角的几何，只用相对相机位姿就能驱动多视角视频生成。
  • 实现：以 Wan 2.1 的 1.3B text-to-video 为 backbone 并保留其结构；把相机与视角信息编码为五轴位置编码——在时空 RoPE 之外加入视角索引与连续 SE(3) 相对相机几何（PRoPE 路线）。输入布局为 36 通道（16 通道噪声 latent + 16 通道条件 latent，目标视角条件位置补零 + 4 通道二值 mask 标识参考/目标）。
  • 训练课程：三阶段——① 单参考单目标下适配新的相机感知位置编码；② 引入动态参考视角采样 + 背景随机丢弃，学会可变参考→目标配置；③ temporal rollout（用 clean 的历史目标 token 训练，支持长序列）。另加入多视角 caption 以支持测试期文本控制。
  • 下游：FreeTimeGS；在 DNA-Rendering / ActorsHQ 上评测。⚠️【待核实】二手站点称其在 DNA-Rendering 上超过 Diffuman4D-GT-skeleton 约 +1.21 dB PSNR、相对单目基线 +8~9 dB，未回原文核对
  • 与 4DAnyone 的差异（第三方交叉解读，⚠️【推测】）：Flex4DHuman 更「通用/少条件」，支持动物类；4DAnyone 的可辩护增量在于容纳未知内参、不把相机参数直接喂给生成模型、并用 RCP/TCR 把更多视角纳入同一套一致性设计。

3.3 三个关键技术分歧

分歧一：条件信号用什么

骨架系（Diffuman4D、4DAnyone）：稀疏但准确，误差不会像稠密深度那样灾难性传播，代价是丢失体型/衣物细节线索。
几何渲染系（MV-Performer 的视角相关法线图、部分点云渲染）：信息量大，但依赖单目几何估计质量。
无几何系（Flex4DHuman 的纯相对位姿）：最通用于任意动态主体，但也意味着一致性完全压给生成模型本身。

分歧二：上下文怎么管

这是 2025→2026 的核心战场。滑动迭代去噪（在 latent 网格上滑窗交替去噪）、RCP+TCR（压缩参考 + 轮换目标分组）、级联解耦（先布局后外观）、历史 token rollout（长序列自回归）。四者的共同目标都是在有限注意力/显存下维持全局一致。

分歧三：下游用什么重建器

4DGS（FreeTimeGS / Deformable-GS）为主流；3DGS（splatfacto）适合只需静态+位移近似的场景；动态 NeRF（SV4D）在稀疏视角下插值更好，但有实时性代价——SV4D 2.0 项目页明确说 4D Gaussians 在其稀疏设定下会出现时序闪烁与漂浮点。

4路线 B：潜空间直连 4D（绕过 RGB 中介）

这条路线提出的问题比它的方法更值得记住：生成与重建之间的接口，为什么一定要是 RGB？

Latent-to-4D / Beyond Pixels: From Video Priors to 4D Worlds（2026-08）

arXiv 2608.10744｜浙大 ReLER / CCAI｜项目页 hayd-zju.github.io/Beyond-Pixels

  • 对既有两条范式的批评：
    • generate-then-reconstruct（路线 A）：保留了生成器的模块性，但让一个在窄得多的重建数据上单独训练的 4D/重建模型插在视频先验与 4D 输出之间——开放域内容与时序伪影会传播成不稳定的几何（distribution mismatch + error propagation）。
    • integrated feed-forward（让某个视频生成器直接预测几何）：先验转移更直接，但把 4D 预测绑定在该生成器与条件协议上，换一个预训练视频模型就要重训几何监督。
  • 核心洞察：共享同一个 VAE（同 latent 归一化 / 布局 / 压缩约定）的多个 video DiT，其最终去噪 latent 落在同一表示空间；而该空间位于 RGB 解码的上游，因此可以作为「一次几何监督、服务多个生成器」的可复用接口。
  • 实现：把 video latent 对齐到预训练 4D decoder 的 token grid，配 frame-wise 与 global 的时空注意力精修；约 1K 条重建 clip 训练，单个 checkpoint 在同 VAE 家族的多个 video DiT 间直接迁移、无需改动。
  • 数字：Text4D-200 / I4D-200 上，投影 DINO-F1 相比「同 latent 的 Wan + 4RC 级联」分别高 2.88-3.45 与 5.81 点，人工评分在几何、时序稳定性、整体质量上均更受偏好。
  • 与本项目的相关性：如果后续要把「视频先验」接进自研重建链路，这条路线给出的建议是——接口层尽量下沉到 latent，而不是渲染成 RGB 再喂；RGB 接口会引入一次不可逆的信息损失与分布错配。注意该工作面向通用 4D 场景，尚未见人体专用版本。

5路线 C：生成当补全器 / 伪监督源（遮挡与欠观测）

这是与「自采 in-the-wild 视频」最贴近的一条路线。它的前提是承认：真实拍摄中总有大片人体区域从未被观测，几何上无解，只能引入生成先验；而生成内容本身多视角不自洽，必须设计专门机制吸收。

AHOY!（2026-03）— 遮挡下的可动画 avatar

arXiv 2603.17975（v2 2026-06-28）｜MPI 等｜项目页含 GitHub

  • 靶子：现有 avatar 重建都假设输入「无遮挡、全身可见、常在规范姿态」，而真实视频里的人常被家具、物体、他人挡住。
  • 四个组件：① hallucination-as-supervision——用身份微调过的扩散模型为未观测区域生成稠密监督；② canonical → pose-dependent 两阶段架构，从稀疏观测 bootstrap 出完整 pose-dependent 高斯图；③ map-pose / LBS-pose 解耦——专门用来吸收生成数据带来的多视角不一致；④ head/body 分开监督以保住面部身份。
  • 结果：在 YouTube 视频与含显著遮挡的多视角捕获数据上报告 SOTA，且重建出的 avatar 可用新姿态驱动、合成进手机视频拍的 3DGS 场景。
  • 可借鉴点：③ 的「解耦吸收不一致」比「想办法让生成更一致」更工程可行。

StudioRecon（2026-07）— 人机分工：视频扩散只管背景

arXiv 2607.09125｜首尔大学｜SIGGRAPH Conference Papers 2026（DOI 10.1145/3799902.3811165）｜项目页 sisyphm.github.io/studiorecon-page

  • 设定：健身房/家庭等真实场景下，只有 4 台低重叠（约 90° 分布）、未标定的相机，多人频繁遮挡。
  • 关键判断（原文）：近期方法在欠观测区域仍有明显伪影；video diffusion models 作为另一条可选路线，对人体会给出几何不一致的结果。
  • 因此的分工：背景用 camera-controlled 视频扩散合成数百个视角做稠密监督；人体走几何路线——cross-view identity association + 三角化多视角关键点拟合，得到可变形高斯人的鲁棒初始化；最后用递归增强模块 + motion-adaptive consistency injection 把二者合成的结果统一，消除残留伪影。
  • 能力：四个真实数据集上 SOTA 的新视角合成，支持新轨迹渲染与人体替换。
  • 与本项目的相关性：我们的 12-16 视角（中度稀疏）场景比它的 4 路低重叠友好得多，但「背景交给生成、人体交给几何」这条分工原则可以直接借用。

对照：用 2D 图像扩散（不是视频扩散）做同样的事

  • WonderHuman（arXiv 2502.01045）：单目动态人体重建中「幻觉出未见部位」。核心是 Dual-Space SDS——在规范空间与观测空间同时做 score distillation，前者保证内容自然完整，后者处理跨姿态的动态；另配视角选择策略与姿态特征注入，以调和 SDS 预测与已知观测的冲突。评测覆盖 ZJU-MoCap / MonoCap / MVHumanNet / in-the-wild。
  • OccFusion（Stanford CS191 项目，非 arXiv）：三阶段——部分可见 mask → 完整人体 mask 的初始化；3D 高斯在 SDS 额外监督下优化出完整几何；in-context inpainting 精修欠观测部位。在 ZJU-MoCap 与 OcMotion 上报告 SOTA。⚠️【待核实】来源为课程项目页 PDF，非正式发表

为什么仍把它们归入路线 C：靶子相同（观测缺失），机制相同（生成先验当监督）。差别只在先验的维度——视频先验额外提供时序一致性，静态遮挡场景下 2D 先验已够用，成本低得多。

6路线 D：视频扩散当 SDS 训练信号

这一族的共同特征：视频扩散模型不产出数据，只产出梯度。它面向的是「生成」而非「重建真实人」，但机制（视频先验如何变成可微信号）对重建同样有效，故单列路线。

PhyGenHOI（2026-05）

arXiv 2605.30268。文本驱动的 4D 人-物交互生成：人体作为语义 agent 由 motion diffusion 的 HMSD（Human Motion Score Distillation）驱动，物体作为物理 agent 由 MPM 仿真，接触检测后重新仿真以体现动量传递与形变；最后用 Temporally-Masked Video-SDS——只在接触帧附近注入视频先验，既提升交互保真度又不破坏物理上已 grounded 的运动。对比 4D-fy 与 AnimateAnyMesh。
对重建的启发：SDS 的作用域可以是局部的（只作用于接触/遮挡区间），不必全程施加——这能大幅减轻 SDS 常见的过饱和与过度平滑。

Animate3D / AKD

用视频扩散模型对静态 3D 资产做动画生成（多视角视频 + 4D SDS 组合）。⚠️【待核实】未核实具体 arXiv 编号，此处只记方法名与所属家族

DreamPhysics

用视频扩散先验估计 3DGS 的物理属性（材料/弹性等），再配合 MPM 仿真生成 4D 内容；提出用 SDS + 帧插值 + log gradient 优化物理参数，而非直接用生成视频做显式监督。与并行工作 PhysDreamer 属同一问法。⚠️【待核实】检索得到的 arXiv 链接形式异常（2406.1476 非 2024 年合法编号），编号待核实，此处不给链接

对重建任务的风险提示

SDS 的固有问题是把 2D/视频先验「投影」进 3D 时产生的过饱和、纹理漂移与多视角 Janus 问题；且它优化的是「看起来像」，不是「几何正确」。若目标是可交付的真实人体资产，SDS 更适合作为局部、短时、有掩码约束的正则项（如 PhyGenHOI 的做法），而非主要监督。

7路线 E：VDM 当确定性几何编码器（非生成式复用）

DreamHand: Repurposing Video Diffusion Models for Occlusion-Robust Egocentric 3D Hand Motion Recovery（2026-08）

arXiv 2608.20308｜SJTU / NTU / CUHK / ACE Robotics｜代码 github.com/ggxxii/dreamhand

  • 问题：第一人称视频里手被物体遮挡、甚至短暂离开画面（out-of-sight）时，单帧回归器无从下手；滑窗模型超出窗口即断；而近期的生成式做法要跑多步随机采样先渲染出 RGB，既有延迟又把生成伪影带进姿态估计。
  • 核心做法：把预训练 VDM 改造成确定性几何编码器——不做生成，只在 clean latent 上做一次前向提取特征（Deterministic Clean-Latent Encoder），再用双向时空解码器（Bidirectional Spatiotemporal Decoder）在整段 clip 上推理，让后面的可见帧帮前面的遮挡时刻；另提供基于射线的相机求解器（Ray-Based Camera Solver）以支持测试期不提供内参的配置。
  • 数字：五个第一人称基准上 SOTA；遮挡严重的 ARCTIC 上 MPJPE-p 降 30%，HOT3D 降 40%；把「出画的手」也纳入评测后提升达 46%-61%。不依赖外部手部检测器。
  • 为什么值得单独列为一条路线：它把 VDM 从「渲染器」降级为「编码器」，代价是放弃像素输出，收益是更快、更确定、无生成伪影。这与重建任务的需求高度契合——重建要的是几何与对应关系，不是好看的中间帧。
  • 对本项目的直接启发：我们的链路目前靠 COLMAP + 3DMM + 657 点 landmarks 提供几何线索；在遮挡/欠约束片段，可以考虑用 VDM 的 clean-latent 特征做「时序补全的对应先验」，而不是先渲染多视角视频再重建。注意其局限：离线片段级，不适合在线/实时；对可见锚点质量敏感。

8路线 F：视频扩散生成动态外观（pose-dependent dynamics）

AvatarDynamizer: From Static to Dynamic Human Avatars via Generative Dynamic Textures（2026-08）

arXiv 2608.19900｜MPI for Informatics + 波恩等｜项目页 vcai.mpi-inf.mpg.de/projects/AvatarDynamizer

  • 靶子：person-agnostic 方法能从单图/视频/文本得到静态 3D avatar，但骨架驱动的动画没有真实的表面动力学（衣物褶皱）；person-specific 方法动力学真实却需要昂贵的多视角逐人采集。
  • 洞察（原文关键判断）：差异在于表面动力学的嵌入位置。图像空间方法把动力学嵌入视频先验与 3D 姿态控制，能用上基础模型但牺牲 3D 一致性；texel / 高斯回归方法把动力学嵌入确定性的前馈回归，天然保 3D 一致却无法直接利用预训练 2D/视频生成先验，且在数据有限时容易退化成过度平滑或近乎静态。
  • 做法：引入 texture-space 表面动力学嵌入——把 pose-dependent 动力学显式写进彩色的动态纹理图（texel 空间时空自洽、且与预训练视频扩散模型兼容），再由 Generalized Gaussian Decoder 解码为 3D Gaussians 保证多视角一致渲染；Dynamic Texture Generator 则把动力学学习表述为 texel 空间的条件图生图任务（输入静态纹理 + 姿态法线图，输出带褶皱的动态纹理），从而直接复用视频生成先验。
  • 数据：自建 DynaHuman——58 位 actor × 100 台 4K 相机，每段序列约 27000 帧。
  • 定位：不解决「重建」，解决的是「重建之后动画起来像不像」。对以「固定表情系数消除微动」为目标的链路，这条路线提示了另一条思路：把难建模的高频动力学搬到 2D 纹理空间去生成，而不是在 3D 表示里硬拟合。

稀疏视角 + 条件工程Diffuman4D骨架 latent + Plücker 相机依赖已知相机；分组去噪不一致需滑窗补偿
上下文工程（规模化的关键）4DAnyone3D 骨架 + RCP/TCR 注意力预算管理真实无控场景泛化仍差（DyMVHumans 21.03 vs 24.33）；背面属推测
去几何先验（通用性优先）Flex4DHuman仅相对相机位姿（PRoPE）一致性全压给生成模型；人体细节线索（体型、贴身衣物）无处输入
接口下沉（绕过 RGB）Latent-to-4D同 VAE 家族的共享 latent 空间绑定 VAE 家族；4D 监督数据稀缺；尚无人体专用版
补全当监督（承认边界、分工）AHOY!、StudioRecon扩散生成密集伪监督 + 几何关联需专门机制吸收生成数据的不一致；流程长
非生成式复用（编码器）DreamHandVDM 的 clean-latent 特征离线片段级、非实时；依赖可见锚点
动态外观生成（texel 空间）AvatarDynamizer视频扩散的条件图生图能力依赖准确姿态与纹理初始化；计算成本高

一句话脉络

2024 年解决的是「能不能」（多视角扩散 + 可变形高斯能否闭合）；2025 年解决的是「人体上准不准」（骨架/法线条件、360° 覆盖、级联解耦）；2026 年解决的是「规模与接口」——上下文怎么在有限注意力下保持全局一致（RCP/TCR）、生成与重建的接口放在哪一层（latent vs RGB）、以及视频先验能不能不做生成就直接当特征用（DreamHand）。

硬件现实（单卡 3090 24GB）

  • backbone 规模决定可行性：Flex4DHuman 建在 Wan 2.1 1.3B 上，是本调研中显存最友好的多视角生成路线；4DAnyone 建在 Wan2.2-TI2V-5B 上，且要同时生成数十个视角，原始配置是 128×H20-3E 训练，单卡复现需要显著降采样或分组。
  • 分组不是可选项而是必选项：只要目标视角数超过单次前向容量，就必须分组，也就必然遇到 4DAnyone 指出的两个瓶颈（参考侧 O(N)、目标侧组间漂移）。选型时应优先看方法有没有针对性的上下文管理机制，而不是看生成样例好不好看。
  • Diffuman4D 提供了 demo_4d_tiny（4 输入相机 × 15 帧 → 44 相机 × 15 帧）这类小配置，适合先验证链路再放大。

与本仓既有资产的对接点

  • 本仓已有 4danyone/ 复现脚本（00_setup_env / 00a_setup_env / 01_download_models / 02_run_inference / run_all），说明路线 A 已进入工程验证阶段；下一步的瓶颈更可能在显存与视角数，而非环境。
  • 条件信号我们全都有：COLMAP 相机位姿、3DMM/MHR 头模、SAM3 person mask、ExpTracker 657 点 landmarks——这恰好能拼出 Diffuman4D / 4DAnyone 需要的「骨架 + 相机」条件。相对而言，骨架条件路线对我们是低改造成本的；Flex4DHuman 的纯位姿路线改造更少但与现有先验脱钩。
  • 「固定表情系数消除微动」的目标下，路线 A 的整段生成可能过重：若微动是主要矛盾，路线 C 的分工思路（背景用生成、人体用几何 + 局部生成补全）比端到端生成更可控，也不会把生成的身份漂移引进人脸区域。
  • 注意生成与重建的口径差：生成视频 PSNR 高 ≠ 4DGS 重建质量高；4DAnyone 的 DNA-Rendering 24.33 dB 是重建后的渲染指标，与「生成视频的 PSNR」不是一回事。

推荐的三步验证顺序（低风险 → 高风险）

  1. 先做条件可用性验证：把我们现有的 MHR/landmarks 投影成骨架条件图，在 Diffuman4D 的小配置上跑通「4 视角 → 44 视角 → 3DGS」，确认生成的视角对我们的人体（贴身/宽松衣物）是否可用。
  2. 再验证上下文规模：把目标视角从 44 提到 100+，观察是否出现目标侧结构漂移；若出现，则 4DAnyone 的 RCP/TCR 就不是可选项。
  3. 最后才考虑换 backbone：若 1.3B 级质量不足以支撑人脸/手部细节，再评估 5B 级 backbone 在 24GB 上的可行降级方案（分块、降帧、降低目标视角数）。

12未解问题与可改进方向

[高优先级] 评测口径不统一，跨论文数字不可比

各工作分别报告重建后渲染 PSNR（DNA-Rendering）、生成视频质量、用户研究（SV4D）、以及不同基线下的相对提升。4DAnyone 与 Flex4DHuman 都声称在 DNA-Rendering / ActorsHQ 上超越前作，但基线配置（是否给 GT 骨架、目标视角数、帧数）并不一致。改进建议：内部复核时统一「同一批输入视频 + 同一 4DGS 优化器 + 同一评测帧」的三同口径，只比较生成视频的质量与一致性，不比较论文 headline 数字。

[高优先级] 生成区域没有可信度标记

所有路线 A/C 的方法都在「脑补」未观测区域，但输出里没有任何机制告诉下游「这块是观测到的、那块是生成的」。4DAnyone 自己承认背面细节是「与正面合理自洽的推测」。改进建议：在 4DGS 优化时按观测覆盖率为每个高斯带上置信度权重，让人脸等关键区域只被真实观测约束，生成内容只作用于低置信度区域——这正好契合我们「人脸必须可信」的需求。

[中优先级] 时序一致性缺标准指标

FV4D 只在 SV4D 2.0 等少数工作中使用，多数人体工作仍以单帧 PSNR/SSIM/LPIPS 报告，而「时序闪烁」恰恰是这条路线最典型的失败模式（SV4D 2.0 项目页明确提到 4D Gaussians 的时序闪烁与漂浮点）。改进建议：内部验收加一项「静态段落的帧间差分抖动」指标。

[中优先级] 生成与重建的接口仍以 RGB 为主

路线 A 的绝大多数工作都要先把 latent 解码成视频再喂重建器，而 Latent-to-4D 已经证明同 VAE 家族的 latent 可以直接对接 4D 解码器并带来可观提升。改进建议：若后续在自研链路上引入视频先验，优先评估 latent 直连，避免 RGB 往返的信息损失。

[低优先级] 非生成式复用尚未在人体全身重建上验证

DreamHand 证明了 VDM 的 clean-latent 特征可以替代多步采样做几何回归，但只做了手部。全身人体（含衣物、自遮挡）能否用同样方式提取「遮挡感知的对应特征」仍是空白。潜在机会：这可能是比「生成多视角视频再重建」更轻量的路线，尤其适合 3090 这类单卡资源。

优先级问题可否自行验证预期收益
高评测口径不可比可以（统一三同口径）避免被 headline 数字误导选型
高生成区域无置信度标记可以（用 SAM3 mask + 观测覆盖率）保护人脸/手部不被脑补内容污染
中时序一致性无指标可以（帧间差分抖动）提前发现闪烁，避免后期返工
中接口仍以 RGB 为主需要改造，成本中等减少信息损失，提升跨视角一致
低VDM 特征复用未在全身验证需要实验，风险较高可能打开更轻量的重建路线
