1论文概要与核心贡献

一句话概括:前馈 3DGS 在少视角时崩溃的根因不在重建头,而在重建头读到的那几层 geometry token 里根本没有未观测区域的证据;既然重建只缺「缺失视角的 token」而不缺「缺失视角的像素」,就不必用图像扩散模型去合成整张 RGB 再让 encoder 重新压一遍。DensiTok 把 encoder 输出的 $L$ 层 token 栈压成一个 4 通道的紧凑 latent,在这个 latent 序列里用单步 flow matching 补出未观测视角、再解回 $L$ 层 token 交给冻结的原始重建头。encoder 全程冻结,重建头冻结或只微调图像嵌入层。

核心贡献一句话:把「补证据」的位置从像素空间搬到token 空间并压到 4 维 latent,使得补全代价从「跑一次大图像生成模型 + 全分辨率重编码」降为「一个小 DiT 走一个 Euler 步」——在 AnySplat 上 $n=3$ 输入时 RE10K PSNR 24.28 > 24.04(该 backbone 自己的 $N=16$ 稠密参考)、DL3DV 24.28 > 22.30,而耗时 0.267 s < 0.434 s(Table 1)。$n=2$ 时相对 GLD 提速 133–151×(Table 8)。三个 backbone(AnySplat / WorldMirror / DA3)全部一致提升,且三者都不需要外部相机内参/外参(Table 7)。

论文自述的三条贡献(§1 / Abstract)

  1. 问题重述:指出少视角瓶颈位于重建头上游——encoder 从少量未标定图像得不到跨视角证据,token 只描述被真正看到的表面,遮挡与未覆盖区域完全没有 token,重建头只能把这些空缺渲染成空洞、浮尘与模糊。
  2. LAM-VAE:用层级自适应调制(level-adaptive modulation)把重建头实际读取的 $L$ 层 token 融合并压到 $d_z=4$ 的 latent,使一个 VAE 与一个生成器就能同时服务所有层,且不必预先固定「哪几层重要」。
  3. 相机条件 DiT + 单步化:在 latent 序列上做 rectified flow matching,以全 $N$ 视角相机(Plücker 射线)为条件补全未观测视角;再用 20k 步单步微调把采样压到 1 个 Euler 步。补全结果经 VAE 解码器展开回每层 token,交给原始头。
⚠️ 宣称边界(本笔记复核):① 全部定量结论建立在 RE10K + DL3DV 两个室内/物体级数据集 上,跨数据集泛化只有 Appendix D.1 的 ETH3D / ScanNet / Mip-NeRF 360 三组(仍是同一 backbone、同一 $N=16$ 协议),没有室外大场景或动态场景;② 「$n=3$ 超过 $N=16$」的对比里,稠密参考与 DensiTok 的评测视角采样是同一套(4 个新视角都在首末观测相机之间),而 DensiTok 生成的 13 个虚拟视角也全部落在这个区间内——生成分布与评测分布天然重合,这个「超过稠密」不宜直接外推为「少拍几张反而更好」(详见 §16);③ 「冻结 backbone」是真的,但每个 backbone 要各自训一套 LAM-VAE + DiT(Table 1/6 三套独立结果),不是一份权重通吃;④ 仓库无源码,所有超参不可验证。

2研究背景与动机

论文的动机不是「刷点」,而是对现有四条补救路线的可指认缺陷逐条反驳。它的核心洞察只有一句,但非常锋利:

「What the model lacks, then, is not pixels but tokens.」(§1 原文)——模型缺的不是像素,而是 token。这句话推出一个关键推论:像素是绕路(pixels are a detour)。重建只需要「缺失视角的 token」,而图像生成方法产出的是整帧 RGB,encoder 随后要把它重新压成 token,「生成器产出的大部分内容被立刻丢弃」。更糟的是像素不是共享的 3D 表示,跨生成视角的一致性只能被「鼓励」而无法被「强制」,重建被迫去拟合彼此矛盾的视角。

路线 ①:图像空间合成额外视角

用多视角/视频扩散模型生成新视角,或对渲染结果做修复后再拟合场景。失败模式是双重开销:全分辨率跑一次大生成模型,再把扩大后的视角集合重新过一遍 geometry encoder;且像素不是共享 3D 表示,跨生成视角一致性只被"鼓励"、无法"强制",重建被迫拟合互相矛盾的视角。论文的直接措辞:"pixels are a detour"(像素是绕路)。

路线 ②:专门训稀疏视角架构

不补任何新证据,而是把「从少量视角能榨的对应关系」榨到极限(pixelSplat / MVSplat / DepthSplat / NoPoSplat 一系)。失败模式:上限被输入视角的覆盖范围锁死,且是绑死少量固定视角数的独立架构,不能随视角数伸缩。Table 7 里这类方法在 $n$ 增大时普遍不单调(如 VolSplat RE10K 从 $n{=}2$ 的 21.73 到 $n{=}7$ 的 28.33 是涨的,但 MVSplat 从 26.32 掉到 21.24),说明它们各自的适用视角数是写死的。

路线 ③:直接在 token 空间生成(最接近本文)

Jang et al. 2026 直接在 token 空间生成,方向对了,但没有压缩 latent——必须在上千通道的特征上跑级联多步生成器,代价仍然高昂。这正是 DensiTok 的两处针对性改动:① 先把 $L$ 层 × 2048 通道压到 4 通道;② 把多步采样压到单步。

路线 ④:本文——稠密化证据本身

不生成像素,也不改架构,而是在 encoder 与重建头之间插一个插件:把 $n$ 个观测视角的 token 编码成 latent 序列,为 $N-n$ 个未观测视角生成 latent,解回每层 token。encoder 与重建头都冻结(后者可选最小适配),因此一份设计可以套到不同预训练 backbone 上。

4模块①:LAM-VAE 编码器

这一节解决的是「往哪个空间里补」的问题。重建头要的不是最后一层,而是 $L$ 个固定中间层的整个栈;如果直接在这些层上做生成,等于把问题维度乘 $L$($L=4$、每层 $d_f=2048$ 或 $3072$)。LAM-VAE(Level-Adaptive Modulation VAE)的做法是:先把 $L$ 层按 token 融合成一个向量,再压到 $d_z=4$,于是「一个 VAE + 一个生成器」就能管住全部 $L$ 层。

为什么需要「层级自适应」而不是固定选层

前作 GLD(Jang et al., 2026)在特征空间做 NVS 时,是先固定挑几层做 flow matching、再用冻结 encoder 把其余层推导出来。本文的反驳很直接:哪几层承载最有用的信息,随 backbone 而变、甚至随场景而变,预先钉死一个子集并不稳。于是改为让每个 token 自己决定每层贡献多少——这就是 LAM 的动机。

三个容易被忽略的设计细节,恰好是这套融合能work的原因:
  1. 层级独立 LayerNorm:每层先用自己的 $\operatorname{LN}_\ell$ 归一化。不做这步,层间量级差异会让某一层凭幅值压倒其他层,gate 还没开始学就已经失效。
  2. gate 是「比较」而不是「打分」:$L$ 个摘要同时送进一个 MLP,所以第 $\ell$ 层的 logit 依赖其他层——它在做相对排序;若每层独立过一个打分器,就成了各打各的绝对分,softmax 之后的语义会变。
  3. 用增益 $g_\ell=L\alpha_\ell$ 而不是权重 $\alpha_\ell$ 本身:$\sum_\ell g_\ell=L$,$\mathbb{E}[g_\ell]=1$,于是「均匀权重」正好退化回朴素拼接。gate 学到的只是在拼接基线附近的重加权,而不是把输入整体缩小 $L$ 倍——后者会让后续 transformer 的输入尺度随 $L$ 漂移。

数学形式化

融合(式 3):gate 输出的权重被放大成增益后,对层级投影做加权和。等价的实现方式是「把增益加权后的各层拼接再走一个线性层」,论文明确指出这一点——它说明 LAM 相比朴素拼接只多了一条极窄的 gate 通路,参数量几乎不变。

$$\mathbf{h}=\sum_{\ell=1}^{L}g_\ell\,\mathbf{W}_\ell\mathbf{f}_\ell,\qquad g_\ell=L\,\alpha_\ell,\quad \boldsymbol{\alpha}=\mathrm{softmax}\big(\mathrm{MLP}([\,\mathbf{S}\mathbf{f}_1;\dots;\mathbf{S}\mathbf{f}_L\,])\big)$$(式 3)

残差(式 4):$d_z=4$ 是极窄的瓶颈,而层级信息在进入 transformer 前已经在 $\mathbf{h}$ 里被混掉了,单层特有的细节容易被抹平。于是让归一化后的原始层特征绕过 transformer,用同一组 $\alpha_\ell$ 加权后直接加到后验均值上——「谁主导了融合,谁就来修正均值」。

$$\bm{\mu}=\bm{\mu}_0+\sum_{\ell=1}^{L}\alpha_\ell\,\mathbf{P}_\ell\mathbf{f}_\ell,\qquad \log\bm{\sigma}^2\ \text{保持 VAE encoder 的输出不变}$$(式 4)

采样与推理:

$$\mathbf{z}=\bm{\mu}+\bm{\sigma}\odot\bm{\epsilon}_{\mathrm{vae}},\ \ \bm{\epsilon}_{\mathrm{vae}}\sim\mathcal{N}(\mathbf{0},\mathbf{I})\quad(\text{训练})\qquad\Longleftrightarrow\qquad \mathbf{z}=\bm{\mu}\in\mathbb{R}^{d_z}\quad(\text{推理})$$(式 4 附)

把所有 $N$ 个视角 × $K$ 个 token 的 latent 叠起来得 $\mathbf{Z}\in\mathbb{R}^{N\times K\times d_z}$;补全场景下只编码 $n$ 个观测视角,得 $\mathbf{Z}^{\mathrm{obs}}\in\mathbb{R}^{n\times K\times d_z}$,即下一节生成器的输入。

压缩比算一下就知道这个瓶颈多极端:AnySplat / WorldMirror 是 $4\times2048=8192$ 个通道值 → $4$ 个,约 2048×;DA3 是 $4\times3072=12288$ → $4$,约 3072×。作为对照,图像 VAE(如 SD 的 $8\times8\times4$)在空间上还留着 64 个位置。DensiTok 敢这么压,前提是重建头的下游监督(式 9 里的 rgb / pose / depth 项)保证了「压掉的东西头本来也不用」——单靠 token 层 L2 重建是压不出这个比例的(见下节「监督信号」)。代价是 $d_z$ 成为全链路唯一的信息闸口,Table 11 的 $d_z$ 消融也印证了这一点(见 §13)。

前向流程

  1. 取层:冻结的 $\mathcal{E}_{\mathrm{geo}}$ 跑 $n$ 张观测图,按 backbone 配置抽取 $L=4$ 个中间层的 token,得 $\mathbf{F}^{\mathrm{obs}}_\ell\in\mathbb{R}^{n\times K\times d_f}$(式 2)。
  2. 逐层归一:每层过一个独立的 $\operatorname{LN}_\ell$,消掉层间幅值差。
  3. 算 gate:共享线性把每层压到 64 维 → 拼成 256 维 → gating MLP(hidden 128)出 $L$ 个 logit → softmax 得 $\alpha$。这一步逐 token 独立做,drop 掉视角与 token 下标。
  4. 融合:增益 $g_\ell=L\alpha_\ell$ 加权各层 $\mathbf{W}_\ell\mathbf{f}_\ell$,得 $\mathbf{h}\in\mathbb{R}^{512}$。
  5. 进 transformer:$n$ 个视角的 $\mathbf{h}$ 拼成一个长序列,走 6 对 frame/global block;frame block 只在单视角内注意,global block 跨视角注意,位置由 2D RoPE 编码。
  6. 出后验:每 token 出 $\bm{\mu}_0$ 与 $\log\bm{\sigma}^2$(各 4 维)。
  7. 加残差:用第 3 步的 $\alpha$ 把 $\mathbf{P}_\ell\mathbf{f}_\ell$ 加权加到 $\bm{\mu}_0$ 上,得最终均值 $\bm{\mu}$。
  8. 采样 / 取均值:训练时 $\mathbf{z}=\bm{\mu}+\bm{\sigma}\odot\bm{\epsilon}$,推理时直接取 $\mathbf{z}=\bm{\mu}$。

该模块的监督信号

Stage 1 的损失不是「把 token 重建回去」这么朴素,而是双层的:

$$\mathcal{L}_{\mathrm{feat}}=\frac{1}{L}\sum_{\ell=1}^{L}\Bigl\|\operatorname{LN}_\ell\bigl(\hat{\mathbf{F}}_\ell\bigr)-\operatorname{LN}_\ell\bigl(\mathbf{F}_\ell\bigr)\Bigr\|_2^2$$(式 8)
$$\mathcal{L}_{\mathrm{VAE}}=\lambda_{\mathrm{feat}}\mathcal{L}_{\mathrm{feat}}+\lambda_{\mathrm{KL}}\mathcal{L}_{\mathrm{KL}}+\lambda_{\mathrm{rgb}}\mathcal{L}_{\mathrm{rgb}}+\lambda_{\mathrm{perc}}\mathcal{L}_{\mathrm{LPIPS}}+\lambda_{\mathrm{pose}}\mathcal{L}_{\mathrm{pose}}+\lambda_{\mathrm{depth}}\mathcal{L}_{\mathrm{depth}}$$(式 9)

权重 $(\lambda_{\mathrm{feat}},\lambda_{\mathrm{KL}},\lambda_{\mathrm{rgb}},\lambda_{\mathrm{perc}},\lambda_{\mathrm{pose}},\lambda_{\mathrm{depth}})=(0.1,\,10^{-3},\,1,\,0.05,\,10,\,1)$。三个工程细节:

  • 式 8 里也带 $\operatorname{LN}_\ell$:不只是输入侧归一化,误差度量也归一化——否则深层通道幅值大,PCA 式的 $L_2$ 会被深层独占,L 层的权重形同虚设。
  • 下游一致性项才是主力:$\lambda_{\mathrm{rgb}}=1$、$\lambda_{\mathrm{pose}}=10$,都远大于 $\lambda_{\mathrm{feat}}=0.1$。论文把 $\hat{\mathbf{F}}_\ell$ 再喂进冻结的相机/深度/Gaussian 头,与原 token 的输出比对。理由写得很清楚:「token 重建好 ≠ 冻结的头能用」——头是在完整 token 上训出来的,它可能对某种 $L_2$ 意义下很近的扰动完全不鲁棒。把冻结头当下游 decoder 一起算 loss,是这套压缩能成立的根本。
  • KL 有 warmup + free-bits:权重在前 $10{,}000$ 步从 $0$ 线性升到 $10^{-3}$,并用 0.5 nats / 维度的 free-bits 阈值。$d_z=4$ 时若不设 free-bits,KL 很容易把 4 维压成 1–2 维有效维度,DiT 就没得生成了。$\lambda_{\mathrm{KL}}=10^{-3}$ 之小也印证:这个 VAE 几乎不追求先验匹配,只求「可解码 + 平滑到能被 flow matching 拟合」。
和后文的接口:这里产出的 $\mathbf{Z}^{\mathrm{obs}}$ 是 Stage 2 的唯一条件输入;而 $\mathbf{Z}$(全 $N$ 视角编码)只在训练时可得,作为 flow matching 的目标。也就是说 VAE 一旦冻结,整个人工标注空间就定死了——后面 DiT 的上限被 Stage 1 的压缩质量锁住,这是三阶段训练最容易踩的耦合风险。

5模块②:相机条件 DiT 潜空间补全

拿到了 $n$ 个视角的 $\mathbf{Z}^{\mathrm{obs}}$ 之后,要在同一个 $N\times K\times d_z$ 的张量里把 $(N-n)$ 个未观测视角「想出来」。这里有两个硬约束决定了架构:① 未观测视角没有任何图像,唯一的线索就是「它该在哪个位置看」——即相机;② 观测视角必须逐位精确保持,不能被生成过程的噪声污染,否则冻结的重建头会看到「被轻微改过的真实 token」,反而比不补还差。

问题设定

DiT 吃三样东西:观测 latent $\mathbf{Z}^{\mathrm{obs}}$、掩码 $\mathbf{m}\in\{0,1\}^N$、以及全部 $N$ 个视角的相机 $\mathbf{g}_1,\dots,\mathbf{g}_N$。输出 $\tilde{\mathbf{Z}}\in\mathbb{R}^{N\times K\times d_z}$,其中观测位置严格等于 $\mathbf{Z}^{\mathrm{obs}}$。训练目标是那个「如果当初把 $16$ 张图全喂给 encoder 会得到什么」的 $\mathbf{Z}$——它只在训练时存在。

为什么是「补 token」而不是「补像素」,这里的架构给出了理由:相机是唯一能指定「要生成哪个视角」的量,而相机在 token 空间里可以逐 token 精确注入(Plücker 射线嵌入与 latent 共享 $K$-token 布局);在像素空间里相机只能作为全局条件(如 camera ray 的 per-pixel 编码),与图像内容的空间对应关系要靠网络自己学。token 空间的相机条件是同构的、无歧义的。

数学形式化:训练时的插值状态

rectified flow matching 的约定:$t=0$ 是干净 latent,$t=1$ 是纯噪声。观测视角的 $m_i=1$,整项被 $m_i$ 钉在 $\mathbf{z}^{\mathrm{obs}}_i$ 上,任何时候都不进噪——这直接实现了「观测视角必须精确保持」的约束,不需要额外的 mask 后处理。

$$\mathbf{x}_{t,i}=m_i\,\mathbf{z}^{\mathrm{obs}}_i+(1-m_i)\bigl[(1-t)\,\mathbf{z}_i+t\,\bm{\epsilon}_i\bigr],\qquad\bm{\epsilon}_i\sim\mathcal{N}(\mathbf{0},\mathbf{I})$$(式 5)

每个视角带自己的时间 $\tau_i=t(1-m_i)$:观测视角恒为 $0$(干净),未观测视角跟随全局 $t$。这一个标量让同一套网络在同一序列里同时处理两类视角,不必分两路 forward 或加视角类型嵌入。

数学形式化:速度场与一步采样

速度的定义是「从干净指向噪声」,所以目标速度就是 $\bm{\epsilon}_i-\mathbf{z}_i$。这与常见「从噪声指向数据」的约定符号相反,理解采样方向时必须注意:采样是从 $t=1$ 往 $t=0$ 反向积分。

$$\mathcal{L}_{\mathrm{FM}}=\frac{1}{(N-n)\,K\,d_z}\sum_{i:m_i=0}\bigl\|\widehat{\mathbf{v}}_{\theta,i}-\mathbf{v}^{\star}_{i}\bigr\|_2^2,\qquad\mathbf{v}^{\star}_i=\bm{\epsilon}_i-\mathbf{z}_i$$(式 11)

分母是 $(N-n)K d_z$,即只对未观测视角的每个 latent 元素平均,观测视角被完全排除在损失之外(它们恒为干净状态,不进噪,自然也不该被监督)。

Stage 3 把时间钉死在 $t=1$,单步 Euler 就从噪声直接到干净:

$$\tilde{\mathbf{z}}_i=\bm{\epsilon}_i-\widehat{\mathbf{v}}_{\theta,i}\quad\Longrightarrow\quad \mathcal{L}_{\mathrm{FM}}\big|_{t=1}=\frac{1}{(N-n)K d_z}\sum_{i:m_i=0}\bigl\|\tilde{\mathbf{z}}_i-\mathbf{z}_i\bigr\|_2^2$$(式 13)
这个「等价」是有代价的,论文自己也点明了:固定 $t=1$ 后,flow matching 损失退化成对全视角 latent 的直接回归。但 Stage 3 的最优点不是 Stage 2 多步 ODE 解的蒸馏——论文明确说「不施加与 Stage 2 多步解的 ODE 一致性约束」。也就是 Stage 3 做的是重新训练一个一步映射,而非蒸馏。后果:$N$ 步采样的质量优势会被部分放弃(Table 10 里 50 NFE 的 22.86 就高于一步的 22.56),一步版是精度换延迟的显式取舍。

AdaLN 的具体形式(A.1)

两种 block 共用同一套结构、参数各自独立。条件向量的构造是相加而非拼接:

$$\mathbf{c}_{i,k}=\mathbf{e}^{\mathrm{time}}(\tau_i)+\mathbf{e}^{\mathrm{cam}}_{i,k}\in\mathbb{R}^{d_h},\qquad \bigl(\boldsymbol{\beta},\boldsymbol{\gamma},\boldsymbol{\alpha}\bigr)=\mathrm{MLP}_{\mathrm{block}}(\mathbf{c}_{i,k})$$(A.1,原文无编号)

每个 block 把 $\mathbf{c}_{i,k}$ 映射成自己的一组 shift/scale/gate,分别供给 attention 分支与 MLP 分支。相加而非拼接的含义是:时间与相机被当作两个可叠加的调制偏移,它们在同一 $d_h$ 空间里共存;好处是 $\mathbf{c}$ 的维度与 $d_h$ 一致,不需要为两路条件各配一套投影。

采样时的「重置」机制(容易被漏掉的一步)

多步采样时,每个 Euler 步之后都要把观测视角的 latent 强行写回 $\mathbf{Z}^{\mathrm{obs}}$。原因:Euler 积分是逐元素更新,即使观测视角在训练时永远处于干净状态,多步累积的数值误差与网络泛化误差也会让它们缓慢漂移;一旦漂移,下游重建头看到的不再是「真实的观测 token」,而是被污染的版本,render 结果会在本应完美的观测视角上出现瑕疵。重置保证「条件永不退化」。

前向流程(Stage 2 训练一步)

  1. 采 $n\sim U\{2,\dots,8\}$,不放回选 $n$ 个观测视角,其余 $N-n$ 为未观测;
  2. 全 $N$ 视角过冻结 encoder + 冻结 LAM-VAE,得 $\mathbf{Z}$(目标)与其中的 $\mathbf{Z}^{\mathrm{obs}}$(条件);
  3. 采全局时间 $t=\mathrm{sigmoid}(u),\ u\sim\mathcal{N}(0,1)$——不是均匀分布,向两端加权;
  4. 按式 5 构造 $\mathbf{x}_{t}$:观测视角取 $\mathbf{z}^{\mathrm{obs}}$,未观测视角插值到噪声;
  5. 构造 $\mathbf{c}_{i,k}$:时间 $\tau_i=t(1-m_i)$ + 该视角对齐后的 GT 相机 Plücker 嵌入(§6);
  6. DiT 前向,出 $\widehat{\mathbf{v}}_{\theta,i}$;按式 11 算 $\mathcal{L}_{\mathrm{FM}}$;
  7. 额外一路:用 $\hat{\mathbf{z}}^{(t)}_{0,i}=\mathbf{x}_{t,i}-\tau_i\widehat{\mathbf{v}}_{\theta,i}$ 反推干净 latent,送冻结 VAE decoder → token → 冻结重建头,算 rgb / LPIPS / pose / depth(式 12,见 §8);
  8. 反向传播,只更新 DiT 与相机嵌入(以及 A.2 的 $h_{\mathrm{img}}$、$\mathbf{e}^{\mathrm{miss}}$)。

该模块的监督信号

DiT 的监督是三层嵌套的,一层比一层「更靠下游」:

  • latent 层(式 11):$\mathcal{L}_{\mathrm{FM}}$,权重 $1$。只描述「速度对不对」,不保证解出来的 token 有用。
  • token → 图像层:把 $\hat{\mathbf{z}}_0$ 解码回 token 再渲染,与 GT 图像比 rgb($\lambda{=}1$)与 LPIPS($\lambda{=}0.05$)。这一步必须回传穿过冻结的 VAE decoder 与冻结重建头,所以求导链路很长。
  • token → 相机/深度层:pose($\lambda{=}10$)与 depth($\lambda{=}1$)。其中 pose 项是对「原全视角 token 过冻结相机头」的 teacher 做 Huber,并且作用在相机头每一个 refine 迭代上、早期迭代权重更小;depth 项只在 teacher 的深度置信度选中的像素上算平方误差。用 teacher 而不是 GT 位姿,是为了让 DiT 学「和 backbone 自己一致的位姿」而非「绝对正确的位姿」——这与 §6 的相机对齐是同一套思路。
为什么 latent 损失不能单独用:$d_z=4$ 的 latent 上没有定义任何「有用性」度量。两个 latent 在 $L_2$ 下接近,解码出的 token 可能让 Gaussian 头给出完全不同的颜色(尤其 AnySplat 那种需要 RGB 外观输入的)。论文的做法是把「有没有用」的判断完全交给冻结的下游头——冻结模块在这里同时充当了正则器与评估器,这是全文最省事也最讨巧的一步。

6模块③:相机条件双轨(训练 / 推理)

这是全文最容易做错、也最容易被读者跳过的一节。DiT 需要 $N$ 个视角的相机,但训练时有 GT 却不能用,推理时没有 GT 只能猜——两条路径必须产出「同一个世界坐标系下、同一尺度」的相机,否则 DiT 在训练与推理看到的是两种分布,一步采样必然崩。

问题的精确形状:只差一个尺度

关键观察是:backbone(AnySplat / WorldMirror / DA3)的相机头已经在第一观测视角下归一化输出相机,而数据集提供的 GT 相机也按同样约定表达。所以两者的全局旋转与平移已经共享,只差一个全局尺度——因为 backbone 重建出的场景尺度是任意的(单目/少视角几何本身就只恢复到相似变换)。

如果直接拿原始 GT 相机训练会怎样:DiT 学到的相机条件落在「数据集尺度」的世界里;推理时喂进去的是「backbone 预测尺度」的相机,中心坐标可能差一个数量级。Plücker 射线嵌入对中心偏移极敏感(它编码的是相对于相机的方向与力矩),尺度错位会让条件向量完全失真。论文用单因子缩放这一个动作就把这个 gap 消掉了——因为两者本来就只差这一维。

训练轨:用预测相机的中心散布去标定 GT

$$s=\frac{\operatorname{spread}\bigl(\{\hat{\mathbf{g}}^{\mathrm{obs}}_i\}_{i=1}^{n}\bigr)}{\operatorname{spread}\bigl(\{\mathbf{g}^{\mathrm{gt}}_i\}_{i=1}^{n}\bigr)},\qquad \mathbf{g}^{\mathrm{aligned}}_i=\bigl(\mathbf{R}^{\mathrm{gt}}_i,\ s\cdot\mathbf{t}^{\mathrm{gt}}_i\bigr),\ i=1,\dots,N$$(§3.4 正文,原文无编号)

要点:缩放因子只算一次、作用到全部 $N$ 个视角(不是逐视角),且只在观测子集上估分子分母。用单因子而非逐视角缩放,才不会破坏相机之间的相对几何(逐视角缩放会让轨迹变形,DiT 学到的就是错的运动先验)。旋转不动,只动中心。

论文原文表述是「rescaling all ground-truth camera centers by a single factor, the ratio of the spread of the predicted centers to that of the ground-truth centers over the observed views」。【待核实】「spread」的具体度量未在正文定义——按上下文应为某种离散度(标准差或包围盒对角线)。这是复现时的真实空白:不同选择会给出不同的 $s$,在长基线序列上差异可能不小。

推理轨:样条 + slerp,且只插不外推

① 预测观测相机冻结相机头从 $\mathbf{F}^{\mathrm{obs}}$ 出 $\{\hat{\mathbf{g}}^{\mathrm{obs}}_i\}_{i=1}^{n}$
→
② 中心插值自然三次样条(natural cubic spline)
+
③ 旋转插值球面线性插值 slerp
→
④ 落位全部虚拟视角放在首末观测相机之间

两个细节值得单独说:

  • 中心用自然三次样条而不是分段线性:相机的运动在实际拍摄中近似平滑,样条的二阶连续性能避免在观测视角处出现「折角」,而折角恰好落在有 GT 对照的位置上会立刻暴露。旋转用 slerp 是因为旋转在 $SO(3)$ 上,线性插值会离开流形、产生非正交的「伪旋转」。
  • 只插值、不外推:所有 $(N-n)$ 个虚拟视角都被放在第一与最后一个观测相机之间。这不是偷懒,而是本文最硬的限制——见 §16。外推意味着要预测「从未被任何观测约束过的空间」,而在 token 空间里没有任何机制能保证外推出的 token 与真实几何一致。

为什么不让 DiT 自己生成相机

一个自然的疑问:既然 token 都生成了,为什么不顺手生成未观测视角的相机?论文的选择是把相机完全外部化,理由在 §3.3 已给:「an unobserved view has no image and its camera is the only information that specifies which view to generate」——相机是输入而非输出,它定义了「要生成什么」。若让网络同时生成相机,任务就变成欠定的:任意相机 + 匹配的 token 都是自洽解,模型可以退化成「生成一个平凡视图」。把相机钉死,等于给生成任务加了一个明确的查询条件。这也与 backbone 的接口一致:相机头解码的是 token,而这里 token 依赖相机——形成一个只有先验相机才能打破的循环,故用「观测视角预测 + 中间插值」的几何先验来打破。

7模块④:外观特征融合

这是一个只有部分 backbone 需要的模块,但缺了它 AnySplat 的结果会直接崩。AnySplat 的 Gaussian 头 $\mathcal{H}_{\mathrm{G}}$ 除了几何 token,还要把每个视角的 RGB 用卷积层 $h_{\mathrm{img}}$ 编码后加到中间特征上,给 Gaussian 颜色提供高频外观。问题很直白:未观测视角没有 RGB。而 LAM-VAE 只补几何 token,补不出颜色。

破局点:未观测视角虽然没有图,但它的相机与深度已经被解出来了(从补全后的 token 解出)。有了相机 + 深度,就可以把观测图 warp 到该视角,得到一个「粗糙但有效」的颜色先验。整个模块是纯几何的、无需任何生成模型,代价几乎为零——这是全文最漂亮的一次「用已有几何换缺失外观」。

三重有效性判据:为什么必须有

$\nu_{c\to i}(\mathbf{u})$ 只在同时满足三条时取 1,任一条不过就丢弃:

  1. 重投影落在 $c$ 图内——否则采样越界;
  2. 深度为正——否则点落在相机背后,投影无意义;
  3. 与 $\hat{\mathbf{D}}_c$ 在相对容差内一致——这是遮挡判据,也是最关键的一条。若某像素在该视角反投影出的 3D 点,重投影到 $c$ 后落在另一物体前面,说明它在视角 $i$ 可见但在视角 $c$ 被遮挡,颜色不可信。与 $c$ 的深度图比对能直接剔除这种情况。

没有第 3 条,遮挡区域的错误颜色会被平均进先验,worst case 比直接用 $\mathbf{e}^{\mathrm{miss}}$ 更糟——因为它带着「看起来合理但完全错误」的高频纹理,conv 会把它当真。

这个模块的隐含依赖链很长,值得警惕:warp 用的相机与深度来自补全后的 token,而补全后的 token 来自 DiT;DiT 又依赖相机条件,相机条件里的未观测相机来自插值。所以外观先验的质量是「DiT 补全质量」的函数——补全差 → 深度差 → warp 差 → 颜色先验差。这是一个正反馈式的耦合,论文没有做「用 GT 深度 warp」的对照实验来隔离这一项。Table 12 显示 $n$ 从 2 增到 7 时「冻结 vs 全量微调 Gaussian 头」的差距从 0.74 dB 缩到 0.10 dB,论文归因为「观测视角间距变小、warp 覆盖率提升」——这恰好是上述依赖链的间接证据:覆盖率越高,先验越可靠,头部越不需要适配。

为什么要微调 $h_{\mathrm{img}}$ + 学 $\mathbf{e}^{\mathrm{miss}}$

论文给了理由,而且是这段最有价值的一句:这些空洞对预训练头来说是 out-of-distribution——它训练时见的都是完整图像,突然输入一片 $\mathbf{e}^{\mathrm{miss}}$ 常量,颜色会崩。所以 Stage 2 在渲染损失下一并微调 $h_{\mathrm{img}}$、并学习 $\mathbf{e}^{\mathrm{miss}}$,让空洞处的 Gaussian 颜色能从周围的观测外观推断,而不是只依赖那个占位符。

注意这句话的言外之意:$\mathbf{e}^{\mathrm{miss}}$ 本身不携带任何颜色信息,它只是一个「此处无数据」的标记。设计上把「推断颜色」的责任交给了卷积的感受野(邻域传播),这是一个很轻量的选择——相比用扩散模型 inpaint 未观测视角的 RGB,它只多了一个可学习标量向量。

采样时间分布:不是均匀的

Stage 2/3 的全局时间按 $t=\mathrm{sigmoid}(u),\; u\sim\mathcal{N}(0,1)$ 采,而不是 $t\sim U(0,1)$。把标准正态过 sigmoid 后的实际密度:$u=0$ 对应 $t=0.5$(密度峰),90% 的质量落在 $u\in[-1.645,1.645]$ 即 $t\in(0.162,\,0.838)$——两端 $t\to0$ 与 $t\to1$ 只是长尾。也就是说训练主要在中段噪声水平上花力气,而不是像均匀分布那样把 20% 的算力分给几乎干净的 $t<0.2$。合理:最难的区间就是「噪得差不多、需要真正补几何」的中段;两端各自的极端情形($t=1$ 纯噪、$t=0$ 干净)在 Stage 3 会被单独钉住训练。【推测】这一动机论文未写,只给了采样公式。真正确定的是:Stage 3 直接把 $\tau_i$ 钉在 $1$,不再采样,所以这个分布在 Stage 3 完全失效。

三阶段设计的本质是「把一个大问题拆成三个各自可监督的小问题」:① 空间选择(在哪补)② 条件补全(按什么补)③ 速度压缩(多快补)。三者互相独立、各有明确的失败信号——这比端到端训一个「从 $n$ 图直接出 $N$ 视角 Gaussian」的模型要好调试得多。代价是每级的上限都被前一级锁死,且三级之间没有任何梯度回传,Stage 1 的压缩误差不会被 Stage 2 优化掉(见 §16)。

相机精度与微调基本无关

从 AUC@3° 列看,三种配置几乎完全一样,甚至有几处微调后反而略降(DL3DV $n=2$:30.6 → 30.4 → 30.2;$n=5$:33.6 → 33.5 → 33.4;RE10K $n=7$:24.7 → 24.5 → 24.5)。这是机制决定的:相机头读的是 geometry token,而 Gaussian 头微调改的是高斯参数头,两者在 backbone 里是并列的两个解码头,互不影响。这个「无关性」本身就是一个有说服力的证据——说明 Table 1 里相机 AUC 的提升确实是 token 补全带来的,而不是头部微调的副作用。

三张附录消融(Table 11 / 12)的共同模式:DensiTok 的增益对「头要不要动」极不敏感,对「latent 要多宽」相当敏感。工程上的优先级因此很清楚——如果你的目标是保住 camera / depth 精度,该花的力气在 $d_z$ 与 $N$ 上;Gaussian 头的微调属于最后 0.1–0.4 dB 的打磨,可以放到最后再决定。

14.2 对比结论(机制级,不是罗列数字)

  1. vs 标定稀疏前馈(DepthSplat / VolSplat):赢在「少一个约束」,输在「起步就落后」。$n=2$ 时 DepthSplat 26.636 比最好的 DensiTok 变体(WorldMirror 25.079)高 1.56 dB,而且更快(0.067 s vs 0.071 s)。这不是调参差距,是输入信息量的差距:DepthSplat 把 GT 内外参直接喂进代价体,射线几何是给定的;DensiTok 要先从图像估相机,再拿估出来的相机去插值、再拿插值相机去条件化 DiT——误差在链条上累积了两次。反过来,$n\ge5$ 时 DensiTok(AnySplat)反超 VolSplat($n{=}5$:28.034 vs 27.404;$n{=}7$:28.522 vs 28.328),机制是观测越多、DiT 的条件越紧:观测 latent 与观测相机都是硬条件,补出来的 token 被钉得越死。所以「DensiTok 适合什么场景」的准确答案是「$\ge$4–5 视角且完全拿不到相机」,而不是笼统的「稀疏」。
  2. vs NoPoSplat(仅需内参):4.62 dB 的差距主要来自「补全」,不是「免相机」。$n=3$ 时 DensiTok(AnySplat)26.919 vs NoPoSplat 22.298。这一条最容易被读反——手机视频的 EXIF 里通常就有内参,省掉内参本身值不了 4.6 dB。真正的来源是作用位置不同:NoPoSplat 把观测图在规范空间里对齐,它做的是「把已有证据摆正」;DensiTok 是在 token 层无中生有地补出未观测区域的证据。前者受物理上限约束(没拍的像素永远不会自己出现),后者在 4 维 latent 里补的是「这个区域该长什么样」的压缩先验。这也是本文标题那句 "not pixels but tokens" 的实证含义。
  3. vs FreeSplatter / Splatt3R(同为无相机):赢在「表示层级」,快在「少一次全分辨率编码」。DensiTok 在 $n\in\{2,3,5,7\}$ 上 PSNR / SSIM / LPIPS 全面超过 FreeSplatter,唯一例外是 DA3 变体在 DL3DV $n=2$ 的 PSNR。耗时上 0.071 s(Splatt3R 的 1/11)也说明差距来源:FreeSplatter / Splatt3R 走的是匹配 → 三角化 → 逐视角 Gaussian 回归的像素级路线,图像分辨率直接决定代价;DensiTok 走的是整条 token 栈 → 4 通道 latent → DiT,其中 DiT 那一段是与分辨率脱钩的(它只在 $L\times d_z$ 上跑),但前面的 backbone encoder 仍需全分辨率前向——这正是它从 256 的 0.071 s 涨到 512 的 0.510 s(约 7×)的来源。加速收益落在「补全」环节,不落在「编码」环节,这一点对工程预算的分配很关键。
  4. vs 扩散 NVS(GLD / Matrix3D / NVComposer):同为「补」,差在「补在哪一层」。GLD 已经是这三家里最接近本文思路的——它把扩散搬到几何特征空间,而不是像素空间,所以 $n=2$ 拿 23.608,远高于 NVComposer 的 14.897。DensiTok 比 GLD 再高一档(24.435 vs 23.608,同为 $n=2$ / $512\times512$ / Table 8 同一批视角)且在 $n$ 增大时差距持续拉开($n=7$:28.527 vs 26.918,+1.61 dB),但真正的分水岭是成本量级:GLD $n=7$ 要 150.433 s,DensiTok 0.656 s,约 229×。机制上这来自采样步数——GLD 是多步迭代去噪,DensiTok 的 Stage 3 把它压成一步(Table 10 自己给了 19× 的实测:多步与单步在 $n=2$ 下 PSNR 只差 0.02 dB 量级,却换来 19 倍速度)。
  5. 「打过自己的稠密参考」的临界 $n$ 因 backbone 而异,这条最能说明插件的能力边界。回 Table 1 同一口径看:AnySplat 的稠密参考($N{=}16$)是 24.04,+DensiTok 在 $n=2$ 时 22.56(还差 1.48)、$n=3$ 时 24.28 首次超过;WorldMirror 的稠密参考是 25.11,+DensiTok 在 $n=2$ 时 22.06、$n=3$ 时 23.81、$n=5$ 时 24.91 都还没到,要到 $n=7$ 的 25.31 才超过。同一套插件、同样的训练步数,临界面却从 3 滑到 7——差别只在被冻结的 backbone。这条对比是本文最硬的证据(bottleneck 确实在 token 不在头:补上 token 就能用 3 张图打过 16 张图),同时也是最大的局限:插件不能突破 backbone 自己的上界,backbone 越强,需要补的视角越多才能体现收益。【推测】WorldMirror 临界点更晚,可能因其稠密参考本身已接近该 backbone 的表达上限。
一句话的谱系定位:DensiTok 不是「更好的 3DGS 重建器」,而是「给已有重建器装上缺失视角的先验」。它把「补像素」类方法(扩散 NVS)的内容自由度砍掉(因为条件锁死在 token 上),同时也把「补几何」类方法(VolSplat 等)的输入依赖砍掉(不要内外参)。代价是两头都不极致:$n=2$ 打不过要相机的 DepthSplat,画质细腻度也打不过真正的大扩散模型(本文没做 512 以上的分辨率,也没比 SDXL 级生成)。它选的是一个很具体的生态位——手机随手拍的少量无标定视频,要一步出可用的 3DGS。

15.2 接入时的最小改动面

从论文的模块边界看,需要改的地方只有三处,而且都在 backbone 的「层间」而非内部:

① 读出多层级 token需知道该 backbone 的层索引与通道数
→
② 插入 LAM-VAE编码 + 解码,$d_z{=}4$
→
③ 插入 DiT条件 = latent + mask + 相机
  • 前置条件:必须能拿到该 backbone 的预训练权重,并能在冻结状态下跑通「$n$ 张图 → $L$ 层 token」的前向。这是硬门槛——论文三个 backbone 都是这种结构(几何 encoder + 多个解码头)。
  • 必须自己解决的两件事:① 该 backbone 的层选择(论文对 AnySplat 用 4 层、DA3 是 3072 通道,说明不同 backbone 的层级特征不同,论文用 LAM 的「层级自适应」来吸收这个差异,但并未给出层索引的选取规则);② 相机条件的接入点(需要该 backbone 的 camera head 能吐出每视角相机)。
  • 不必改的:backbone 的 encoder、camera / depth / Gaussian 三个解码头(可选微调 $h_{\mathrm{img}}$)。

15.3 相机条件的落地细节(最容易踩的地方)

训练与推理用的相机来自两个完全不同的分布,这是全篇最脆的一环。训练时用 GT 相机乘一个单因子缩放(按「预测中心散布 / GT 中心散布」定标),推理时用 backbone 自己预测的观测相机再插值。也就是说:DiT 从没见过真实预测误差的形态,只见过「GT 被统一缩放」这一种扰动。
  • 后果:如果目标 backbone 的相机预测误差是非均匀的(比如近处准、远处飘,或有系统性尺度漂移),这个单因子对齐无法覆盖,补全质量会明显低于论文数字。论文对此没有任何量化分析。
  • 可操作的对策:接入前先用你的数据统计「预测相机 vs GT 相机」的中心偏差分布。若呈现明显的逐视角方向性偏差(而非统一尺度),应考虑把 §6 的训练轨改成「用模型自己的预测相机 + 加噪」,而不是「GT × 单因子」。
  • 另一个坑:论文未定义「spread」的具体度量(只写 center spread)。复现时必须自己选(中心点两两距离的均值/中位数/最大?)。【待核实】

16.3 可以往下做的三个方向(本笔记的建议)

  1. 把 $d_z$ 做成自适应:既然 $d_z{=}16$ 的收益集中在相机精度、且随 $n$ 增大而增大(§13 表),那就没有理由全局固定 4。可以做「$n$ 小用宽 latent、$n$ 大用窄 latent」,或按区域重要性分配通道。这条最省力、收益最直接。
  2. 把插值扩成外推:作者自己点出的方向。技术上难在「外推区域没有观测约束」,但 DensiTok 的架构天然适合加约束——可以给外推视角一个随距离衰减的条件强度(而非现在的硬条件/无条件二分)。
  3. 把三阶段改成两阶段(或加一个轻量联合头):Stage 1 的压缩误差目前完全无法回传。最小改动是在 Stage 2 里放开 VAE decoder 的最后几层,让 DiT 的梯度能微调解码侧。风险是破坏「冻结」的叙事,但那是叙事问题,不是技术问题。

17总结与演进定位

17.1 三句话总结

  1. 问题诊断准确。本文最有价值的不是某个模块,而是那个判断:前馈 3DGS 少视角崩溃的瓶颈在重建头读到的 token,而不在头本身。证据是硬的——补上 token 后,$n{=}3$ 就能超过同 backbone 的 $N{=}16$ 稠密结果(AnySplat 24.28 > 24.04),这在「瓶颈在头」的假设下不可能发生。
  2. 解法选得克制。没有去训练更大的 3DGS 模型,而是插一个轻量插件:encoder 与头全冻,只补中间那 4 维 latent。代价是必须为每个 backbone 单独训 420k 步,换来的是「不动原模型也能提升」的工程可用性。
  3. 边界说得比多数论文清楚,但仍有两处含糊。论文主动承认只做插值不外推、$N>12$ 收益递减;但对「为什么主实验不用更好的 $d_z{=}16$」「训练相机与推理相机分布不对称如何保证」这两个更实质的问题没有交代。

17.3 一句话给读者

如果你手上的任务是「少量、无标定、静态、手机随手拍的多视角图 → 要一个能用的 3DGS」,DensiTok 的定位刚刚好,尤其 $n\in\{3,\dots,8\}$ 这个区间。如果你的任务要求极致画质、或要求实时、或场景是动态的、或需要外推视角,它都不是合适的选择——前三个是它的上界,第四个是它明确没做。
