手部微动重建解决方案：分层混合架构

1问题定义与成因定位

场景：环绕人物拍摄一段单目视频，要求重建出"人物 + 场景"的三维高斯模型。症状：人物运动导致手部区域重建质量显著劣于身体与场景——目视表现为重影、撕裂、漂浮高斯与细节糊化。

1.1 手部模糊的三种成因

在与峰哥的讨论中，将"手部模糊"拆解为三种物理来源不同的成因，对策完全不同：

成因机理现象本场景权重（峰哥确认）
① 成像运动模糊曝光时间内手在动，单帧 RGB 本身带拖影输入图手部模糊影响较小
② 优化欠拟合手速远超身体，运动场表达力不足手部糊成一团、无细节影响较小
③ 跨帧不一致逐帧独立变形，无持久身份与全局运动约束重影 / 撕裂 / 漂浮，视角稍变即破主因

核心判断（2026-10-12 与峰哥讨论定案）

主要矛盾是成因③：跨帧几何不一致。它对应的是"运动模型的时间结构"问题——Deformable-3DGS 的逐帧形变 MLP 对每一帧独立回归位移，没有任何机制保证"第 t 帧手上的高斯"与"第 t+1 帧手上的高斯"是同一块组织。相机环绕 + 手部微动叠加后，这种不一致在手部（运动速度最快、面积最小、纹理最易混淆的区域）被放到最大。

1.2 为什么是手部而不是别处先崩

运动幅度最大

环绕拍摄时，手部成像速度 = 手部自转 + 身体摆动 + 相机环绕三者在像面上的叠加，是全身上下运动最快的区域。

监督信号最弱

手部面积小、自遮挡频繁，2D 特征跟踪（TAPIR/CoTracker 类）与 COLMAP 匹配点在手部的密度与存活率天然最低——越需要约束的地方约束越少。

纹理最易混淆

五指形态相似、肤色接近，逐帧独立匹配时左手右手、食指中指极易串号，表现为手指级"重影"。

2已尝试路径复盘

两条工程路径均已在本机 WSL（RTX 3090 24GB）跑通全流程，以下结论均有 media_code/vggt_human/README_wsl.md 与 media_code/deformable_human/README_wsl.md 的实测记录支撑。

2.1 路径 A：vggt_human（VGGT-Omega 前馈 + 原版 3DGS）

链路：HEIC→JPG → VGGT-Omega 前馈（位姿+深度+点云）→ npz→COLMAP（~200k 初始点）→ 官方原版 3DGS 训练 30k 迭代 →（可选）新视角去噪 / HYPIR 人脸增强 → 人脸区 finetune。

尝试过的增强内容对手部问题的效果
depth-normal / noise-negate / BA / dynamic mask+filter训练脚本级增强，实测后默认全关、归档至 archive/（README_wsl.md「全流程命令」step 4 注释）不解决——动态人物违反静态假设
人脸模糊治理方案一升级版（06b face_finetune）30k 基线 ply 续训至 35k，LR×0.1、densify 冻结、人脸区互补双监督（FACE_WEIGHT=0.5 dual）有效但只针对人脸——人脸有 MediaPipe 检测器可依赖，手部没有同等可靠的逐帧定位
HYPIR 前/后处理人脸增强（step 01/06）扩散先验增强人脸区域不解决手部；且 HYPIR 在本机仍为遗留问题（SD2 base / LoRA 权重）

路径 A 的根本局限

原版 3DGS 是静态场景假设：一个人物动作序列喂进去，运动区域只能靠"同一位置堆多个半透明高斯"去拟合各帧观测的加权平均——手部重影是结构性必然，调参与后处理无法根治。

2.2 路径 B：deformable_human（Deformable-3DGS 逐帧形变 MLP）

链路：单目视频 → 模糊门剔帧（BLUR_THRESHOLD=100）抽帧（VIDEO_FPS=6）→ COLMAP →（可选 01c 位姿规整）→ canonical 高斯 + 逐帧形变 MLP 训练 20k 迭代 → 渲染评测。

尝试过的增强内容实测结论（README_wsl.md）
USE_POSE_REFINE=1每训练相机一组可学 w2c（四元数+平移），COLMAP 初值起步，weight 0.01缓解位姿误差，但对"手部跨帧串号"无能为力——位姿对了，形变场仍逐帧独立
模糊门剔帧 + 抽帧加密剔低质帧、提 VIDEO_FPS改善输入质量（成因①），不治本
复杂背景降载参数-r 2 --densify_grad_threshold 0.0004 --densify_until_iter 2000治显存爆炸（见 §9），与手部质量无关
MODE=original 时间×视角渲染03_render.sh 的组合渲染，专为目视检查重影设计确诊工具——重影在该模式下清晰可见

路径 B 的根本局限（= 成因③的直接来源）

D-3DGS 的形变 MLP 以 $(\mathbf{x}, t)$ 为输入逐帧独立回归 $(\Delta\mu, \Delta R, \Delta s)$：无持久身份、无跨帧运动结构约束、无遮挡推理。手部恰好是其失效模式的放大器。这与 SoM 调研笔记 §12.1 对 D-3DGS 失败模式的源码级分析一致。

未走的路：Phase 2 MHR 锚定导出

deformable_human README 明确标注 Phase 2（逐帧 MHR + 657 landmarks 锚定）未实现，且要求"vanilla baseline 的残差分析出来之前不用碰"。本文方案正是这个残差分析之后的选型结论。

4候选方案对比与选型

方案运动表示对手部成因③关键风险结论
S1 维持 D-3DGS 调参逐帧形变 MLP结构性无效—排除
S2 全量替换为 SoMB=10 全局 SE(3) 基 + 凸组合有效（防撕裂/漂浮）手部或落在低秩子空间外；预处理全家桶替换成本高；前景仅 40k 高斯资源摊薄吸收思想，不整仓替换
S3 MANO/HaMeR 先验驱动参数化手模驱动高斯理论最对症峰哥明确指出：手臂/手指姿态估计不准、帧间抖动，会引入比它消除的更大的误差；HaMeR 无置信度输出、纯单帧（HaMeR 笔记 源码级结论）降级为可选弱监督，不作主干
S4 分层混合（推荐）场景静态 + 身体 SoM 式低维基 + 手部局部高自由度子模型有效，且资源向手部倾斜分区边界处理、工程量选定

选型逻辑

S2 的思想（持久身份 + 低秩运动基）是治疗成因③的正确药物，但它的"全局 10 条基"对手部粒度过粗；S3 的先验足够强但观测源（手部姿态估计）在当前技术下不可靠。S4 取两者之长：用大尺度低秩结构锁住全局一致性（治撕裂/漂浮），用手部局部高自由度子模型补足表达力（治细节），用加密 tracks + 局部刚性正则补足监督（治串号）。HaMeR 只在置信度门控后作为弱观测源参与，姿态估计误差被隔离在硬约束之外。

6手部子模型设计

手部是全方案的新增核心。设计原则：表达力局部化、监督加密、刚性先验替代姿态先验。

6.1 表示：手部专属局部运动基

沿用 SoM 的凸组合形式（其 §4 式 4），但基的集合改为手部局部：

$$T^{hand}_{0\rightarrow t}(\mathbf{x}) = \sum_{b=1}^{B_{hand}} w^{(b)}(\mathbf{x})\, T^{(b)}_{0\rightarrow t}, \qquad \sum_b w^{(b)} = 1$$ (式 1)
  • B_hand ≈ 8–16：比全局 B=10 更细粒度。单手 5 指 ≈ 15 个近似刚体段，凸组合下 B_hand=12 是起步值，【待核实】需 Phase 1 实验扫描 {8, 12, 16}。
  • 基的初始化局部化：SoM 用全场景速度方向 k-means + 逐类加权 Procrustes（init_utils.py，见 SoM 笔记 §9）；手部子模型只在手部 mask 内的 tracks 上跑同一套初始化，基天然落在手指运动模式上。
  • 系数时间平滑：$w^{(b)}$ 上施加相邻帧 L2 平滑，压制逐帧抖动（对应成因③的"帧间不一致"）。

6.2 监督：手部区域 tracks 加密

现状问题

SoM 默认 TAPIR 在 4px 网格上均匀采点，手部小面积区域分到的跟踪点极少，且快速运动时存活时间短——监督在最需要的地方最稀。

对策

手部 mask（检测器/分割给出，见 §8 工程节）内独立加密采样：网格步长从 4px 收紧至 1–2px，跟踪点配额与面积脱钩、按区域保底。轨道权重沿用 SoM 的 conf×exp(−2Δt/T) 时间衰减（SoM 笔记 §9.2）。

6.3 先验：ARAP 局部刚性替代姿态模型

不引入 MANO 骨架（峰哥已否决其作主干：姿态估计误差大于收益），改用手外科常识级的弱先验——局部尽量刚性（As-Rigid-As-Possible）：

$$\mathcal{L}_{arap} = \sum_{i}\sum_{j\in\mathcal{N}(i)} \omega_{ij}\, \Big\| (\mathbf{x}_i^t - \mathbf{x}_j^t) - \mathbf{R}_i^t(\mathbf{x}_i^0 - \mathbf{x}_j^0) \Big\|^2$$ (式 2)

对手部高斯的 kNN 邻域施加邻域变换一致性：允许手指段间相对运动（邻域跨关节时权重 $\omega_{ij}$ 衰减），惩罚段内拉伸剪切。效果等价于"软骨架"，但完全数据驱动、不承担姿态估计误差。【待核实】ARAP 权重衰减的具体形式（按初始距离/按运动系数差异）需 Phase 1 确定。

6.4 HaMeR 弱监督（可选，置信度门控）

HaMeR 笔记的三个源码级缺口决定它只能当配角：① 无置信度输出（仅 ViTPose 2D 分数可作代理）；② 纯单帧无时序；③ 检测级联是第一召回瓶颈。使用方式：

  • 仅取高 ViTPose 分数帧的 HaMeR 输出，投影为 2D landmark 观测，以小权重加入手部监督；
  • 对 HaMeR 轨迹施加低秩约束（其帧间抖动是高频噪声，低秩投影后可用性提升——该判断见 HaMeR 笔记结论）；
  • MANO 参数不进入可优化变量的硬约束，只做软观测。

Phase 0：数据与基线体检（1–2 天）

  • 在现有 hand_motion 序列上跑 CoTracker3/TAPIR，统计手部区域 tracks 密度与存活时长——这是整个方案的天花板，不达标先补拍（降手速、提帧率、补光），不在算法上空耗。
  • 用 deformable_human 的 MODE=original 时间×视角渲染对现有 20k baseline 做重影定量/定性归档（README 里该模式本就是为此设计），作为后续对比基线。

Phase 1：运动基替换形变 MLP（核心验证，约 1 周）

  • 在 deformable_human 框架上，把逐帧形变 MLP 换成 canonical 高斯 + SoM 式全局运动基 + 凸组合系数（先不分区），渲染/光栅化/训练循环全部复用现有 D-3DGS 基建。
  • 验收：同序列上重影/撕裂目视消除，手部区 masked PSNR 不低于 D-3DGS baseline。
  • 同步确定 B_body 与 ARAP 权重形式。

Phase 2：三分区与手部子模型（约 1–2 周）

  • SAM3 mask 切分 scene/body/hand 三区；手部高斯密度加密、独立局部基 B_hand、tracks 加密采样接入。
  • 与 vggt_human 的 scene_gs 静态线对接：场景部分直接复用路径 A 的 30k 静态高斯作初始化。

Phase 3（可选）：HaMeR 弱监督

  • 按 §6.4 的置信度门控方式接入；若 Phase 2 手部质量已达标则跳过。

9工程落地约束

9.1 硬件与显存（RTX 3090 24GB）

  • 已知爆炸点：deformable_human 在复杂背景场景（满架杂物）下稠密化复利爆炸，hand_motion 场景实测爆炸点约 2600 步；用 --densify_until_iter 2000 冻结后稳定 17GB / 3.1 it/s（deformable_human README_wsl.md「可能遇到的问题」）。新方案高斯分区后总量上升（手部加密），该降载参数组合必须沿用，且 hand_gs 的 densify 阈值建议单独收紧。
  • 分区后三个高斯组共享一次光栅化（拼接渲染），显存开销 ≈ 单模型，不重复计费。

9.2 环境复用

  • 训练侧基于 deformable_human env（torch 2.5.1+cu121，clone 自 vggt_human；注意其 depth-diff-gaussian-rasterization fork 会遮蔽原版——这是刻意的，README 已注明）。
  • 预处理侧复用 vggt_human 的 VGGT-Omega 位姿/深度产物与 COLMAP 场景，不引入 MegaSaM/Depth Anything，避免重复建设。
  • SAM3 人/背景 mask 与 track 去重是 vggt_human 既有能力，直接接入。

9.3 数据侧既有教训

  • COLMAP 掉帧：动态人体占画面大、背景匹配点少时掉帧严重；对策维持 README 三条（抽帧加密、模糊门收紧、保证背景静态纹理）。位姿质量是本方案所有时序监督的地基。
  • 模糊门（BLUR_THRESHOLD=100）继续生效——成因①虽小但顺手剔除。
  • Python 版本红线：本机 WorkBuddy Python 3.13，目标 env 3.10.20，提交前跑 99h_check_py_syntax.py（vggt_human README_wsl.md 实测教训）。

11风险与开放问题

R1：tracks 质量天花板 [高]

手部 tracks 密度/存活率不达标时，一切运动监督失效。缓解：Phase 0 先行体检，不达标转采集端补拍，这是最便宜的路径。

R2：B_hand 与 ARAP 权重调参 [中]

基太少表达不足、太多退回逐帧过拟合。缓解：Phase 1 扫描 {8,12,16}，以手部 masked 指标定。

R3：分区边界 artifacts [中]

手腕处 hand/body 基不连续可能出现接缝。缓解：边界带高斯同时挂两组系数、权重按距离混合。【推测】该设计未经验证，Phase 2 重点检视。

R4：单目尺度与深度噪声 [低]

VGGT-Omega 深度噪声会污染 tracks 反投影。缓解：沿用 SoM 的置信度加权与 scale+shift 对齐。

明确不做

① 不以 MANO/HaMeR 姿态为硬约束主干（峰哥 2026-10-12 定：姿态估计误差大于收益）；② 不引入 deblur 类曝光建模（成因① 权重低，采集端控制）；③ 不整仓替换为 SoM 预处理全家桶（复用现有 VGGT-Omega/COLMAP 基建）。
