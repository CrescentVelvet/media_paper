1为什么用 AI 做论文调研

读论文是研究者的日常,但传统方式有两个顽疾:读完就忘(没有可检索的沉淀)、笔记碎散(Markdown 散落在十几个文件,找不到也接不上)。AI 协作的真正价值,不是"替你读",而是把读论文变成可累积的知识资产生产。

1.2 AI 协作的真正价值定位

很多人把 AI 当"快速读论文的工具",这低估了它。正确的定位是:AI 是知识资产的"生产线",人是"产品经理 + 质检员"。你不必逐字读论文,但必须决定:调研什么、产出什么形态、什么质量算合格。AI 负责把链接变成结构化笔记,你负责验收与深化。

三个具体价值:

  1. 从消耗战变资产:读一篇论文不再是 2 小时读完就忘,而是产出一个可检索、可复用、可关联的 HTML 笔记,下次遇到相关问题直接 grep。
  2. 从碎散变结构化:笔记不是 Markdown 散文件,而是统一样式(Style A/B)、统一命名、统一目录、有索引的可浏览知识库。
  3. 从被动变主动:AI 不只复述论文,还会写"可改进方向""技术路线对比"等增值章节,逼着你从"读懂"走向"评判"。

2.1 第 1 步:输入解析

  • arXiv 链接(https://arxiv.org/abs/2410.01425):提取 arxiv-id 2410.01425
  • GitHub 链接:提取仓库名作短名,从 README 找论文 arXiv 链接与项目主页
  • 关键:查最新版本号。abs 页有 submission history,取 v2/v3...。HTML 全文 URL 是 https://arxiv.org/html/<id>v<n>,版本号错了会 404

2.2 第 2 步:并行信息抓取

四路并行(一条消息里发 4 个工具调用),不要串行等:

① arXiv abs 页

取标题、作者、机构、abstract、提交日期、版本号、会议。小,直接 webfetch。

② arXiv HTML 全文 最重要

https://arxiv.org/html/<id>v<n>。含完整方法、公式、实验、图。不要自己 Read 全文(会爆上下文),委派子代理(见 §4)。

③ 项目主页

.github.io / research.nvidia.com/labs。取 Method Overview 图、可视化对比图、bibtex。

④ GitHub README + 源码

取环境配置、训练命令、数据集说明。深度调研时 git clone --depth 1 读 train.py/config/*.yaml,检验论文"宣称 vs 实现"差异。

2.3 第 3 步:子代理深读(详见 §4)

HTML 全文常超 2000 行/51200 字节,主代理直接读会爆上下文。委派 explore 子代理读取,提取方法/损失/实验/消融/图 URL,返回结构化素材。

2.4 第 4 步:框图绘制(详见 §5)

方法密集型论文用 Mermaid 画 pipeline、损失树、演进路线;总结性大图用内联 SVG;轻量嵌入用 HTML/CSS。ASCII 已废弃。

2.5 第 5 步:分点解析成笔记

按模板(Style A 方法密集型 13 节 / Style B 通用 14 节)填充。关键章节:

  • 实验表格:PSNR/SSIM/LPIPS 等量化指标必须完整数字,最优行标 .best
  • 可改进方向:知识库特色章节,三维度(方法/数据/工程)+ 优先级表 + 代码佐证,不能空谈
  • 技术路线对比与演进:把论文放回领域脉络,范式 → 代表方法 → 先验 → 局限

3AGENTS.md:让规范成为协作的"操作系统"

用 AI 协作最容易被忽视的一步:没有规范,每次产出都不一样,质量随心情起伏。AGENTS.md 是写给 AI 看的"作业规范",它把你的偏好固化下来,让每次调研都按同一套标准产出。

3.1 为什么必须写 AGENTS.md

反模式:不写规范,每次口头交代"帮我深度调研这篇论文"。结果:今天 14 节明天 8 节;今天 Mermaid 明天纯文字;今天有可改进方向明天没有;文件名一会儿英文一会儿中文。三个月后自己都看不懂自己的笔记。

AGENTS.md 解决三件事:

  1. 一致性:命名、样式、章节结构统一,知识库像系列产品而非草稿堆
  2. 可验收:有验证清单,产出前自查,质量稳定
  3. 零记忆负担:规范在文件里,新会话的 AI 读一遍就上手,不必每次重新交代

3.2 AGENTS.md 的 7 个必备模块

本知识库的 AGENTS.md(133 行)覆盖这 7 块,可作为模板:

模块内容为什么重要
① 工作流5 步:输入解析→并行抓取→子代理深读→框图→分点解析让 AI 知道"先做什么后做什么",不会跳步
② 文件命名PREFIX-YYYYMMDD-Name.html,4 个前缀(3D-/VideoGen-/SR-/CV-AI-)排序即分类,日期即版本,一眼看出归属

⑤ 图像策略优先热链 arXiv HTML 图(loading="lazy"),失效则本地化热链省存储且图自动跟论文版本走
⑥ 对比表格✓/✗/~ 标记,.best/.fail 标色对比一目了然,最优行突出
⑦ 验证清单成稿前 9 项自查(lang/主题色/链接/图/Mermaid/表格/可改进方向/index)质检门,防止低质产出

4子代理与人机协作:让 AI 读 2000 行论文

这是整套工作流里最关键、也最容易被忽略的技巧。arXiv HTML 全文动辄 700-2000 行,主代理直接读会撑爆上下文窗口,后续写作就废了。解法是委派子代理。

4.1 为什么要用子代理

反模式:主代理自己 webfetch arXiv HTML 全文,返回 2000 行被截断,主代理 context 被占满,写笔记时遗忘前文、重复内容、丢公式。上下文是稀缺资源,要留给写作。

子代理有独立的上下文窗口。主代理委派它去读全文、提取结构化素材,子代理返回精炼结果,主代理的 context 只消耗"精炼结果"那部分,写作空间充足。

flowchart LR MAIN["主代理
(写作 context)"] -->|"委派 Task + 详细 prompt"| SUB1["子代理 A
读 arXiv HTML 全文"] MAIN -->|"并行"| SUB2["子代理 B
git clone 读源码"] MAIN -->|"并行 webfetch"| ABS["abs 页(小,直接读)"] MAIN -->|"并行 webfetch"| HOME["项目主页(中)"] SUB1 -->|"返回结构化素材
方法+公式+表格数字+图URL"| MAIN SUB2 -->|"返回代码佐证
真实超参/硬编码/命令"| MAIN ABS --> META["元信息"] --> MAIN HOME --> METHOD["方法图+可视化"] --> MAIN MAIN --> WRITE["写作(只用精炼素材,
context 充裕)"] style MAIN fill:#dbeafe,stroke:#3b82f6,color:#1e3a5f style SUB1 fill:#ede9fe,stroke:#a78bfa,color:#4c1d95 style SUB2 fill:#ede9fe,stroke:#a78bfa,color:#4c1d95 style WRITE fill:#dcfce7,stroke:#34d399,color:#065f46

4.2 子代理 prompt 怎么写:三要素

委派子代理的 prompt 决定素材质量。三要素:明确任务目标、列出要提取的字段、要求原文照录关键数据。

📋 点击展开:委派子代理读 arXiv HTML 全文的 prompt 模板(实战版) 
请深度调研 arXiv 论文 [标题] 的 HTML 全文,URL 是 https://arxiv.org/html/[id]v[n]

## 任务目标
用 webfetch 抓取该 URL(format 用 markdown),从返回内容中结构化提取以下信息。
若内容被截断(超 2000 行/51200 字节会落盘到临时文件),用 Read 工具读取
临时文件各部分,确保覆盖全文。

## 需要提取的内容(请尽量原文照录关键数字、公式、表格数据)
### 1. 论文基本信息
- 标题、作者、机构、提交日期、会议、一句话定位
### 2. Abstract 全文(逐字)
### 3. Introduction
- 现有方法痛点的具体表现 / 核心思路 / 贡献点列表(逐条)
### 4. Method(最重要)
- 各子节详解:网络结构、数学公式(LaTeX 原文)、输入输出
- 所有 Figure 的编号、caption、图片 URL(完整路径 https://arxiv.org/html/[id]v[n]/xN.png)
### 5. 损失函数
- 每个损失的公式、权重、作用
### 6. 实现细节
- 训练数据集(名称/规模/来源)、训练超参(lr/batch/iter/GPU/时长)、推理超参
### 7. 实验
- 量化结果表格:把每个表格的数值逐行列出(方法名+各指标+最优行标注)
- 消融实验:每个组件 + ΔPSNR/Δ指标
### 8. 局限性章节原文要点
### 9. 关键图清单(完整 URL)

## 返回格式
结构化 markdown。关键要求:
1. 公式用 LaTeX 原文($$...$$)
2. 实验表格的数字必须完整,不要省略任何一个数字
3. 图片 URL 必须是完整路径
4. 方法部分要足够详细,能支撑写一份方法密集型分析笔记

三个不可妥协的要求:① 公式用 LaTeX 原文(否则主代理写作时要重新找);② 实验表格数字必须完整(子代理爱省略,要明确禁止);③ 图 URL 必须完整路径(主代理写作时直接热链)。

4.3 并行 vs 串行:何时用并行

独立任务必须并行。abs 页、项目主页、子代理读全文、git clone 源码这四路互不依赖,一条消息里发 4 个工具调用同时跑,比串行快 4 倍。有依赖才串行:读完 abs 页才知道版本号 → 才能委派读 HTML 全文(这种情况用 cmd1; if ($?) { cmd2 })。

4.4 源码佐证:让 AI 检验"论文宣称 vs 实现"

深度调研时,让子代理 git clone --depth 1 仓库到临时目录,读 train.py/lib/*.py/config/*.yaml,提取真实超参(损失权重、特征维度、循环次数)、硬编码限制。这是超越论文复述的关键。

实战案例:GEN3C 论文说"用视频扩散模型",代码里实际是 nvidia/GEN3C-Cosmos-7B(Cosmos-7B 底座),README 暴露自回归 chunk 是 121 帧、8 种预设轨迹、ViPE/VGGT 工具链。这些是论文正文不写但代码暴露的"真实",写进笔记的"可改进方向"才有底气。

6.3 三个关键决策点

① 选 Style A 而非沿用旧 Style B

GEN3C 是方法密集型(3D cache pipeline + 多公式 + 多实验表),Style A 的 MathJax+Mermaid+数字徽章更匹配。旧版用 Style B 是错配。

② 委派子代理读全文

HTML 全文 771 行,若自己 webfetch 会爆 context。委派子代理返回结构化素材(含完整 Table 1-6 数字、所有图 URL、式 1-5 LaTeX),主代理只消耗精炼结果。

③ 拿到 README 作代码佐证

GitHub webfetch 失败,改用 raw.githubusercontent.com 拿到 README,发现实际底座是 Cosmos-7B(论文写 SVD)、chunk=121 帧、8 种轨迹 —— 写进"可改进方向"才有底气。

6.4 新增了什么:可改进方向章节

旧版没有"可改进方向",新版有 9 个(高3+中3+低2+优先级表)。这是知识库特色章节,要求每点有代码/实验佐证。例:

改进点示例(GEN3C):说"自回归 chunk 漂移风险"—— 佐证是代码 --num_video_frames 121*N-1(仅 1 帧重叠);说"Cosmos 微调不充分"—— 佐证是论文 §5.7 写"10K 步、batch 64"。不能空谈,要能指到具体行。

"equation div:  " + ([regex]::Matches($c, 'class="equation"')).Count

# arXiv 图可访问性验证
$urls = @("https://arxiv.org/html/<id>v<n>/x1.png", ...)
foreach ($u in $urls) {
  $r = [System.Net.HttpWebRequest]::Create($u).GetResponse()
  "{0} {1}" -f $r.StatusCode.value__, $r.ContentLength
  $r.Close()
}

这两个验证脚本是我每次重写后必跑的。section 不闭合说明 HTML 坏了;图 HTTP 非 200 说明热链失效要本地化。这是质量门。

9经验总结:知识沉淀的三层境界

回看这 40 篇笔记的演进,其实是知识沉淀的三层境界。

第一层

复述

把论文摘要翻译成中文,列几个要点。DynamiCrafter(219 行)就是这个层级。价值:低。因为摘要本身 arXiv 就有,你没增值。

第二层

结构化解析

完整方法 + 公式 + Mermaid 框图 + 完整实验数字 + 消融。EVA-Gaussian(884 行)是这个层级。价值:中。可检索、可复习,但仍是"读懂论文"。

第三层

评判与关联

加"可改进方向"(代码佐证)+"技术路线对比与演进"+ 跨论文引用。GEN3C(876 行)是这个层级。价值:高。从"读懂"走向"评判",把论文放回领域脉络。

9.1 三条核心经验

  1. 规范先行,产出稳定。AGENTS.md 是一切的基础。没有规范,AI 协作就是"看心情",笔记质量随会话漂移。先把命名、样式、章节、验证清单定死,再让 AI 按规格产出。
  2. 子代理是上下文倍增器。主代理的 context 是稀缺资源,留给写作。读全文、读源码这种消耗 context 的活,委派子代理。一个 prompt 写得好,子代理能帮你读 2000 行论文返回精炼素材。
  3. 代码佐证让评判有底气。"可改进方向"不能空谈。说"多视角名不副实"要引用 torch.stack([lmain, rmain]);说"chunk 漂移风险"要引用 121*N-1。读源码是超越论文复述的关键。

9.2 给上手者的最小建议

  1. 先建 AGENTS.md:哪怕只写命名规范 + 5 步工作流 + 1 个样式模板,先立起来
  2. 先做 3 篇深度版:别堆量,3 篇 800 行深度版比 30 篇 200 行简略版有价值
  3. 每次都委派子代理读全文:主代理别碰 HTML 全文,留 context 写作
  4. 每次都验证:section 闭合 + 图 HTTP 200,跑两个脚本就够
  5. commit 信息写中文写章节:未来 grep 自己的演进史

最后一句:AI 协作做调研,真正的杠杆不在"AI 多聪明",而在你有没有把规范、工作流、验证清单沉淀下来。这套东西沉淀好,换任何 AI 工具都能复用,且产出会越来越稳。media_paper 知识库就是这套思路的活样本 —— 40 篇笔记、51 个文件、一条清晰的演进线,全部开源可参考。
