同事人体重建 Pipeline 详细流程

📅 2026-07-27 📂 3D / Digital Human / Pipeline 🔍 9 步详解 + 框图 + 大白话 + 术语表 🔗 关联：同事方案分析（MHR 版）

📖 这是什么？

这是一份把同事的人体重建 pipeline从头到尾讲清楚的文档。整个 pipeline 做的事用一句话说就是：

输入：一段拍摄视频（人物在里面动）
输出：一个 3D 高斯数字人模型（能渲染任意视角、能驱动新 pose）
中间：9 个步骤，像流水线一样把视频"消化"成 3D 模型
想象你要给一个人做一尊 3D 雕像。你拿着相机绕他拍一圈视频，然后把这视频丢给电脑。电脑要干的事：
  • 第一步：在每帧视频里找到这个人（人体跟踪）
  • 第二步：找到他的脸（人脸检测）
  • 第三步：确认这个脸确实属于这个人（人脸匹配）
  • 第四步：在脸上标出几百个点，知道他朝哪、什么表情（人脸重建）
  • 第五步：把脸变清晰（人脸增强）
  • 第六步：把 3D 脸模型"摆"到图像里脸的位置（人脸对齐）
  • 第七步：在 3D 脸模型上挂高斯球，训练（人脸高斯初始化）
  • 第八步：从场景点云里抠出身体部分，初始化（身体高斯初始化）
  • 第九步：脸 + 身体 + 场景 + 背景一起训练，优化所有参数（高斯训练循环）
最后你得到一个完整的 3D 数字人雕像，能从任意角度看，还能动起来。

关于本文档

本流程是按同事口述记忆整理的，可能存在误差（见文末"可能的笔记误差"小节）。但整体框架与社区主流数字人 pipeline（HUGS + GaussianAvatars 混合）一致，对理解研究方向有参考价值。

🚶 第 1 步：人体跟踪（找出视频里的人）

SAM3 文字提示 逐帧传播 mask 人物ID
一句话：在视频每一帧里找出人在哪里，给每个人一个编号（ID），并标记出人的轮廓（mask）。

为什么需要这一步？

视频里可能有多个人，我们需要：

  • 知道哪部分图像是"我们的主角"（不能把背景路人也建进去）
  • 在不同帧里跟踪同一个人（不能这一帧是张三下一帧变李四）
  • 拿到人的轮廓（mask），后面要用它来约束身体高斯区域

具体怎么做？

  1. 文字提示找人：用 SAM3 模型，输入文字描述（比如"穿红衣服的人"），模型在第一帧找到对应的人
  2. 逐帧传播：在第一帧找到人后，后续帧自动跟踪这个人（不需要每帧都重新搜索，效率高）
  3. 输出：每一帧每个人体一个 ID + 一个 mask（黑白图，白色是人）
输入
视频帧序列 + 文字提示（如"穿红衣服的人"）
输出
每帧的 (人物ID, mask) 列表
像你拿相机拍一群人，先指着那个穿红衣服的说"我要这个人"，然后相机自己跟着他走，每一帧都标记出他的轮廓。最后你得到一摞"贴纸"——每帧一张，上面只有那个人的剪影。

关键术语

术语解释
SAM3Segment Anything Model 3，Meta 出品的"分割一切"模型，能从图像里抠出物体轮廓
mask（掩码）一张黑白图，白色标记"哪里是人"，黑色标记"哪里不是"
逐帧传播第一帧用提示找一次，后续帧靠模型自动跟踪，不用每帧都重新搜索

👤 第 2 步：人脸检测（找出脸上的关键点）

RetinaFace 三种扫描框 5关键点 NMS
一句话：在每一帧图像上找到人脸位置，并标记出 5 个关键点（双眼/鼻尖/嘴角）。

为什么需要这一步？

  • 人脸是数字人最重要的部分，需要单独精细处理
  • 后面要对齐 3D 人脸模型（3DMM），必须先知道脸在图像哪里、关键点位置
  • 5 个关键点是标准化的"人脸定位锚点"，几乎所有 3DMM 对齐算法都用它们

具体怎么做？

  1. 缩放图像：把图像缩放到 1024×1024（模型要求的标准尺寸，太大会爆显存，太小看不清脸）
  2. 滑动扫描：用三种不同大小的"扫描框"在图像上滑动，每个位置都问一次"这里有脸吗？"
    • 三种大小是为了检测不同距离的人脸（近的脸大，远的脸小）
  3. RetinaFace 检测：模型对每个扫描框判断：是不是脸 + 5 个关键点位置
    • 5 关键点：左眼、右眼、鼻尖、左嘴角、右嘴角
  4. NMS 去重：同一个人脸可能被多个扫描框检测到，用 NMS（非极大值抑制）保留最确信的那一个
  5. 过滤：把置信度太低或框太小的检测结果扔掉（避免误检干扰后续）
输入
每帧图像（1024×1024）
输出
每帧的 (人脸框, 5 关键点坐标, 置信度) 列表
像你在一张大合照里找人脸。你拿着三个不同大小的放大镜（小、中、大）在照片上扫一遍，每扫到一个位置就问"这里有脸吗？" 找到脸以后在眼睛、鼻子、嘴角位置画五个点。同一张脸可能被多个放大镜扫到，只保留最确信的那次。太小的脸或不确定的，直接忽略。

关键术语

术语解释
RetinaFace经典人脸检测模型，输出人脸框 + 5 关键点
NMS（非极大值抑制）多个重叠的检测框只保留置信度最高的那一个
5 关键点左眼/右眼/鼻尖/左嘴角/右嘴角，人脸定位的标准锚点

🔗 第 3 步：人脸匹配（把人脸框对应到人体 ID）

IoU 人体mask 人脸框 一一对应
一句话：把第 1 步的人体 ID 和第 2 步的人脸框对应起来，给每个人配上正确的脸。

为什么需要这一步？

  • 第 1 步知道了"哪里是人体"（ID + mask）
  • 第 2 步知道了"哪里是人脸"（人脸框 + 关键点）
  • 但两边没关联！需要把它们匹配起来，才能知道"这个 ID 的人脸在哪"

具体怎么做？

  1. 对每个人体 ID，取出第 1 步对应的 mask（人体轮廓）
  2. 遍历第 2 步所有检测到的人脸框
  3. 计算每个人脸框和这个 mask 的重叠率（IoU）：
    • IoU = 交集面积 / 并集面积
    • IoU = 1 表示完全重合，IoU = 0 表示完全不重叠
  4. 给每个 ID 选择 IoU 最高的那张人脸作为匹配结果
  5. 约束：一个 ID 最多匹配一张脸（防止一个人配两张脸，保证一一对应）
输入
人体 ID+mask 列表（第1步）+ 人脸框列表（第2步）
输出
每个 ID 对应的人脸框 + 关键点（一一对应）
想象你有一摞人形剪影（第1步的 mask）和一摞人脸框（第2步）。你要把每张脸贴到正确的人形剪影上。怎么判断？看脸框和剪影重合多少——重合最多的那张脸，就是属于这个剪影的。

关键术语

术语解释
IoU（Intersection over Union）两个区域的重叠度。交集面积 ÷ 并集面积。1 = 完全重合，0 = 完全不重叠

🔎 第 4 步：人脸重建（检测 657 个点 + 表情系数）

ExpTracker 657关键点 头部朝向 表情系数 逆仿射变换
一句话：用 ExpTracker 模型在脸上标出 657 个密集点，并预测头部朝向和表情系数。

为什么需要这一步？

  • 第 2 步只标了 5 个粗略关键点，不够精细
  • 后面要对齐 3D 人脸模型（3DMM），需要密集的对应点作为监督
  • 表情系数用于驱动数字人表情（哪帧在笑、哪帧在皱眉）

具体怎么做？

  1. 裁剪人脸区域：从原图裁出人脸部分
  2. 放大到 512×512：模型要求的标准尺寸
  3. 裁剪框放大 2.5 倍：不只是脸，把上半身也带进来
    • 提供上下文：ExpTracker 需要看到肩膀/脖子才能准确判断头部朝向
  4. ExpTracker 推理：模型输出：
    • 657 个脸上点的像素坐标（眉毛、眼睛、嘴唇、脸颊等密集关键点）
    • 头部朝向（pose，三个轴的旋转角）
    • 表情系数（expression coefficients，控制表情的参数向量）
  5. 逆仿射变换：把模型输出的坐标（在 512×512 裁剪图里的）换回原图坐标系
    • 因为第 4 步裁剪+缩放过，坐标变了；后面要用原图坐标
输入
人脸框 + 512×512 裁剪图（含上半身 2.5×）
输出
657 关键点（原图坐标）+ 头部朝向 + 表情系数
第 2 步只在脸上点了 5 个点，太粗了。这一步用更精细的模型，在脸上点 657 个点（眉毛怎么弯、嘴角怎么翘、眼皮怎么垂），还能算出"头往左偏 15°，在微笑"。

关键术语

术语解释
ExpTracker人脸密集跟踪模型，输出密集关键点 + 表情参数（具体是哪篇工作待确认）
657 关键点比 5 关键点密集 100 多倍的脸部定位点，覆盖眉毛/眼睛/鼻/嘴/脸颊
表情系数控制表情的数字向量，如 [微笑度, 皱眉度, 张嘴度, ...]
逆仿射变换把"裁剪+缩放"过的图坐标，反向换算回原图坐标

✨ 第 5 步：人脸增强（提升人脸画质）

HYPIR RetouchFormer 高斯模糊 LQ 美颜 HQ 54px 渐变融合 前处理+后处理
一句话：用 HYPIR 模型把模糊/噪点的人脸变清晰，并和原图平滑融合。

为什么需要这一步？

  • 视频里人脸可能模糊、有噪点、光照差
  • 后面要拿去训练 3D 高斯，垃圾输入 = 垃圾输出
  • 增强后能显著提升重建质量

具体怎么做？

  1. 裁剪人脸区域：放大到 512×512
  2. HYPIR 推理：模型把 LQ（低画质）变 HQ（高画质）
    • 训练数据：LQ = 加高斯模糊的图；HQ = 加 RetouchFormer 美颜的图
    • 所以 HYPIR 同时去模糊 + 美颜（一举两得）
  3. 缩放回原大小
  4. 渐变融合：用 54 像素宽的渐变 mask 把增强图和原图拼起来
    • 中心区域用增强图，边缘渐变过渡到原图
    • 避免增强区域和原图有明显接缝
  5. 两个阶段：
    • 前处理增强：训练前增强输入帧（让 tracking 更准、纹理更干净）
    • 后处理增强：训练中期对渲染图增强（再喂回去训练，迭代提升）
输入
512×512 人脸裁剪图（LQ）
输出
增强后的人脸（已融合回原图坐标）
你拍的脸照片糊了，用修图软件一键美颜+锐化。这个软件（HYPIR）是专门训练过的：给它看的"差图"是加了模糊的，"好图"是美颜过的，所以它学会了一步搞定去模糊+美颜。但只对脸做美颜太突兀，所以脸周围用渐变过渡，让美颜区域和原图无缝衔接。

关键术语

术语解释
HYPIR扩散先验图像复原模型，一步推理，支持用户控制复原强度（详见 HYPIR 笔记）
RetouchFormer美颜模型，用作 HYPIR 的训练目标（生成 HQ）
渐变融合 mask让增强区域和原图无缝拼接的权重图，从中心 1.0 渐变到边缘 0.0
前处理 vs 后处理前处理 = 增强输入帧；后处理 = 增强训练中渲染图（闭环迭代）
⚠️ 多视角一致性提醒：美颜属于 2D 后处理，每帧独立处理可能破坏多视角一致性（不同视角美颜力度不同 → 闪烁）。建议把美颜约束作为纹理优化 loss，而非纯 2D 后处理。前处理（去噪/去模糊）影响小，可放心用。

🎯 第 6 步：人脸对齐（3DMM 模型与图像对齐）

3DMM PnP 视线交叉法 Adam 300次 SRT 锚点正则
一句话：把 3DMM 人脸模型"摆"到图像里人脸的位置和姿态，使两者对齐。

为什么需要这一步？

  • 第 4 步得到了 657 个 2D 关键点
  • 3DMM 模型是 3D 的，需要确定它在该帧图像里的"位置、姿态、大小"
  • 对齐后才能把 3D 高斯绑到 3DMM 上（第 7 步）

具体怎么做？（三层优化）

① 全局对齐（所有人脸一起优化）

  1. PnP 估计初始位姿：用 5 个粗略关键点 + 3DMM 标准关键点，用 PnP 算法估计初始 SRT（scale, rotation, translation）
  2. 视线交叉法估计：用多视角的视线交叉，进一步估计 3D 关键点位置（多视角约束更准）
    ⚠️ 笔记可能有误：原话"用PnP估计初始位姿然后视线交叉法估计初始位姿"——两次说"估计初始位姿"。可能第二个是"估计 3D 关键点"或"细化位姿"。
  3. 过滤：扔掉拍摄角度太大的图像（侧脸/后脑勺看不清的，对齐会不准）
  4. Adam 优化 300 次：迭代优化得到最终的 SRT

② 局部对齐（每张图微调）

  • 微调每张图像的偏差（每帧都有一个小的偏移修正）
  • 加锚点正则：约束每帧修正不超过一定范围，防止局部修正跑太远

③ 系数优化

  • 身份系数（这个人长什么样，所有帧共用）
  • 每帧表情系数（这帧是什么表情，每帧独立）
输入
657 关键点（多帧）+ 3DMM 模型
输出
每帧 SRT + 身份系数（共用）+ 每帧表情系数
想象你有一个 3D 的塑料人脸模型（3DMM），现在要把它"摆"到视频每一帧里人脸的位置。你先用 5 个粗略点估计大概位置（PnP），再用多视角交叉精确化，然后扔掉看不清的角度，最后迭代优化 300 次让模型和图像脸对齐。对齐后再微调每帧的小偏差，最后定下"这个人长什么样"（身份系数）和"每帧什么表情"（表情系数）。

关键术语

术语解释
3DMM3D Morphable Model，参数化人脸模型（如 FLAME），用一组参数控制脸型+表情
PnPPerspective-n-Point，从 2D-3D 对应点估计相机位姿的经典算法
SRTScale, Rotation, Translation（缩放、旋转、平移），描述 3D 模型在图像里的位姿
视线交叉法多视角下，从每个视角画一条经过 2D 关键点的视线，所有视线交点即为 3D 关键点
Adam 优化一种自适应梯度下降算法，比普通 SGD 更稳定
锚点正则约束每帧修正不偏离太多，防止局部优化跑飞
身份系数这个人"长什么样"的参数，所有帧共用

🎮 第 7 步：人脸高斯初始化（绑骨 + 训练）

AvatarGaussianModel FaceAlignment 绑骨 rig 可微渲染
一句话：把 3D 高斯球绑到 3DMM 人脸模型上，初始化、渲染、训练。

为什么需要这一步？

  • 经过第 6 步，3DMM 已经和图像对齐了
  • 但 3DMM 只是 mesh（网格），没有高斯渲染能力
  • 要把高斯"挂"到 3DMM 上（绑骨/rig），才能渲染出真实感图像

具体怎么做？

  1. AvatarGaussianModel 绑骨：把高斯球绑到 3DMM 的三角面上（rig）
    • 每个高斯定义在某个三角面的局部坐标系里
    • 三角面动 → 高斯跟着动（这就是"绑骨"）
  2. FaceAlignment 继承全局 SRT 和身份系数：复用第 6 步的优化结果，作为初始化
  3. 初始化：放置初始高斯球（在 3DMM 表面均匀放置）
  4. 渲染：用可微高斯渲染器渲染当前视角
  5. 训练：与原图对比 loss，反向传播优化高斯参数
输入
3DMM + SRT + 身份系数（来自第6步）
输出
训练好的人脸高斯模型
3DMM 是一个塑料脸模型，本身不能渲染照片。现在往这个塑料脸上贴满小光球（3D 高斯），每个光球记住"我在哪个三角面上、什么颜色、多亮"。这些光球跟着塑料脸动。然后用可微渲染器把这堆光球"画"成图像，跟原图对比，调整光球参数让它越来越像真人。

术语解释

绑骨（rig）把高斯绑到 mesh 三角面，让高斯跟随 mesh 形变（详见 第七章 LBS 解码）
FaceAlignment对齐结果类，继承全局 SRT 和身份系数

🧍 第 8 步：身体高斯初始化（场景点云抠身体）

BodyGaussianModel 场景点云 去人脸附近 深度加权稠密化 代表视角颜色
一句话：从场景点云里抠出身体部分，初始化身体高斯。

为什么需要这一步？

  • 人脸有 3DMM 模型作为骨架（第 6-7 步）
  • 但身体没有精确的 3D 模型可用（不像脸有 3DMM）
  • 改用"从场景点云里抠身体"的方法
⚠️ 与之前讨论的差异：之前讨论的 MHR pipeline 是把身体也绑到 MHR mesh 上（参数化 rig）。但当前同事的 pipeline 身体部分没用 MHR，而是直接从场景点云抠出身体部分。这是更接近 HUGS 早期"SMPL 初始化 + 偏离"思路的简化版。

具体怎么做？

  1. 从场景点云抠身体：从整个场景的点云里，分离出属于身体的部分（用第 1 步的 mask 约束）
  2. 去掉人脸附近的点云：人脸已经被第 7 步处理了，身体部分不要重复
    • 避免人脸高斯和身体高斯重叠
  3. 深度加权稠密化：根据深度信息调整点云密度
    ⚠️ 笔记可能有误：原话"深度重头有稠密化"，"重头"可能是"重加权"或"重新"的笔误。
  4. 代表视角颜色初始化：选一个代表视角，用它的颜色给高斯初始化
输入
场景点云 + 人体 mask（第1步）+ 人脸 mask（第7步）
输出
身体高斯初始化（颜色/位置/不透明度）
脸有塑料模型可以贴光球。身体没有现成模型，怎么办？把整个场景的 3D 点云拿来，从中抠出"这个人"的点（用第1步的剪影约束），再把脸那块的点去掉（脸已经单独处理了）。剩下的点就是身体点云，给它们染上颜色，变成身体高斯。

术语解释
场景点云3D 重建整个场景得到的点云（含人+背景+物体）
稠密化增加点云密度的过程，让稀疏区域更密
代表视角选一个最正面、光照最好的视角，用它的颜色给高斯初始化

🔥 第 9 步：高斯训练循环（核心训练）

多模型叠加 L1+SSIM+mask+语义 分裂/剪枝 SH升级 0→3阶 表情统一 位姿优化+曝光补偿
一句话：把人脸高斯 + 身体高斯 + 场景高斯 + 背景高斯叠加起来，一起训练，优化所有参数。

为什么需要这一步？

  • 第 7 步只训练了人脸高斯
  • 第 8 步只初始化了身体高斯
  • 但完整图像包含：人脸 + 身体 + 场景 + 背景
  • 需要联合训练，让所有部分协调一致（避免边界接缝）

具体怎么做？（训练循环）

① 渲染与损失

  1. 多个模型叠加渲染：avatar（人脸）+ body（身体）+ scene（场景）+ bg（背景）一起渲染成一张图
  2. 多种损失：
    • L1 损失：像素级绝对值差（基础重建损失）
    • SSIM 损失：结构相似性（比 L1 更符合人眼感受）
    • mask 损失：人体区域约束（让身体高斯不要乱跑）
    • 语义损失：语义一致性（如脸/身体/背景的语义分割一致）

② 训练策略

  1. 禁用动态干扰消除：训练时不做动态干扰消除（先把静态建好）
    ⚠️ 笔记可能有误："动态干扰消除"具体指什么不确定，可能是某种动态干扰去除模块。
  2. 禁用新视角生成：训练时不生成新视角（避免引入误差，先把已有视角建好）
  3. 位姿优化 + 曝光补偿：训练时联合优化相机位姿和曝光参数（让位姿更准、光照一致）

③ 高斯自适应

  1. 梯度大处分裂：在梯度大的区域（细节多）分裂高斯球，增加密度
    • 梯度大 = 该区域信息丰富 = 需要更多高斯表达
  2. 不透明度低处剪枝：不透明度太低的高斯球直接剪掉（节省计算）
  3. 球谐函数（SH）升级：
    • 训练初期：只用 0 阶 SH（颜色简单，每个高斯一个固定颜色）
    • 后期：升级到 1 阶、2 阶、3 阶 SH（颜色更精细，能表达视角相关效果，如反光）
    • 先粗后细，加快收敛

④ 表情统一

  1. 表情统一为代表视角：人脸增强后处理之前，把所有帧的表情统一为代表视角的表情
    • 原因：避免表情差异影响重建（不同表情的纹理对不齐）
    • 统一后所有帧用同一个表情的纹理，canonical 空间更干净
输入
人脸高斯 + 身体高斯 + 场景/背景高斯 + 多帧图像
输出
训练好的完整数字人模型
现在脸、身体、场景、背景的"光球"都准备好了，但各自独立。这一步把它们全部叠加渲染成一张图，跟原图对比，差距越大就越调整对应光球。怎么调？信息多的地方（细节多）多放几个光球（分裂），看不到的光球删掉（剪枝），颜色一开始简单后面变复杂（SH 升级）。最后所有帧的表情统一成同一个表情，避免表情差异搞乱重建。

关键术语

术语解释
L1 损失渲染图与原图像素级绝对值差
SSIM结构相似性，考虑局部结构，比 L1 更符合人眼
mask 损失用人体 mask 约束身体高斯区域，防止乱跑
语义损失语义分割一致性约束
分裂（split）把一个高斯球分成两个，在信息密集区域增加密度
剪枝（prune）删掉不透明度太低的高斯球（看不见的，浪费计算）
球谐函数（SH）表达高斯颜色随视角变化的函数。阶数越高越精细。0阶=固定色，3阶=可表达反光/高光
位姿优化训练时联合优化相机位姿（让位姿估计更准）
曝光补偿不同帧光照不同，补偿曝光差异让纹理一致

🔗 与之前讨论的 MHR 方案的关系

当前同事的 pipeline（本文件描述）与之前讨论的 MHR pipeline（同事方案分析）有一些关键差异，对比如下：

维度当前 pipeline（本文档）MHR pipeline（之前讨论）
人脸参数化模型3DMM（PnP+视线交叉+Adam 对齐）FLAME（GaussianAvatars 风格）
身体表示场景点云抠身体（无参数化模型）MHR mesh + 高斯 rig + LBS
身体动画能力❌ 无（点云无 rig）✅ 有（MHR + LBS 驱动）
身体 tracking无 per-frame pose 估计SAM 3D Body 逐帧预测 MHR 参数
是否用 MHR❌ 未提及✅ 核心组件
整体定位HUGS 早期简化版（场景点云 + 身体偏离）F3G-Avatar 风格（MHR rig + 双分支）
关键洞察：当前 pipeline 的身体部分是非参数化的（直接从场景点云抠出身体），没有 MHR rig 骨架。这意味着：
  • 身体不能驱动新 pose（只能渲染原视角）
  • 没有 per-frame pose 估计 → 没有同事之前说的"手臂转向估计错"问题
  • 身体部分本质上是静态点云重建，不是动态重建
可能的发展方向：如果未来要支持身体动画（驱动新 pose），需要把身体从"场景点云"升级为"MHR mesh + 高斯 rig"，这就是之前讨论的 MHR pipeline。也就是说：当前 pipeline 是 MHR pipeline 的前身/简化版，升级到 MHR 后才能获得完整的可驱动能力。
