Stipple:实时增量高斯泼溅与视觉惯性跟踪

1论文摘要与核心数据

3DGS 提供高效渲染的逼真场景表示,但其重预处理和训练步骤使其不适合需要实时重建的机器人/XR 应用 —— 标准 3DGS 需先用 COLMAP 做 SfM 估计位姿和点云,再做大量批量优化迭代。Stipple 的核心论断:实时跟踪(VIO)与实时重建(3DGS)可以解耦并行 —— 直接复用 VIO 输出的位姿和关键帧,采用增量式训练策略,仅在锚帧(~10% 关键帧)上运行深度估计与高斯添加,与跟踪线程异步并行,mutex 仅序列化 GPU 访问。

把 3DGS 从"离线批处理"重构为"在线增量流式",与 VIO 跟踪异步并行。这是 3DGS SLAM 从"离线 SfM 后训"向"实时 VIO 联训"的范式转向,与 3DGS 综述 中"在线化"主线呼应。

3DGS 已成为场景表示 SOTA,但其训练流程依赖离线 SfM(COLMAP)估计位姿与点云 + 大量批量优化迭代。机器人/XR 等实时场景需"边走边建",标准 3DGS 不适用。下表对比 3DGS 局限与 VIO/SLAM 的互补优势:

💡 核心洞察:解耦并行 + 锚帧稀疏化

已有 3DGS SLAM 要么"3DGS 自跟踪"(不稳),要么"VIO 跟踪 + 全帧重建"(开销大)。Stipple 的关键是双重解耦:① 跟踪与重建异步并行(mutex 仅序列化 GPU 访问,SLAM 线程不在训练上阻塞);② 锚帧稀疏化(仅 ~10% 关键帧触发深度估计与高斯添加,大幅减少计算)。这是把"3DGS 在线化"问题从"加速"重构为"稀疏化触发"。

3算法总体框架

Stipple 由五个核心模块构成,围绕"VIO 实时跟踪 + 锚帧增量重建"这一约束展开:

模块 A · Basalt VIO 跟踪

立体图像 + IMU → Basalt VIO 实时输出位姿 + 关键帧 + 回环检测。两线程无阻塞,传入视图排队给异步训练器。

模块 B · 锚帧判断

从当前地图渲染该位姿,测量 $\alpha<0.05$ 的像素比例(未重建区域)。若 > 5% → 成为锚帧,分配立体深度图并播种新高斯。

模块 C · 5 步高斯添加

仅在锚帧执行:深度播种 → 占用剪枝 → 突发拟合 → SSIM 致密化 → 收敛训练。

模块 D · 回环修正

VIO 输出位姿修正 → 仅锚帧"拥有"高斯 → 对锚帧高斯施加刚体变换(平移均值 + 旋转协方差),内存中连续 → 顺序操作。

模块 E · 持续优化

无锚帧待处理 → 从所有关键帧均匀随机采样一帧,执行单步训练;附 gsplat 位姿精修(局部光度对齐,不反馈 SLAM)。

模块 F · 鱼眼 + 立体

为 Brush 添加 Kannala-Brandt 鱼眼相机模型支持(消除去畸变与立体校正需求);FoundationStereo / BM / SGBM-WLS 立体深度。

🔑 设计哲学:异步 + 稀疏 + 刚体

三个关键原则贯穿 Stipple:异步(跟踪线程不阻塞训练)、稀疏(仅锚帧触发重建)、刚体(回环修正用刚体变换而非重训)。这三者共同实现"实时 + 增量 + 闭环一致"。Rust/CubeCL 实现还解锁了 GPU 厂商无关(对比 CUDA-only 方法)。

4阶段一:锚帧选择

Stipple 的稀疏触发核心:不是每关键帧都做重建,而是仅当未重建区域足够大时才触发:

  • Basalt 跟踪每帧;高斯仅从关键帧创建
  • 提交前,从当前地图渲染该位姿,测量 $\alpha<0.05$ 的像素比例(未重建区域)
  • 若未重建比例 > 5% → 成为锚帧:分配立体深度图并播种新高斯
  • 否则 → 仅加入持续优化视图池
  • 锚帧通常仅占~10% 关键帧 → 保持管线实时(深度估计是主要瓶颈,FoundationStereo ~150ms on RTX 5060 Ti)

🎯 锚帧判断的几何意义

5% 阈值不是经验选择,而是信息增量度量:已重建区域不会带来新几何信息,只有未重建区域才需要新高斯。这与传统 3DGS 的"全帧致密化"形成对比 — Stipple 把致密化触发从全局误差改为局部未覆盖。

判断标准动作占比
未重建区域 > 5%成为锚帧,触发 5 步流程~10% 关键帧
未重建区域 ≤ 5%加入持续优化视图池~90% 关键帧

5阶段二:5 步高斯添加流程

步骤操作目的
① 深度播种立体深度估计(FoundationStereo / BM / SGBM-WLS)→ 反投影每像素为 3D 点生成密集候选高斯均值
② 占用剪枝CPU 占用哈希集(网格 0.1m),丢弃已重建区域的候选避免重复,保持新增高斯数小
③ 突发拟合高学习率短优化(仅锚帧)平坦/纹理少区域在此步已足够好
④ SSIM 致密化逐像素 SSIM → $n_{\text{add}}=\text{MAX}\times(1-\overline{\text{SSIM}})/2$ → 权重采样低 SSIM 位置精准定位小、重建差区域
⑤ 收敛锚帧较长训练 + 无锚帧时随机关键帧训练新高斯收敛 + 全局持续优化

5.1 深度播种(FoundationStereo / BM / SGBM-WLS)

锚帧分配立体深度图,通过三种立体匹配方法估计密集深度,反投影为 3D 点作为候选高斯均值。FoundationStereo 在 RTX 5060 Ti 上 ~150ms,是主要计算瓶颈 → 这正是锚帧稀疏化(10%)的关键理由。

5.2 占用剪枝(CPU 哈希集)

CPU 端维护占用哈希集,网格 0.1m,丢弃已重建区域的候选 → 避免重复高斯,保持新增高斯数小。这是 CPU/GPU 协作:CPU 做几何判断,GPU 做渲染与训练。

5.3 突发拟合(Burst Fitting)

高学习率、短步数的优化(仅锚帧)。平坦/纹理少区域在此步已足够好,不需进入致密化。这一步是"快速占位",后续步骤做"精准补强"。

🔧 工程要点:突发拟合的分工

突发拟合用高学习率快速收敛平坦区域 → 让 SSIM 致密化能聚焦于真正的差区域。若没有突发拟合,SSIM 致密化会被全局误差主导,失去"局部精准"特性。这是 5 步流程的分工哲学:前 3 步做粗,后 2 步做精。

6阶段三:SSIM 驱动致密化

Stipple 的致密化准则核心创新:用逐像素 SSIM 而非 L1/L2 误差驱动。

$$n_{\text{add}}=\text{MAX\_SAMPLES}\cdot\frac{1.0-\overline{\text{SSIM}}}{2}. \qquad \text{(式 1)}$$

其中 $\overline{\text{SSIM}}$ 是渲染图与图像的逐像素 SSIM 均值。$n_{\text{add}}$ 个新高斯通过权重采样放置在低 SSIM 位置(权重与 $1-\text{SSIM}$ 成正比)。新高斯尺度从 $k$ 近邻距离初始化(稀疏区域更大)。

为什么用 SSIM 而非 L1/L2?

  • 有界性:SSIM 在 $[-1,1]$ 范围有界 → $n_{\text{add}}$ 自然有界,无需 clip
  • 局部结构:SSIM 捕获局部结构差异而非全局一致性(L1 偏好)
  • 精准定位:小型、渲染与图像仍不一致的区域被 SSIM 高亮,而 L1 会被大面积平坦区域主导
  • 致密化尺度自适应:$k$ 近邻距离初始化让稀疏区域自动用更大高斯

SSIM 致密化的潜在病理

SSIM 在纹理复杂区域可能过度触发(因结构高频差异),添加超过实时训练预算能收敛的高斯数。Machine Hall 上 Stipple 落后(CaRtGS 21.80 vs Stipple 19.48)正是此问题:高斯数爆炸(394k vs CaRtGS 118k),尺度正则损失仅部分缓解。

⚠️ 实验佐证:Machine Hall 落后是 SSIM 致密化的失败模式

Machine Hall 上 Stipple PSNR 19.48(落后 CaRtGS 21.80),高斯数 394k(CaRtGS 118k 的 3.3×),GPU 显存 4.7GB(CaRtGS 2.9GB)。论文假设 SSIM 致密化准则过度触发,添加了远超实时训练预算能收敛的高斯数 → 这是 SSIM 驱动策略的已知失败模式。尺度正则损失 $\mathcal{L}_{\text{scale-reg}}$ 部分缓解但不完全解决。

7阶段四:回环检测与位姿修正

  • 回环检测和位姿图修正完全由 VIO 跟踪器处理(Basalt 内建)
  • 修正到达时:更新所有关键帧存储位姿(非锚帧仍用于训练,位姿重要)
  • 仅锚帧"拥有"高斯 → 仅其高斯接收几何更新:施加与锚帧位姿相同的刚体变换(平移均值 + 旋转协方差)
  • 因每帧仅播种一次,锚帧高斯在内存中连续 → 回环更新是简单顺序操作
$$\boldsymbol{\mu}_i'=\mathbf{R}_{\text{loop}}\boldsymbol{\mu}_i+\mathbf{t}_{\text{loop}},\qquad \boldsymbol{\Sigma}_i'=\mathbf{R}_{\text{loop}}\boldsymbol{\Sigma}_i\mathbf{R}_{\text{loop}}^\top. \qquad \text{(式 2)}$$

🎯 刚体变换的优雅性

回环修正不需要重训高斯,只需对锚帧高斯施加刚体变换。每帧仅播种一次 → 锚帧高斯在内存中连续 → 顺序操作。这是 Stipple 数据结构(锚帧拥有高斯)与算法(刚体修正)的协同设计:数据结构为算法服务。对比需要重训的方法,这是 O(n) vs O(n×训练步数)的差距。

修正对象更新方式说明
关键帧位姿直接更新存储值所有关键帧(锚帧 + 非锚帧)
锚帧高斯刚体变换(式 2)仅锚帧拥有高斯,内存连续
非锚帧高斯—不拥有高斯,无需更新

8阶段五:持续优化

  • 无锚帧待处理时 → 从所有关键帧中均匀随机采样一个,执行单步训练
  • 从 gsplat 移植位姿精修(局部光度对齐,不反馈到 SLAM 轨迹)
  • 上游贡献:为 Brush 添加 Kannala-Brandt 鱼眼相机模型支持(消除去畸变和立体校正需求)

🔧 持续优化的工程意义

持续优化让跟踪间隙不浪费 GPU:VIO 在做位姿估计时,GPU 不闲着,持续优化已有高斯。这是异步并行的另一面 — 不仅训练不阻塞跟踪,跟踪间隙也让训练跑。位姿精修不反馈 SLAM 是为了避免循环依赖(3DGS 优化过的位姿不应反过来影响 SLAM 估计)。

9损失函数汇总

$$\mathcal{L}=\lambda_1\mathcal{L}_1+\lambda_2\mathcal{L}_{\text{SSIM}}+\lambda_3\mathcal{L}_{\text{depth}}+\lambda_4\mathcal{L}_{\text{anti-needle}}+\lambda_5\mathcal{L}_{\text{scale-reg}}. \qquad \text{(式 3)}$$
损失公式作用触发范围
$\mathcal{L}_1$L1 像素重建标准 3DGS 重建损失所有训练帧
$\mathcal{L}_{\text{SSIM}}$结构相似性标准 3DGS 重建损失所有训练帧
$\mathcal{L}_{\text{depth}}$$\|1/\mathbf{D}-1/\mathbb{E}[\hat{\mathbf{D}}]\|_1$(逆深度 L1)深度监督仅锚帧(参考深度图仅锚帧有)
$\mathcal{L}_{\text{anti-needle}}$$\text{mean}(\max(s)/\min(s))=\text{mean}(\exp(\max\log s-\min\log s))$正则化高斯向各向同性,防"针状"退化所有锚帧训练
$\mathcal{L}_{\text{scale-reg}}$$\sum s^2\cdot\mathbb{1}\{s>\text{threshold}\}$防高斯爆炸(Machine Hall 问题)所有锚帧训练

$\mathcal{L}_{\text{depth}}$:逆深度 L1

从 gsplat 移植,用逆深度而非原始深度 — 远处深度误差相对容差更大,符合视觉感知。仅对锚帧(参考深度图仅锚帧有)。

$\mathcal{L}_{\text{anti-needle}}$:反针状正则

正则化高斯向各向同性协方差 → 防止边缘区域高斯退化为针状(needle)导致渲染模糊。max/min 尺度比的指数形式。

$\mathcal{L}_{\text{scale-reg}}$:尺度正则

惩罚超阈值尺度的高斯 → 专门解决 EuRoC Machine Hall 上的"高斯爆炸"病理。但 Machine Hall 落后说明该正则不够强。

💡 损失设计的层次

Stipple 的损失分三层:重建($\mathcal{L}_1+\mathcal{L}_{\text{SSIM}}$,所有帧)、几何监督($\mathcal{L}_{\text{depth}}$,仅锚帧)、形态正则($\mathcal{L}_{\text{anti-needle}}+\mathcal{L}_{\text{scale-reg}}$,防退化)。这种层次化反映"不同信息在不同帧上可得" — 深度监督仅在锚帧,形态正则在所有锚帧训练。

🎯 实验的二元结论

Stipple 的实验呈现清晰的二元结论:在纹理丰富、合理运动的场景(Vicon Room、MSD)上,Stipple 全面领先(PSNR +1~5 dB,FPS 3-4×);在纹理少、Machine Hall 类型场景上,SSIM 致密化过度触发导致高斯爆炸,PSNR 落后。这是 SSIM 驱动策略的已知失败模式,不是方法本身缺陷。

演进定位

📈 3DGS SLAM 的三次范式演进

  1. 离线 SfM + 批量 3DGS(原版 3DGS):需 COLMAP 预处理 + 大量迭代,非实时。
  2. 3DGS 自跟踪(SplaTAM/MonoGS):3DGS 同时做跟踪与重建,避免 SfM 但跟踪不稳。
  3. VIO + 增量 3DGS(Stipple):VIO 提供鲁棒跟踪,3DGS 仅在锚帧增量重建 → 实时 + 闭环一致。这是把 3DGS SLAM 从"3DGS 包打天下"重构为"VIO 做跟踪,3DGS 做表示"的解耦分工。

Stipple 与知识库 3DGS 综述、Deformable 3DGS 等离线 3DGS 工作形成在线 vs 离线对比;与 前馈 3D 重建、VGGT 等前馈方法形成增量 vs 前馈对比 — Stipple 是 SLAM 路线的代表,前馈方法是数据驱动路线的代表。

14核心洞察

洞察一:解耦并行 > 联合优化

Stipple 不试图让 3DGS 同时做跟踪与重建,而是VIO 做跟踪(擅长),3DGS 做表示(擅长)。这与"3DGS 自跟踪"路线的根本差异是分工:让每个模块做最擅长的事。3× 的 FPS 优势(211 vs 69)是这种分工的红利。

洞察二:稀疏触发 = 信息增量度量

锚帧判断(未重建 > 5%)本质是信息增量度量:已重建区域不带来新几何信息,只有未重建区域才需新高斯。这把致密化从"全局误差"改为"局部未覆盖" — 这与 2DGS 等离线方法的"全局致密化"形成对比。

洞察三:SSIM 致密化的双刃剑

SSIM 在 Vicon Room 上精准定位小型重建差区域(PSNR +1.08),但在 Machine Hall 上过度触发导致高斯爆炸(394k vs 118k)。这说明局部结构度量在纹理丰富场景是优势,在纹理少场景是病根 — 致密化准则需场景自适应。

洞察四:刚体回环修正 = 数据结构 + 算法协同

回环修正用刚体变换而非重训,关键是锚帧高斯在内存中连续(因每帧仅播种一次)。这是数据结构(锚帧拥有高斯)为算法(顺序刚体变换)服务的协同设计。O(n) vs O(n×训练步数)的差距让回环修正真正实时。

洞察五:GPU 厂商无关是工程红利

Rust/CubeCL 实现(Brush)让 Stipple 不锁 CUDA,可跑在 AMD/Intel GPU 上。这在 XR/机器人场景(常需移动端 GPU)是关键工程红利。对比 CUDA-only 的 CaRtGS,Stipple 的部署灵活性更高。

洞察六:失败模式与正则互补

Machine Hall 落后是SSIM 致密化过度触发 + 尺度正则不够强的合谋。消融显示尺度正则 +0.64 dB,但 Machine Hall 上仍落后 CaRtGS 2.32 dB → 正则部分缓解但不完全解决。这指出后续工作方向:自适应致密化 + 更强正则。

15可改进方向分析

本节为知识库特色分析章节,从方法/数据评估/工程实用性三维度分点,每点含问题描述 + 论文/实验佐证 + 改进建议,标优先级。

方法层面

[高优先级] SSIM 致密化准则在纹理少场景过度触发

问题:Machine Hall 上 Stipple PSNR 19.48(落后 CaRtGS 21.80),高斯数 394k(CaRtGS 118k 的 3.3×),GPU 显存 4.7GB(CaRtGS 2.9GB)。论文假设 SSIM 致密化准则过度触发,但未给出 SSIM 阈值/触发的统计分布。n_add = MAX×(1-SSIM̄)/2 在纹理复杂区域 SSIM̄ 天然偏低 → $n_{\text{add}}$ 过大 → 超过训练预算能收敛。

改进:① 致密化准则场景自适应:根据场景纹理统计动态调整 MAX_SAMPLES 或阈值;② 引入高斯数预算硬上限(如 max 200k),触发后切换为优化已有高斯而非新增;③ 改用 SSIM + L1 联合准则(SSIM 主导局部,L1 主导全局)。

[高优先级] 锚帧阈值 5% 与占用网格 0.1m 是经验值,未做敏感性消融

问题:论文给出锚帧阈值 5%(未重建像素比例)与占用网格 0.1m,但均为经验值,未报告敏感性消融。5% 阈值过高(漏锚帧)或过低(过度触发)的影响未知;0.1m 网格在不同尺度场景(室内 vs 室外)的适用性也未知。

改进:扫描阈值(1%/3%/5%/10%/20%)与网格(0.05m/0.1m/0.2m/0.5m),报告 PSNR/FPS/高斯数的权衡曲线。室外大场景应自适应更大网格。

[中优先级] 深度估计方法选择(FoundationStereo vs BM vs SGBM-WLS)未对比

问题:论文提供三种立体深度方法(FoundationStereo / BM / SGBM-WLS),但未报告三者精度/速度/鲁棒性对比。FoundationStereo ~150ms 是主要瓶颈,但其在弱纹理/重复纹理场景的失败模式未分析。

改进:报告三种方法在 EuRoC 各序列的深度精度 + 速度;分析 FoundationStereo 失败时是否回退到 BM/SGBM-WLS;或设计场景自适应方法选择。

[低优先级] 突发拟合的学习率/步数未披露

问题:突发拟合用"高学习率短优化",但具体学习率与步数未披露。这影响可复现性,也影响"突发拟合 vs SSIM 致密化"分工的边界判断。

改进:附录补全突发拟合超参表;报告突发拟合步数对最终 PSNR 的影响。

数据与评估层面

[高优先级] 仅 EuRoC + MSD 两个数据集,真实世界泛化未验证

问题:EuRoC 是无人机室内序列(Vicon Room + Machine Hall),MSD 是 VR 头显室内序列。均无室外/大尺度/动态场景。Stipple 在室外大尺度场景(自主驾驶 / 大型室外 SLAM)的适用性未知 — 锚帧阈值 5% 与占用网格 0.1m 均基于室内尺度。

改进:补充 KITTI / NuScenes 等室外大尺度数据集测试;报告跨域性能衰减;或自适应调整锚帧阈值与网格尺度。

[中优先级] 评测协议"原始速率回放"未充分分析

问题:协议是"原始录制速率回放(不给额外处理时间)",但未报告各方法的实际处理延迟与帧率的关系。211 FPS 跟踪速度是否意味着每帧 4.7ms 内完成?深度估计 ~150ms 如何不阻塞?异步队列的延迟特性未量化。

改进:报告端到端延迟(从帧到达到地图更新);分析异步队列长度分布;明确"实时"的具体定义(跟踪实时 vs 重建实时)。

[低优先级] 无动态场景评估

问题:EuRoC 与 MSD 均为静态场景。Stipple 假设场景静态(锚帧高斯刚体变换),但真实机器人场景含动态物体(行人/车辆)。动态物体如何处理?是否会被错误播种为新高斯?

改进:补充动态场景测试(如 KITTI 序列);或引入动态物体检测与过滤模块。

工程实用性层面

[中优先级] GPU 显存波动大(2.6-4.7GB),XR 头显部署边界

问题:Stipple GPU 显存在 Vicon Room 2.9GB,Machine Hall 4.7GB(CaRtGS 2.9GB 稳定)。波动大且峰值高,在 XR 头显(典型 4-8GB 共享显存)上可能爆显存。SSIM 过度触发时尤为严重。

改进:显存硬上限机制(达到上限切换为优化模式);高斯数/显存自适应控制;分块加载策略。

[中优先级] 反针状正则在 Machine Hall 不够强

问题:消融显示尺度正则 +0.64 dB,但 Machine Hall 仍落后 CaRtGS 2.32 dB。说明 L_anti-needle 与 L_scale-reg 不足以遏制 SSIM 过度触发的高斯爆炸。

改进:增强正则强度;或引入致密化预算硬约束(优先于损失);或动态调整 SSIM 阈值。

[低优先级] 鱼眼支持仅 Kannala-Brandt 一种模型

问题:为 Brush 添加 Kannala-Brandt 鱼眼模型支持,但未支持其他鱼眼/折反射模型(如 equidistant、equisolid、stereographic)。这与 UCPE 支持任意镜头形成对比。

改进:扩展到统一相机模型(UCM)框架,支持任意镜头;或报告 KB 模型在常见鱼眼镜头上的近似误差。

🎯 个人认为最关键的三点

  1. SSIM 致密化过度触发 —— 这是 Stipple 在 Machine Hall 落后的根因,也是论文自承的失败模式。需场景自适应致密化准则:根据纹理统计动态调整 MAX_SAMPLES 或阈值,或引入高斯数预算硬上限。这是把 Stipple 从"Vicon Room SOTA"推向"通用 SLAM SOTA"的关键解锁。
  2. 仅室内数据集验证 —— EuRoC + MSD 均室内,室外大尺度(KITTI/NuScenes)未测。锚帧阈值 5% 与占用网格 0.1m 均基于室内尺度,室外需自适应。这是从"学术 demo"到"机器人产品"的关键缺口。
  3. 关键超参无敏感性消融 —— 5% 锚帧阈值、0.1m 网格、突发拟合学习率/步数均为经验值,未报告敏感性。这是可复现性与可比较性的硬缺口,需补全扫描曲线。

16总结与资源

Stipple 把 3DGS 从离线批处理重构为在线增量流式:Basalt VIO 提供鲁棒跟踪,3DGS 仅在锚帧(~10% 关键帧)增量重建,5 步流程(深度播种 → 占用剪枝 → 突发拟合 → SSIM 致密化 → 收敛)分工"粗-精",回环修正用刚体变换 O(n) 更新。在 EuRoC Vicon Room 上以 211 FPS 跟踪(CaRtGS 3×)、PSNR 23.49(+1.08 dB)领先;在 Machine Hall 上因 SSIM 致密化过度触发落后 — 是已知失败模式而非方法缺陷。Rust/CubeCL 实现解锁 GPU 厂商无关,适合 XR/机器人部署。

最大亮点

  • VIO + 3DGS 解耦并行,跟踪 211 FPS(3×)
  • 锚帧稀疏化(~10%)让深度估计瓶颈可控
  • 刚体回环修正 O(n),内存连续顺序操作
  • GPU 厂商无关(Rust/CubeCL),跨平台部署
  • SSIM 致密化在纹理丰富场景精准定位

主要局限

  • SSIM 致密化在 Machine Hall 过度触发(394k 高斯)
  • 仅 EuRoC + MSD 室内数据集,室外泛化未知
  • 锚帧阈值/网格/突发拟合超参无敏感性消融
  • GPU 显存波动大(2.9-4.7GB),XR 边界
  • 无动态场景评估

演进定位

在本知识库 3DGS 脉络中,Stipple 代表离线 → 在线的范式转向(VIO + 增量 3DGS);与 3DGS 综述 离线方法、前馈 3D 重建 前馈方法形成三路线对比:离线精度高、前馈速度快、SLAM 实时闭环。后续若融合 Stipple 锚帧稀疏化 + 前馈深度(如 VGGT),可推进实时 3DGS 落地。
