1论文概要与核心贡献

一句话概括:第一人称(egocentric)视频里恢复带度量尺度的双手 3D 轨迹,最大难点是手-物遮挡与手出画(out-of-sight, OOS)。此前路线要么逐帧「检测-裁剪-回归」、手一出画就丢,要么像 ViDiHand 那样把视频扩散模型(VDM)当像素渲染器多步采样再回归姿态,又慢又把生成伪影带进几何。ACE-Ego-Hand 的做法是把预训练 VDM(Wan2.2-Fun-5B-Control)改造成确定性几何编码器:对干净 latent 做单次 σ=0 前向,在 block-15 处取特征,接 LoRA 端到端微调;再用一个双向时空解码器整段恢复双手 MANO 轨迹,并用射线场相机求解器把度量放置与相机内参解耦(K-free 配置测试时完全不需要内参)。

核心贡献一句话:把「视频扩散先验」从「随机多步渲染器」降级为「单次前向的确定性编码器」,配合全片段双向注意力,在五个第一人称基准上把出画手的腕部对齐误差从最强基线的 126–164mm 拉到 35–39mm,同时速度快 33×。

三个宣称的贡献(论文 §1)

  1. 框架:离线片段级(clip-level)框架,把 VDM repurposing 成 Deterministic Clean-Latent Encoder,无需任何外部手部检测器即恢复带度量尺度的双手轨迹。
  2. 解码与相机:Bidirectional Spatiotemporal Decoder(空间锚定 query + 片段级形状先验 + 双向推理)负责重建出画手;Ray-Based Camera Solver 把手部运动与相机内参/ ego-motion 解耦,支持测试时无内参(K-free)推理。
  3. 实验:五个第一人称基准(ARCTIC / HOT3D / HOI4D 零样本 / H2O / OakInk2)48 项主指标胜出 45 项,严重遮挡与手出画场景下保持稳定。

2研究背景与动机

2.1 三条既有路线的具体失败模式

① 单帧「检测-裁剪-回归」

代表:InterWild、HaMeR、Hamba、WiLoR、WildHands、EgoForce(表 1 的六个单帧基线)。

失败模式:尺度与深度绑定在检测框上,手被严重遮挡或出画时根本不产生输出——不是误差变大,而是轨迹断裂。附录 C.2 的数据显示,这类方法在出画手帧上集体塌进 126–164mm 的窄带,且排名与可见帧排名完全无关,等于「没有在做人」。

② SLAM 锚定跟踪

代表:HaWoR(DROID-SLAM + 补全)。

失败模式:误差随时间累积;81 帧(2.7s)短片段上 DROID-SLAM 不稳定。论文评测时被逼把 HaWoR 的 SLAM 与补全两级都关掉、只评其相机空间前端(附录 A.3 明确声明这是对 HaWoR 不利的设定)——即便如此它的 MPJPE-p 仍是 ARCTIC 最差的 45.4mm。

③ 窗口化时序模型 / 生成式补全

代表:OmniHands(9 帧融合)、Dyn-HaMR、GENMO、EgoH4;以及最直接的对手 ViDiHand(VACE 微调 Wan 生成几何叠加图,再从去噪特征回归 MANO,12–25 步采样)。

失败模式:窗口化模型手出画即失去历史上下文,重回画面后无法连贯续接;ViDiHand 式「渲染再回归」路线要付出完整采样轨迹的延迟(1.91 fps),且骨干网络吃不到重建目标的梯度(解码器在冻结缓存特征上训练),生成伪影会直接传播成几何误差。

2.2 作者的关键假设与核心洞察

核心洞察(论文 §1 原文逻辑,两条):
  1. VDM 对重建的最大价值是当编码器,不是当渲染器。rectified-flow 预训练的 DiT 在序列级学到了物体恒存性(object permanence)、3D 结构一致性、遮挡推理等时空先验——这些先验已经在其中间层特征里,一次 σ=0 的干净前向就能读出来,不需要真的把视频「生成」出来。
  2. 通用特征必须经端到端 3D 监督改造才能变成几何感知特征。冻结特征直接回归(ViDiHand 路线)浪费了适应性,因此用 LoRA 把骨干放进训练回路。
配套判断:度量 3D 手部轨迹恢复本质上是离线片段级时空推理任务——出画区间的合理重建需要同时看到过去与未来,因果跟踪器在结构上做不到。

2.3 这些假设在什么条件下会失效

论文自陈与可推导的失效条件(交叉核对 §5 与附录 F):
  1. 「VDM 特征含有用先验」只在训练域相机族内成立。附录 F.1:预测射线场「在训练中见过的相机族内泛化最好」;发布的 checkpoint 只在针孔数据上训练,鱼眼直接拒绝服务(代码 geodit_arch.py:70-87 对鱼眼内参抛 NotImplementedError)。
  2. 离线假设 = 无法闭环控制。整个 backbone 对全片段做一次双向前向,延迟下界是片段长度而非 63.1 fps 吞吐——它是「从录像里采机器人数据」的工具,不是控制器(附录 F.1 原文)。
  3. 出画恢复的上限是「腕部对齐的合理性」,不是「度量放置」。OOS 区间的绝对位置依赖回归深度与方位角,无图像证据约束;论文明确说「没有任何表格度量出画手的绝对放置」(附录 F.1)。夸大解读 OOS 数字是读这篇文章最容易犯的错。
  4. 伪 GT 污染。HOI4D 与 H2O 的 MANO 标注部分来自逐帧估计器的伪真值;H2O 还在训练混合里,等于「在自己训练过的标注分布上考试」(附录 A.2 自陈)。头条数字只应看 ARCTIC/HOT3D(原生 MANO GT)。
与库内调研的关系:本文正是《视频生成驱动动态人体重建调研》路线 E(「确定性几何/运动编码器——非生成式复用」)的唯一代表工作。该综述的判断「把 VDM 从随机多步渲染器降级为确定性编码器,绕开采样延迟与生成伪影传播」在本文得到完整工程落地与 SOTA 验证;其指出的风险(离线片段级延迟、依赖可见锚点质量)也与本文附录 F 的自陈一致。

4.2 数学形式化

骨干 $\Phi$ 是以 rectified flow 在加噪 latent $x_\sigma=(1-\sigma)z+\sigma\epsilon$ 上预训练的 DiT。本文把它严格当编码器用:冻结 VAE 编码器压出干净 latent $z=\mathcal{E}(V)$,在零噪声水平做单次确定性前向,并截断到第 $L^{\star}=15$ 块:

$$F=\Phi_{0:L^{\star}}(z;\sigma=0)$$ (式 1,论文 Eq.1)

得到 $T'=21$ 个 latent 帧(对应 $T=81$ RGB 帧)的特征序列 $F=\{F_\ell\}_{\ell=1}^{T'}$,每帧是 $D=3072$ 通道的空间网格(672×480 输入时为 $42\times30$,即 16×16 像素/格)。

4.3 前向流程(数据流与可导性)

  1. 视频 → VAE:冻结,无梯度(推理时占端到端耗时的 72%,附录 C.4)。
  2. $z$ 进 DiT 的「噪声样本」输入槽(48ch),控制槽(100ch)填零,$t=0$ → σ=0 的确定性前向(源码 geodit_arch.py:298-314 证实:feature_mode=noised_video + nv_sigma=0.0 时 $x=(1-0)z+0\cdot\epsilon=z$,$t=0\cdot1000=0$)。
  3. patch embedding 全量微调;30 块全部注入 LoRA(rank 64,α 64,无 dropout,每块 10 个线性层,源码 wan_backbone.py:134-136),但梯度只流经前 16 块。
  4. block-15 输出同时喂给 Ray Head(§6)与双向时空解码器(§5)。

4.4 为什么这样做(机制解释)

为什么读 σ=0 而不是带噪 latent?论文附录 D.4 的对照实验:同一配方把读取噪声水平换成 σ=0.5,MPJPE-p 从 15.26 涨到 17.66mm(+2.40mm),CT-p 恶化 39%(0.0208→0.0343m),而 PA-p 只差 0.52mm——噪声主要破坏的是度量几何而非关节结构;且因为不做生成采样,注入噪声带来的多样性完全用不上,纯亏。31 个验证 checkpoint 里 29 个都是 σ=0 更优(均值差 1.2mm)。
为什么 tap 在 block-15?附录 D.3 的 tap 深度扫描(表 S6):block-10 差 1.67mm,block-20/24 最多再买好 0.17mm 且两项指标排序不一致(被判为运行间噪声)。中层特征已保留几乎全部可用精度,跳过后半省约一半前向算力。
为什么 LoRA 而不是全微调?5B 骨干全微调既贵又容易冲掉预训练先验。LoRA(161.2M)+ patch-embed(1.8M)让 3D 监督「重塑」特征而不是「覆盖」特征;消融(表 2)显示去掉 LoRA,MPJPE-p 16.95→23.10mm、MPJPEOOS 41.5→50.1mm,任务适配的价值是实打实的。

4.5 监督信号

该模块无独立损失,但通过 LoRA / patch embedding 接收全部下游损失($\mathcal{L}_{\mathrm{rot}}$、$\mathcal{L}_{\mathrm{joint}}$、$\mathcal{L}_{\mathrm{img}}$、$\mathcal{L}_{\mathrm{cam}}$、$\mathcal{L}_{\mathrm{tmp}}$、$\mathcal{L}_{\mathrm{ray}}$)的反传梯度——这正是与 ViDiHand「冻结缓存特征」路线的本质区别(论文 §2 明确指出后者骨干吃不到重建梯度)。

论文没写、源码里看到的两个细节(§9 展开):① DiT 的 cross-attention 文本条件是一个固定不变的 caption embedding,内容竟是渲染生成血统遗留的 "Three geometry renders of two hands on black background: color-coded depth, joint skeleton, surface normals."(scripts/precompute_caption.py:26-27);② 100 通道控制分支在推理时全零,视频只走「噪声输入」槽。

5.2 数学形式化

每个 latent 帧的 patch token 由两项加性位置编码构成:

$$X_{\ell}=\mathrm{LN}(W_{F}F_{\ell})+P^{\mathrm{sp}}+g\big(\Gamma(\hat{r})\big)$$ (式 2,论文 Eq.2)

$W_F$ 把 3072 通道投影到 384 维解码器空间;$P^{\mathrm{sp}}$ 是可学习 16×16 网格双线性重采样到 token 分辨率的空间 PE;$\Gamma$ 对 Ray Head 预测的视线方向做 8 倍频傅里叶编码(方位角/仰角的 sin/cos,源码 memory_projector.py:99-148),零初始化 MLP $g$ 映射到解码器维度——把「每个像素朝哪看」的几何先验直接注入 token。

关节 $j$ 的 2D 锚点由其 query 的 cross-attention 权重做 soft-argmax:

$$\hat{p}_{j}=\sum_{u}A_{j}(u)\,u,\qquad\sum_{u}A_{j}(u)=1$$ (式 3,论文 Eq.3)

$u$ 遍历 $[0,1]^2$ 归一化格子中心。该形式可导、亚格子精度,且 anchor 不依赖检测框(直接省掉匈牙利匹配)。源码 memory_encoder.py:562-565, 629-638 逐行对应。

5.3 前向流程与设计机制

  1. 空间锚定 query:关节 query 绑定物理关键点,而不是让一个大向量回归全部 21 点——消融(表 3)显示把关节 query 换成手内池化,MPJPE-p +1.880mm、EPE2D-p +1.681px。
  2. 交替结构:每层先在帧内从 patch 网格读空间细节(Cross-Attn),再让全部帧的 query 互相交换运动信息(Temporal Self-Attn)。与「先池化成每帧 1-2 个 token 再做时间注意力」相比,空间细节不会被池化掉(源码 docstring:这是移植 VGGT-Omega 的 register-token 交替注意力思路)。
  3. RoPE 时间轴:旋转相对位置编码(base 10000,源码 memory_encoder.py:57-68)消除绝对长度约束——同一份权重可以单次前向解码任意长度(附录 D.2 实测整段 594–1087 帧直出)。换成绝对 PE,MPJPE-p +2.523mm、Jitter 2.704→2.948。
  4. 无因果掩码:每帧同时条件于过去与未来——这是「重建」出画手而非「外推」出画手的结构基础,也是它只能离线的根本原因。
  5. 片段级形状先验:$\hat\beta$ 对整段只预测一次/手(物理上同一个人手型恒定),防止逐帧估计在遮挡与运动下的尺寸闪烁与漂移。代码:betas_scope=per_hand, per_hand_betas_source=slot_mean(memory_projector.py:897-898,对手槽时间均值过 head_betas_hand)。

6模块三:Ray-Based Camera Solver(基于射线的相机求解器)

6.1 问题:为什么要「解」相机而不「回归」平移

直接在相机系回归 3D 平移会把手部关节运动与头部 ego-motion 耦合在一起,并且让读出头去「背」某台相机的像素-度量映射——换内参就失效(论文 §3.3:"Readout heads that memorize the pixel-to-metric mapping of one camera fail to generalize across intrinsics")。ACE-Ego-Hand 的方案是把相机几何显式参数化为连续视线场(ray field),平移只剩一个可闭式求解的小问题。

6.3 Mixed-PnP 平移求解(全文最巧的一步)

思路:不回归完整 3D 平移。Camera Head 只回归光轴深度 $\hat t_z=\exp(\hat\zeta)$(指数保证正定度量深度);平面内平移 $(t_x,t_y)$ 用模型自己的 2D 关节锚点闭式解出。逐帧逐手:MANO 前向得「未放置」关节 $J^{\mathrm{can}}=\mathcal{M}(\hat R,\hat\theta,\hat\beta)$,关节 $j$ 深度 $z_j=J^{\mathrm{can}}_{z,j}+\hat t_z$;方位角 $b_j$ 两个来源(K-free:对 $\hat r$ 拟合等效针孔 $(\hat f,\hat c)$,$b_j=(\hat p_j-\hat c)/\hat f$;标准:$((u_j-c_x)/f_x,(v_j-c_y)/f_y)$)。透视投影对平面位移是线性的,故 $t_x$ 有加权最小二乘闭式解:

$$b^{x}_{j}=\frac{J^{\mathrm{can}}_{x,j}+t_{x}}{z_{j}}\;\Rightarrow\;\hat{t}_{x}=\frac{\sum_{j}m_{j}z_{j}^{-1}\big(b^{x}_{j}-J^{\mathrm{can}}_{x,j}/z_{j}\big)}{\sum_{j}m_{j}z_{j}^{-2}}$$ (式 5,论文 Eq.5)

$t_y$ 对称。$m_j\in\{0,1\}$ 是投票门:关节在相机前 ≥5cm 且锚点在画面内留 ≥2% 边距。有效关节 <6 个、或重投影 RMS 残差 > max(15px, 手部 2D 框对角线 × 0.25) 时,整只手回退到「腕部射线在深度 $\hat t_z$ 上的反投影」。这些常数在源码里逐字对应:memory_projector.py:1252-1257(_PNP_Z_NEAR=0.05、_PNP_INTERIOR_MARGIN=0.02、_PNP_MIN_INTERIOR=6、_PNP_RESID_MIN_PX=15.0、_PNP_RESID_FRAC=0.25)。

为什么这个设计重要(机制):① 深度与平面位移解耦——深度由网络全局估计,平面位置被 2D 锚点「钉死」,二者误差不再互相放大;② 求解器可微,$\mathcal{L}_{\mathrm{cam}}$ 的梯度穿过闭式解流回 2D 锚点头、MANO 头与 log-depth 头(附录 B.3);③ 门控回退保证 OOS / 出画边界帧有一个物理合理的兜底,而不是让 LSQ 在 0 个有效关节上发散。消融(表 3):把 mixed-PnP 换成纯反投影,CT-p 0.020→0.030m;换成直接回归平移,EPE2D-p +1.231px(但 Jitter 最低 2.658——论文明确说这是他们不做的 trade)。

6.4 K-free 的相机拟合与两个配置的差别

K-free 配置额外学一个「从射线场拟合等效针孔相机」的闭式逐轴线性回归(有方差下限 $10^{-4}$ 与焦距区间保护;失败的片段——包括鱼眼 Re:InterHand 训练臂——回退到直接读射线场),并用 $\mathcal{L}_{\mathrm{fit}}$(拟合相机方位角对 GT 的误差,权重 5,前 500 步线性 warmup)监督。拟合相机的价值:能外推出画锚点并给逐 token 射线场去噪。附录 D.1 量化:不加拟合时,画面最外圈(r>0.75)平移误差从 0.048 涨到 0.165m(ARCTIC,3.4×)/ 0.035→0.190m(HOT3D,5.4×),而腕对齐姿态几乎不变——边缘失败是纯度量放置问题;加上拟合后 OOS 平移误差 ARCTIC 0.55→0.10m、HOT3D 0.52→0.11m、OakInk2 0.45→0.06m,HOT3D 假阴从 2,491 降到 74。

⚠️【待核实】宣称 vs 发布代码的出入(本笔记源码复核发现):论文 §3.3/附录 B 说 K-free 的解码用「拟合出的等效针孔」提供方位角;但发布的推理代码里,mixed-PnP 的 ray 模式是直接在每个关节像素处 grid_sample 原始射线场取方位(memory_projector.py:1341-1355),腕部回退同理(memory_projector.py:1173-1185);而等效针孔拟合 _fit_pred_K(inference.py:24-45)的结果只被写进输出的 pred_intrinsics 元数据,没有参与解码。也就是说,发布代码的 K-free 解码路径对应论文附录 D.1 里「w/o camera fit」的变体,表 1 的 K-free 数字是否由带拟合的解码产生、拟合是否只在训练回路里起作用,在训练/评测代码发布前无法确认。实际部署 K-free 时,画面边缘的平移精度应预期接近附录 D.1 的下限而非表 1。

12.2 逐条机制解释(为什么强 / 为什么弱)

  1. 对 crop 系单帧方法(HaMeR/WiLoR/WildHands/EgoForce):差距不只在时序。detect-crop 范式把手从场景上下文里抠出来,尺度/深度锚在检测框上;ACE-Ego-Hand 的「整帧进 VAE、锚点 soft-argmax」保留了全局上下文,且存在性头把「检测」内化成无需匈牙利匹配的读出。结果:检测 F1 0.95→1.00,同时免去 ViTDet-H+ViTPose 前端(那正是基线们 1.5–1.7 fps 的成本大头)。
  2. 对 OmniHands(画面内遮挡专精):9 帧窗口只能补「画面内」被挡的手;ARCTIC MPJPE-p 几乎减半(29.674→15.256)说明窗口时序 ≠ 片段时序——出画需要的是整段双向证据。
  3. 对 HaWoR(SLAM 系):世界系重建依赖 SLAM 外参,而第一人称快速头动下 DROID-SLAM 在 81 帧短段上不稳定;相机系方法绕开了这个误差源。HaWoR 的 45.4mm 部分是协议所致(论文自陈关了它的 SLAM/补全),但即便考虑这一点,差距也是数量级的。
  4. 对 ViDiHand(同族对手,最重要的对比):同一个 Wan 血统、同一个评测协议,差别纯在「怎么用 VDM」。ViDiHand = 生成式用法(VACE 微调生成几何叠加图,12–25 步采样,解码器读冻结特征);ACE-Ego-Hand = 编码式用法(σ=0 单次前向 + LoRA 端到端)。结果:精度 -30~40%,速度 33×,OOS 149→35mm。这基本宣判了「渲染再回归」路线在此任务上的终结——生成能力没有被用到,反而付了采样延迟与伪影传播两份税。

13🎯 应用场景与落地适配性

13.1 它解决什么、不解决什么

✅ 适合

  • 机器人操作数据采集(论文的核心动机):从日常第一人称录像批量产出带度量尺度的双手 MANO 轨迹,做模仿学习/retargeting(附录 E.3 已演示到 Inspire 灵巧手,且 63 fps 不是采集瓶颈)。
  • 离线标注工具:81 帧段 63 fps,整段录像也可单 pass(精度换平滑),适合给自建第一人称数据补 3D 手部 GT。
  • 无标定素材:K-free 配置完全不需要内参,HOT3D 这种广角场景下 2D 锚点与有内参配置打平(F1 0.995 vs 0.996)。

❌ 不适合

  • 在线/闭环控制:整段双向注意力,延迟下界=片段长度;作者自己定位是「数据采编工具,不是控制器」。
  • 鱼眼原生素材:发布 checkpoint 针孔限定,鱼眼直接报错——需先去畸变(会改变边缘几何分布)。
  • 需要出画手绝对位置的场合:OOS 只有腕对齐保证,绝对深度在出画期间无约束(附录 F.1)。
  • 第三人称/多视角:全部训练数据是第一人称;论文未做任何第三人称评估。

14可改进方向分析

按三维度分点,每点给证据与建议。标注:📄=论文自陈,✅=源码佐证,💡=本笔记推断。

14.1 方法层面

[高优先级] 出画手的度量放置无任何评估与约束 💡📄

问题:OOS 指标全部是腕对齐的;附录 F.1 自陈「手在出画期间的位置依赖回归深度与方位角,无图像证据约束,失败签名是姿态合理但深度漂移的手」。而「手出画后去哪了」恰恰是机器人数据采集最关心的问题。

建议:① 评测侧:构造带 OOS 绝对位置 GT 的协议(如用多视角/动补标注的子集);② 方法侧:OOS 区间的深度不确定性应该被显式建模(输出分布而非点估计),至少给存在性头之外再加一个「放置置信度」。

[高优先级] K-free 解码的「相机拟合」在发布代码中缺失 ✅

问题:§6.4 已述——论文说解码用拟合相机,发布代码直接采样原始射线场,拟合只写元数据。按附录 D.1,这意味着发布的 K-free 推理在画面外圈 CT 可能差 3.4–5.4×。

建议:复现/部署时在 _decode_cam_trans_mixed_pnp 的 ray 模式前插入 _fit_pred_K 的等效针孔,用 $(\hat p_j-\hat c)/\hat f$ 替代逐点采样;或等官方训练代码发布后核对真实实现。

[中优先级] 离线结构 → 流式变体 📄

问题:全片双向注意力使延迟=片段长度。附录 F.1 给出的方向是「蒸馏成因果变体」。

建议:代码库里其实已留好脚手架——memory_encoder.py 的 _MemGRU 跨窗口记忆(alt_mem_tokens,当前配置 =0 关闭)与 temporal_window 时间范围层级。以 K-free 权重为教师做因果学生蒸馏,并量化「多少精度来自未来帧」(作者自己点名的实验)。

[中优先级] 固定 caption 的影响从未消融 ✅

问题:DiT cross-attention 吃的是固定文本「Three geometry renders of two hands on black background...」(precompute_caption.py:26-27)——一句描述渲染任务的提示词,而当前任务是视频编码。这个失配是渲染血统遗留,论文与消融均未提及。

建议:把 caption 换成空串/手部描述做对照;若差异显著,说明 σ=0 编码读出的特征仍受文本条件调制,发布配置的选择可能只是「训练时沿用了遗产」。

14.2 数据与评估层面

[中优先级] 基准 GT 与切分不均 📄

问题:仅 ARCTIC/H2O 被试隔离;HOI4D/H2O 部分伪 GT;H2O 还在训练混合里(附录 F.1/A.2 自陈)。H2O 的 -43% 与 OakInk2 的 -66% 都应按「in-domain 上限」打折看待。

建议:引用本文数字时只用 ARCTIC/HOT3D(原生 MANO GT);后续工作补一个全员 out-of-domain 的基准。

[中优先级] 鱼眼支持缺口 📄✅

问题:射线场理论上兼容鱼眼(§3.3),但发布 checkpoint 针孔限定、代码硬拒绝鱼眼;训练混合里的鱼眼臂(Re:InterHand)在拟合失败时回退读场。第一人称硬件(Aria、GoPro)大量是鱼眼。

建议:按附录 F.1 的方向补径向方位模型(OpenCV-KB / MEI 的射线参数化已在代码注释中提及),而不是要求用户去畸变——去畸变会裁掉 FOV 边缘,而边缘恰是手部常出现的位置。

[低优先级] 单次运行的随机性 📄

问题:附录 C.1 自陈每个 H2O/OakInk2 条目来自单次训练运行;附录 D.3 把 block-20/24 的 ±0.17mm 判为运行间噪声——说明 run-to-run 噪声量级约 0.2mm,表 1 里 K-free 与标准的部分差距同量级。

建议:精读时对小差距保持警惕;复现应报多种子均值。

14.3 工程实用性层面

[中优先级] 训练不可复现 ✅

问题:只发布推理;20k 步 × 16 A100 的配方、损失路由、数据预处理全部黑箱。论文 §9.5 表里所有训练侧数字无法验证;社区无法在其数据上继续训练。

建议:这一实测应写进论文正文;对其他想「从手反推相机」的工作是直接的反面教材。

15总结与演进定位

15.1 总结

ACE-Ego-Hand 给「视频扩散模型还能怎么用」提供了一个范式级答案:不当渲染器,当编码器。三个具体的技术决策支撑了这个答案:① σ=0 单次前向 + block-15 tap + LoRA 端到端适配——用一半算力把 5B VDM 变成确定性特征提取器,且特征被 3D 监督「重塑」成几何感知;② 48-query 双向交替时空解码器 + 片段级形状先验——结构上保证出画手是「重建」而非「外推」,RoPE 顺带解锁了任意长度单 pass;③ 射线场 + mixed-PnP——把度量放置分解成「网络回归深度 + 2D 锚点闭式解平面位移」,并让梯度穿过求解器。结果是五个基准的全面 SOTA、出画手腕对齐误差 4× 于最强基线的改善、以及 33× 于同族生成式方法的速度。

对读者最重要的三条保留:① 出画数字全部是腕对齐的,绝对放置没有证据;② 发布的 K-free 推理代码缺了论文所说的相机拟合解码步骤(§6.4);③ 训练代码未发布,训练侧所有数字只能信论文。
