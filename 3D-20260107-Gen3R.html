1论文摘要与核心贡献

一句话:Gen3R 不去学习一个全新的 3D VAE,而是把已经很强的重建基础模型 VGGT 重铸成一个「非对称几何 VAE」——用一个轻量因果卷积适配器把 VGGT 的中间 token 压进视频扩散模型(Wan2.1-1.3B)的潜空间,并用 KL 损失把几何潜分布对齐到 RGB 潜分布;随后两个模态的潜变量沿宽度拼接,由同一个 DiT 联合去噪,一次前向同时产出 RGB 视频、逐帧深度、相机内外参、全局点云四种资产。

问题:给定 1 张图、首尾 2 帧、或一整段视频,生成/重建出几何一致、相机可控的 3D 场景资产。方法:重建模型的 token 流形本身就是「自带多视角几何结构的紧凑潜空间」,与其费劲训一个 3D VAE,不如把 VGGT 的 token 适配进视频扩散的潜空间、用分布对齐损失让两者同构,再联合扩散。结果:外观生成上 1-view 设定在 Re10K/DL3DV 取得最优或次优 PSNR;几何生成 CD 全面压制 Aether / WVD;并且在纯重建(全帧输入)任务上反超 VGGT 自身的 CD(TartanAir 1.5101 vs 1.5957)——生成先验反过来修正了重建模型的漂浮点。

核心贡献(论文 §1 自述三点):
  1. 框架:把视频扩散模型与几何基础模型(VGGT)在潜空间层面桥接,RGB 先验与几何先验互相增益;
  2. 解耦但对齐的双潜空间:几何/外观潜变量保持独立通路、只约束分布一致(KL),既保多视角一致又保可控生成;
  3. 灵活的多任务统一:1-view / 2-view / 全序列重建三种条件模式、有无相机条件均可,一个模型覆盖生成与重建。

2研究背景与动机:为什么「直接压缩点云」会失败

路线一:SDS / 增量外扩

LucidDreamer 式逐帧扩画 + 优化。具体失败模式:几何结构差、优化成本高(论文 §1: "poor geometric structure or high optimization cost")。

路线二:从头训 3D 几何 VAE

WVD / 后续工作学一个压缩 3D 场景的 VAE 再做潜空间扩散。具体失败模式:大规模 3D GT 稀缺,监督只有 2D 信号,几何与生成质量双输(§1: "suboptimal geometry and constrained generation quality")。

路线三:用 RGB VAE 压重建输出

拿现成图像 VAE 去编码 VGGT 的点云(WVD VAE-only)。具体失败模式:本文 Tab.3 实测——RGB VAE 编解码点云后 Co3Dv2 CD 从 VGGT 的 0.9632 恶化到 1.2080,TartanAir 从 1.5957 恶化到 2.7867。点云分布与图像分布差异过大,压缩即失真。

作者的关键洞察(论文 §1):DUSt3R / VGGT 这类 transformer 前馈重建模型,本身就工作在空间紧凑的 token 空间里,而这些 token 已经编码了深度、相机、全局结构等跨视角几何信息。「重建模型的内在潜流形,能不能直接拿来当 3D 生成的地基?」——答案是把它重铸成 VAE 用,而不是去压缩它的输出。
⚠️ 关键假设与失效条件:
  • 假设 1:VGGT token 流形足以支撑扩散建模——依赖 VGGT 自身质量。失效条件:输入域超出 VGGT 训练分布(如强动态人体、极端模糊),token 本身即失真,扩散只能放大不能修复。
  • 假设 2:几何/外观两潜空间只需「分布对齐」即可联合建模——KL 只对齐边缘分布,不约束逐样本对应。失效条件见 §15 改进方向 1:两模态逐像素错位时,RGB-几何资产各自可用但不可互相当监督。
  • 假设 3:静态场景——VGGT 与所有训练数据都是静态多视角;运动物体(含动态人体)违反该假设,这是本文对 vggt_human 类 pipeline 的主要边界(§14)。

4.2 数学形式化

$$\mathcal{V} = \mathcal{E}_{\mathcal{V}}(\mathcal{I}) \in \mathbb{R}^{N\times L\times h_v\times w_v\times C},\qquad \mathcal{G} = \mathcal{E}_{adp}(\mathcal{V}),\quad \hat{\mathcal{V}} = \mathcal{D}_{adp}(\mathcal{G})$$ (式 1)

其中 $L=5$(4 层 patch token + 相机 token 广播到 $40\times40$ 空间网格,$h_v=w_v=40$,$C=2048$,$L\times C=10240$)。适配器与 Wan VAE 共享时序压缩 ×4、空间压缩 ×8(geo_adapter/config.json),因此几何潜与外观潜同形,可逐像素对齐拼接。

机制解释:「非对称」体现在——编码侧输入是 10240 维的富几何 token,解码侧却要重建全部 4 个量(点/深度/相机/图像 token),中间只过 16 通道潜变量。瓶颈极狠(单帧潜像素 70×70×16 = 78400 维 vs 原 token 5×1600×2048 ≈ 1640 万维,压缩比 ≈210×),逼得潜空间必须学出「可生成」的流形而非像素记忆。

4.3 适配器训练损失(源码直读)

$$\mathcal{L}_{rec} = \underbrace{\mathcal{L}_{tok}^{img} + \mathcal{L}_{tok}^{cam}}_{\text{SmoothL1, }\beta=0.15} + 10\,\mathcal{L}_{cam} + 2\,\mathcal{L}_{dep} + \mathcal{L}_{pt},\qquad \mathcal{L}_{sim} = (1-\cos_{img}) + (1-\cos_{cam})$$ (式 2)
$$\mathcal{L}_{KL} = D_{KL}\big(q(\mathcal{G})\,\|\,p_{Wan}(\mathcal{A})\big),\qquad \mathcal{L}_{adp} = \mathcal{L}_{rec} + \mathcal{L}_{sim} + 0.1\cdot w_{ada}\cdot\mathcal{L}_{KL}$$ (式 3)

各项权重出自 train_geo_adapter_pl.py:297-341:token 重建 SmoothL1($\beta$=0.15)、相机位姿 L1 权重 10、深度 2、点云 1,另有图像/相机 token 的余弦相似度损失(各权重 1);KL 项把几何潜的后验分布 $q(\mathcal{G})$ 拉向 Wan VAE 对同一批帧编码出的外观潜后验 $p_{Wan}(\mathcal{A})$,权重用 calculate_adaptive_weight 按数量级自适应(取 $10^{\lfloor\log_{10}(L_{rec}/L_{KL})\rfloor}$)再乘 0.1。消融(Tab.4)证明没有这项 KL,PSNR 掉 4.2 dB。

5.3 扩散过程与条件采样

$$z_t = (1-\sigma_t)\,x + \sigma_t\,\epsilon,\qquad v_\theta = \epsilon - x,\qquad \mathcal{L}_{FM} = \mathbb{E}\big[\,w(\sigma)\cdot m\cdot\|v_\theta(z_t) - (\epsilon - x)\|^2\,\big]$$ (式 5)

Flow Matching 目标(train_dit.py:1588-1613):预测目标为 $\epsilon - x$;损失为带阈值掩码的 MSE($|diff|>50$ 的元素置零,防离群爆梯度)乘 SD3 式 $\sigma$ 加权。条件组合每步等概率($1/3$)取 1-view / 2-view(首尾帧)/ 全序列;文本以 20% 概率丢弃(CFG);相机条件以 50% 概率丢弃(train_dit.py:283-284)。推理:FlowMatchEulerDiscrete 调度、shift 2.0、默认 50 步、CFG 5~6(scheduler_config.json + infer.py:290)。

5.4 前向流程(逐步)

  1. 文本经 umt5-xxl(24 层、4096 维)编码,首帧经 CLIP image encoder 取全局特征;
  2. 条件图经 Wan VAE 编码为 $\mathcal{A}_{cond}$,缺失帧补零,掩码按 control_index 置 1;
  3. 几何条件潜与几何掩码全零初始化(论文 §6.1)——几何完全靠生成;
  4. 噪声 $\mathcal{Z}_T\sim\mathcal{N}(0,I)$ 与条件沿通道拼接($36$ 通道),DiT 迭代 50 步;
  5. 输出 $\hat{\mathcal{Z}}=[B,16,13,70,140]$,按宽度对半切开送两条解码路。

监督信号:联合潜空间上的 Flow Matching 损失(不区分外观/几何半区,无单独几何权重)。

相机条件的两种来源

  • 内置轨迹(zoom_in/out、arc_left/right、translate_up/down):先用 VGGT 估首帧内参与场景尺度(scene_scale = 0.8 × median(depth),infer.py:252),再程序化生成 49 帧 c2w;
  • 外部 json(extrinsics 4×4 + intrinsics 3×3,OpenCV 约定),或 free(无相机条件,轨迹由模型自由发挥)。

相机条件以 Plücker 光线图 $[F,6,560,560]$ 注入(compute_rays),经时序 4× 打包成潜分辨率后走 control adapter;1-view/2-view 模式下也可完全不给(free)。

10.5 落地坑清单(实读源码确认)

  1. 49 帧硬上限:infer.py:232 无条件截前 49 帧,长视频直接丢尾;pipeline_gen3r.py:392 的公式允许其他帧数,但训练从未见过 ≠49 的时序长度,【推测】外推质量无保证。
  2. 分辨率锁定 560×560:任何输入都 resize + 居中裁剪(infer.py:236-239),横构图视频左右内容直接裁掉——对宽画幅街拍/行车数据是硬伤。
  3. allview 忽略相机条件:README 明示 "note that --cameras are ignored in this task";位姿完全由模型生成,与外部标定不一致时需自行配准。
  4. 尺度任意:VGGT 系输出无绝对尺度;需要米制几何时必须引入外部尺度源(如一段已知位移)。
  5. bf16 全链路(infer.py:213),深度精度受 bf16 限制;【推测】远距离薄结构可能受影响。
  6. 置信度被丢弃:DPT head 返回 (pred, conf)(dpt_head.py:157-159),pipeline 里 depth_maps, _ = ... 直接扔掉 conf(pipeline_gen3r.py:447-448),点云过滤只能靠体素/分位数规则。

13.2 对比结论(机制层面)

  • 对 WVD(最相近):WVD 压缩的是 VGGT 的输出(点云),用图像 VAE 硬编几何分布,压缩即失真(Tab.3 的 1.2080 vs 0.9632 是直接证据);Gen3R 压缩的是 VGGT 的中间 token 流形,信息瓶颈前移到网络内部特征,失真小一个量级(适配器 VAE-only 已接近无损:0.9986 vs 0.9632)。
  • 对 Geometry Forcing:GF 在扩散训练过程中把中间特征拉向重建模型特征——两个分布没有显式对齐,约束弱;Gen3R 在扩散之前就把潜空间对齐好(KL),DiT 只需学一个同构空间(论文 §4.2 原文:"GF aligns intermediate diffusion features ... during training, which is less effective in practice",Tab.1 数据支持:16.32 vs 20.51)。
  • 对 LVSM / DepthSplat(重建派):插值设定赢不了前馈重建(2-view 输 2.53 dB),但它们出不了遮挡区域内容;Gen3R 能生成未观测区域(Fig.4 空洞补全)。两者是互补关系。
  • 对 FlashWorld:第三方同协议评测(OneWorld,见 FlashWorld 笔记 §15.4)两者 Re10K 仅差 0.09 dB(20.18 vs 20.09,Gen3R 自报 20.51 存在 +0.42 dB 自评偏差),真正差异在产物形态与速度:FlashWorld 4 步直出可渲染 3DGS,Gen3R 50 步出几何真值(深度/位姿/点云)但不给 GS。

14.1 对「输入视频生成几何」的直接评估

Gen3R 的 allview 模式就是"视频进、几何出":一段视频(≤49 帧) → pcds.ply(全局点云)+ cameras.json(49 组内外参)+ 逐帧深度(取消注释后)+ 重建 RGB。相比直接跑 VGGT/Pi3,它的增量价值是生成先验带来的几何去噪与缺失补全(Fig.5:VGGT 的漂浮点被清掉);代价是 50 步扩散的耗时与结果随机性(seed 固定可复现)。

桥接要点与自检:
  • 几何-外观错位风险:RGB 与深度来自两个独立解码器(Wan VAE / VGGT 头),训练时无任何逐像素对齐损失(§8)。初始化 GS 前建议自检:把 pcds.ply 按 cameras.json 投影回某帧,与该帧 RGB 边缘对比——错位明显时路线 A 的颜色初始化会把错位烙进高斯。【待核实】错位幅度的实测数据(论文与仓库均无此项评估)。
  • 尺度与坐标系:输出为 VGGT 任意尺度;GS 优化本身能吸收整体尺度,但与外部(如 COLMAP/SfM)结果对齐需相似变换。
  • 监督视角密度:49 个视角对 3DGS 优化偏少(常规 COLMAP 管线 100+ 视角);好在 Gen3R 能沿任意轨迹再生成新视角(1view 模式以重建帧为条件),可用来增密监督——这是它相对纯重建方法的独特价值。
  • 置信度要用起来:DPT 头第二返回值就是逐像素 conf(dpt_head.py:157-159),改两行代码即可在初始化时滤掉低置信高斯。

14.3 对 vggt_human 类人体视频 pipeline 的适用性判断

⚠️ 静态场景假设是硬边界:Gen3R 的全部几何监督与训练数据都是静态多视角;运动中的人体违反多视图一致性假设,扩散先验会把"人动了"解释成"几何长这样",输出的深度/点云在动态区域不可信。可能的分工:用 SAM3 person mask 把人剔掉后,Gen3R 只负责背景场景(scene_gs 底座)的几何与补全——这与 vggt_human 现有的拆分架构天然兼容;人体本体仍走 3DMM/逐人高斯路线。【待核实】该分工需实测,Gen3R 训练集中含 Waymo/KITTI 街景(有少量动态目标被当噪声处理),对带人视频的行为无法从论文推断。

15可改进方向分析

1. [高] RGB-几何双解码器无逐像素对齐约束 → 3DGS 桥接的最大隐患

问题:联合潜变量在宽度拼接后,decode_latents 直接 latents.chunk(2, dim=-1) 分两路独立解码(pipeline_gen3r.py:439, 454),扩散损失对两半一视同仁(train_dit.py:1612),全链路没有一条损失约束"第 i 个像素的颜色与深度必须自洽"。论文也从未评估 RGB-深度逐像素一致性。改进:① 加一条重投影一致性损失(用生成的 K/E/depth 把 RGB 帧 warp 到邻帧);② 或训练一个共享解码头。短期替代:桥接前做点云投影自检(§14.2)。

2. [高] 49 帧 / 560² 硬上限,长视频无窗口化机制

问题:infer.py:232 无条件截前 49 帧;infer.py:289 分辨率写死 560;没有任何跨窗口的位姿/点云缝合逻辑。改进:滑窗 + 重叠段相似变换配准(VGGT 系的 Pi3/CUT3R 已有成熟做法可借);分辨率侧可先超分输入或改 RoPE 插值,【待核实】未见官方讨论。

3. [中] 相机信息在解码端被过度压缩

问题:convert_to_token_list 把相机 token 在空间维取均值再重复 5 份(common_utils.py:123),4 层 token 共享同一份均值相机信息;位置稍异的微调相机估计无从表达。改进:保留逐 patch 相机 token 或加相机专用的轻量 adapter 头;【推测】这是重建位姿 AUC 略输 VGGT(Tab.9)的可能原因之一。

4. [中] 置信度产出被白白丢弃

问题:DPT 头原生返回 (pred, conf)(dpt_head.py:157-159),pipeline 两处 depth_maps, _ = ...、point_maps, _ = ... 直接丢弃(pipeline_gen3r.py:447-448),点云过滤只剩体素降采样与 80 分位截断(common_utils.py:134-150)。改进:导出 conf 并用于 GS 初始化过滤/加权监督,改动 <10 行。

5. [中] 评估缺口:无 RGB-几何一致性、无长程/动态评估

问题:几何只在 Co3Dv2/WildRGB-D/TartanAir 评 CD,位姿只在 Re10K/WildRGB-D 评 AUC;没有任何指标回答"生成的深度和生成的 RGB 是不是同一个场景";动态场景完全缺席。改进:补 RGB→depth 渲染重投影误差指标;补动态数据集上的失败案例分析。

6. [低] 50 步未蒸馏,离实时很远

问题:推理 50 步全量 CFG(双流 → 每步 2×31.9k token)。改进:库内已有成熟路线可迁移——DMD2 少步蒸馏、FlashWorld 的跨模式蒸馏;【推测】压到 8 步内、单场景 10s 级是合理目标。

16总结与演进定位

Gen3R 的本质贡献是一个视角转换:3D 生成的瓶颈不是"怎么设计 3D VAE",而是"承认重建基础模型的 token 流形已经是最好的几何潜空间"。把 VGGT 重铸为非对称几何 VAE + KL 对齐 + 宽度拼接联合扩散,三个组件都不复杂,但组合出的模型第一次让「生成 RGB」与「生成几何」在同一个去噪过程里互相校准——消融里 2-Stage 管线 −3.13 dB 的差距就是这个"校准"的价格。

对本库场景的意义:它是FlashWorld(要速度、要 3DGS、要秒级)与 VGGT(要确定性、要稠密帧)之间的第三极:要几何质量与缺失补全,能接受分钟级。在 vggt_human 语境下,它最合适的角色是静态背景的生成式重建器(配 SAM3 掩码剔人),输出的深度+位姿+点云经 §14.2 路线 A/B 桥接进 3DGS;动态人体区域不应交给它。

⚠️ 遗留核实项:单卡推理显存/耗时(§10.4);RGB-深度逐像素错位幅度(§14.2);≠49 帧输入的行为(§10.5-1);带动态人物视频的实际表现(§14.3)。建议在 3090 上做一次 allview 冒烟测试后再定集成方案。
